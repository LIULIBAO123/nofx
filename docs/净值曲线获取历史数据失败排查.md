# 「获取历史数据失败」排查说明

## 现象

实盘/模拟仪表盘「账户净值曲线」Tab 报错：**loadingError / 获取历史数据失败**。

## 原因说明

该接口 `GET /api/equity-history?trader_id=xxx` **需要登录**（已改为需认证路由）。未带有效 Token 或服务端校验不通过时，会返回 4xx，前端显示「获取历史数据失败」。更新后，**下方灰色小字会显示后端返回的具体原因**（如 Invalid trader ID），便于排查。

## 排查步骤

### 1. 确认已部署最新代码并重启

- 服务端需包含「`GET /api/equity-history` 移至 protected 路由」的修改，否则未登录时 `user_id` 为空，会一直返回 400 Invalid trader ID。
- 更新代码后执行：`docker compose pull && docker compose up -d`（或你当前使用的部署方式），并重启后端。

### 2. 确认当前已登录

- 若未登录或 Token 过期，请求会返回 401，前端可能跳转登录页或提示 Session expired。
- 请先登录再打开对应交易员的仪表盘，然后查看「账户净值曲线」。

### 3. 看错误详情（灰色小字）

- 若仍显示「获取历史数据失败」，请看**错误框下方灰色小字**：
  - **Invalid trader ID**：多为未登录导致 `user_id` 为空，或该 `trader_id` 不属于当前用户；确认已登录且未改过 URL 中的交易员。
  - **Get historical data / 其他后端错误**：可能是数据库或内部错误，查看服务端日志进一步定位。

### 4. 查看服务端日志

- 在云服务器上执行：`docker compose logs nofx --tail=100`（或你的后端容器名）。
- 请求 equity-history 时若报错，会有对应错误栈或「Invalid trader ID」等日志，便于确认是认证问题还是库表问题。

### 5. 浏览器网络请求（可选）

- 打开开发者工具 → Network，刷新并触发「账户净值曲线」请求。
- 找到 `equity-history?trader_id=...` 的请求，确认：
  - **Request Headers** 中有 `Authorization: Bearer <token>`；
  - **Response** 状态码（400/401/500）与响应 body 中的 `error` 字段。

## 小结

- 接口已改为**需登录**，请确保**已部署最新代码并重启**，且**当前账号已登录**。
- 前端已改为显示**后端返回的具体错误信息**，请根据灰色小字和上述步骤逐项排查。
