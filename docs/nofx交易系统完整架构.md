# nofx 交易系统完整架构

本文档在「AI 仅作辅助、不执行开平仓」的前提下，梳理 nofx 交易系统的大致架构，并补充各层细节、数据流与代码落点，便于后续迭代与扩展。

---

## 一、架构定位与结论摘要

- **实盘结论**：由 AI 直接负责开仓/平仓的盈利表现不佳，可能与 AI 自主性带来的不稳定有关。
- **设计选择**：将 **AI 定义为辅助工具**，只做**量化数据分析与可选的结构化输出**，**开仓与平仓由系统规则执行**。
- **AI 仍可发挥的作用**：见第二节；在不承担开平仓的前提下，可用于趋势视图、异常识别、数据解读、复盘归因等，既控制风险又保留 AI 价值。

---

## 二、AI 仅作辅助时仍可发挥的空间（建议）

在「AI 不执行开仓/平仓」的前提下，以下方向可继续发挥 AI 作用，且不增加执行风险：

| 方向 | 说明 | 当前状态 / 建议 |
|------|------|------------------|
| **1. 持仓期趋势视图（trend_view）** | 对已有持仓输出 trend_intact / choppy / reversing，系统据此调节**止损确认周期**（reversing→少确认快止损；trend_intact/choppy→多确认防洗）。 | ✅ 已实现：AI 输出 trend_view，`checkDynamicStopLossTakeProfit` 使用。 |
| **2. 量化数据解读与摘要（market_summary）** | 将 OI、资金流、多周期涨跌、币安多空比/资金费率等用自然语言归纳为本周期市场摘要，供人工或后续参考，不参与下单。 | ✅ 已实现：AI 在可选 `<analysis>` 中输出 `market_summary`，解析后写入 FullDecision。 |
| **3. 市场状态/Regime 分类（market_regime）** | 输出当前市场类型（trend_up/trend_down/ranging/high_volatility/reversal），系统或策略参数可据此调节过滤或止盈档位（不直接开平仓）。 | ✅ 已实现：AI 在 `<analysis>` 中输出 `market_regime`，解析后写入 FullDecision；策略层可按需选用。 |
| **4. 异常与风险提示（risk_alert）** | 识别异常波动、流动性骤变、多周期严重背离等，输出 risk_alert；为 true 时本周期不执行系统开仓。 | ✅ 已实现：AI 在 `<analysis>` 中输出 `risk_alert`；执行层若为 true 则本周期跳过系统开仓并记日志。 |
| **5. 复盘与归因** | 对已平仓订单做事后分析：为何触发止损/止盈、是否与当时趋势一致、有无改进点。用于策略与提示词迭代，不参与实时交易。 | 🔲 可扩展：独立「复盘」任务，读取历史决策与行情，输出归因报告。 |
| **6. 策略与提示词的自然语言建议** | 根据近期表现与 AI 分析，给出「建议提高 MinFactors」「建议缩短信号有效期」等自然语言建议，供人工采纳后改策略参数或提示词。 | 🔲 可选：作为辅助调参参考，不自动写回配置。 |

**小结**：在不开平仓的前提下，AI 仍可承担「解释、分类、预警、归因、建议」等角色，与「获取数据 → 过滤 → 方向 → 止盈止损 → 平仓」的**系统执行主链路**解耦，既保留 AI 价值又避免其自主性影响稳定性。

## 三、交易系统整体架构（高层）

您提出的大致链路为：

1. **获取量化数据**
2. **量化数据分析**
3. **结合数据分析的过滤机制**
4. **判断方向（多/空）**
5. **止盈止损机制**
6. **平仓**

再加上：**代码底层逻辑**、**策略参数**、**提示词**。

下面按**数据流 + 执行顺序**拆成完整架构，并标明与代码的对应关系。

## 五、各层架构细节与代码落点

### 5.1 调度与上下文（0）

| 项目 | 说明 |
|------|------|
| **职责** | 按周期（如 5m/15m）驱动一次完整交易循环，先构建统一上下文，再执行「数据→过滤→方向→开仓→止盈止损→平仓」。 |
| **输入** | 定时触发 / 扫描间隔、交易员 ID、策略绑定。 |
| **输出** | `kernel.Context`：账户权益/可用、持仓列表、候选币、后续各层依赖的原始与派生数据。 |
| **代码落点** | `trader/auto_trader.go`：`runCycle()` → `buildTradingContext()`；`kernel.Context` 在 `kernel/engine.go` 等处定义与填充。 |

**子步骤简述**：

- 风控暂停（stopUntil）、每日 PnL 重置。
- `buildTradingContext()`：拉取交易所余额与持仓、候选币列表（来自策略币种来源）、最近成交与统计；**不在此处拉 K 线**，K 线在「获取量化数据」阶段由 kernel 按策略拉取。

---

### 5.2 获取量化数据（1）

| 项目 | 说明 |
|------|------|
| **职责** | 为候选+持仓拉取行情与量化数据，供分析、过滤与方向判断使用。 |
| **输入** | `Context`（候选币、持仓）、策略中的 K 线/指标/量化数据配置。 |
| **输出** | `Context.MarketDataMap`（含多周期 K 线、EMA/MACD/RSI/ATR 等）、`OITopDataMap`、OI/资金流/涨跌排行等（若启用）。 |
| **代码落点** | `kernel/engine.go`：`fetchMarketDataWithStrategy()`；`GetFullDecisionWithStrategy()` 内若 `MarketDataMap` 为空则调用；NofxOS 等数据源在 provider 与 engine 中调用。 |

**数据范围**：

- **行情**：按策略 `SelectedTimeframes`、`PrimaryTimeframe`、`PrimaryCount` 拉 K 线；持仓必拉，候选数量受 `MaxCoinsInPrompt` 等限制。
- **技术指标**：在 market 或 kernel 侧计算 EMA、MACD、RSI、ATR 等并写入 `market.Data`。
- **量化与排行**：OI Top、资金流、涨跌排行等由策略开关控制，写入 Context 对应字段。

---

### 5.3 量化数据分析（2）

| 项目 | 说明 |
|------|------|
| **职责** | 对原始数据进行计算与解释：规则侧得到可量化的因子与方向强度；AI 侧得到趋势视图、摘要、预警等（不参与开平仓）。 |
| **输入** | `MarketDataMap`、OI/资金流/排行、策略参数。 |
| **输出** | 规则：多周期方向、因子通过情况、可靠度/入场信心、方向池分数；AI：trend_view、reasoning、可选 market_regime/risk_alert/市场摘要。 |
| **代码落点** | 规则：`kernel/pipeline.go`（Layer1/Layer2/方向池计算）；AI：`kernel/engine.go`（BuildUserPrompt/BuildSystemPrompt、parseFullDecisionResponse）、`trader/auto_trader.go`（解析 trend_view 等）。 |

**规则分析**：

- 第一层 16 项条件（量能、OI、多周期对齐、流向、涨跌榜、可靠度、RSI/MACD 等）逐币种检查。
- 第二层：因子数 ≥ M、可靠度 ≥ 阈值、入场信心 ≥ 阈值。
- 方向池：按趋势/动能/多周期一致性划分多空池并打分（StrengthPct 等）。

**AI 分析（辅助）**：

- 输入：与规则相同的量化数据 + 策略说明（含止盈止损说明）。
- 输出：对持仓的 trend_view；可选本周期市场摘要、regime、risk_alert；**不输出 open_long/open_short**（系统执行开仓时）。

---

### 5.4 过滤机制（3）

| 项目 | 说明 |
|------|------|
| **职责** | 结合数据分析结果，逐层过滤候选，得到「可提交下单」的标的列表及方向。 |
| **输入** | 候选池（仅含已有行情数据的标的）、策略多层过滤配置、多空雷达（允许做多/做空）。 |
| **输出** | `PipelineState`：`ToSubmitSymbols`、`DirectionLong`、`DirectionShort`、各层通过数量与失败统计。 |
| **代码落点** | `kernel/pipeline.go`：`RunPipeline()`；`GetFullDecisionWithStrategy()` 内当 `strategy_mode=multilayer_filter` 时调用，并据此更新 `Context.CandidateCoins`。 |

**三层结构**：

- **第一层**：16 项条件逐币种检查，未通过项计入失败统计；通过者进入第二层。
- **第二层**：因子数、可靠度、入场信心（均由规则计算）同时满足配置阈值者进入第三层。
- **第三层**：信号年龄（本周期 RunPipeline 时间与开单时校验）、方向允许（多空雷达 AllowLong/AllowShort）；`filterToSubmitByDirection()` 得到最终 ToSubmitSymbols。

**与「数据分析」的关系**：过滤直接依赖「量化数据分析」中的规则结果（因子、可靠度、方向池）；AI 分析结果仅用于 trend_view 等，不参与过滤通过与否。

---

### 5.5 方向判断（4）

| 项目 | 说明 |
|------|------|
| **职责** | 为每个待提交标的确定至多一个方向（做多/做空）；若在多个方向池则按分数择高。 |
| **输入** | `ToSubmitSymbols`、`DirectionLong`、`DirectionShort`、多空雷达允许方向。 |
| **输出** | 每标的 (symbol, open_long | open_short)，供系统开仓使用。 |
| **代码落点** | `kernel/pipeline.go`：`GetSystemEntryList(state, opts)`；`trader/auto_trader.go`：系统执行开仓时遍历该列表并调用 `executeOpenLongWithRecord` / `executeOpenShortWithRecord`。 |

---

### 5.6 开仓执行（5）

| 项目 | 说明 |
|------|------|
| **职责** | 根据「方向判断」结果与策略默认参数（杠杆、仓位比例、初始止损/首档止盈）执行开多/开空；风控由代码强制校验。 |
| **输入** | `GetSystemEntryList()` 的结果、策略 RiskControl 与动态止盈止损配置、当前权益。 |
| **输出** | 交易所订单、本地记录与持仓同步。 |
| **代码落点** | `trader/auto_trader.go`：系统执行开仓分支（`SystemExecutesEntry` 为 true 时）；`executeOpenLongWithRecord` / `executeOpenShortWithRecord`；第三层校验 `kernel.ValidateLayer3()`。 |

**说明**：若策略为「AI 开仓」模式（非系统执行开仓），则开仓信号来自 AI 的 open_long/open_short，执行层仍相同，仅信号源不同。

---

### 5.7 止盈止损机制（6）

| 项目 | 说明 |
|------|------|
| **职责** | 对每个持仓按配置检查动态止损与动态止盈条件，满足则触发平仓逻辑；可选使用 AI 的 trend_view 调节止损确认周期。 |
| **输入** | 当前持仓（含入场价、标记价、数量、杠杆）、策略 DynamicStopLoss/DynamicTakeProfit 配置、可选 trendViewByPosKey。 |
| **输出** | 是否触发止损/止盈、目标平仓数量与价格；实际平仓在「平仓」层执行。 |
| **代码落点** | `trader/auto_trader.go`：`checkDynamicStopLossTakeProfit(trendViewByPosKey)`；`kernel` 内 StopLossChecker / TakeProfitChecker。 |

**逻辑概要**：

- 最小持仓时间、锁利 breakeven 等先决条件。
- **止损链**：初始固定 → 追踪止损 → ATR 止损 → 支撑/阻力 → 逆势早退等；trend_view 仅调节**确认周期数**（reversing 少确认，trend_intact/choppy 多确认）。
- **止盈链**：分层止盈、回撤止盈、固定止盈、ATR 止盈等。

---

### 5.8 平仓（7）

| 项目 | 说明 |
|------|------|
| **职责** | 根据止盈/止损检查结果或人工/同步需求，调用交易所平仓接口，并更新本地记录与持仓状态。 |
| **输入** | 触发类型（止损/止盈/同步等）、标的、方向、数量、价格信息。 |
| **输出** | 平仓订单、PnL 与平仓原因写入记录；策略触发的平仓可写入 `StrategyTriggeredCloses` 供下一周期 AI 参考。 |
| **代码落点** | `trader/auto_trader.go`：`checkDynamicStopLossTakeProfit` 内部调用的平仓路径；交易所适配器（Bybit/Binance 等）的平仓接口。 |

---

### 5.9 支撑层：代码底层逻辑、策略参数、提示词

| 层次 | 内容 | 代码/配置落点 |
|------|------|----------------|
| **代码底层逻辑** | 主循环、上下文构建、数据拉取、过滤、方向、开仓、止盈止损、平仓、存储与 API。 | `trader/auto_trader.go`、`kernel/engine.go`、`kernel/pipeline.go`、`market`、`store`、`api`。 |
| **策略参数** | 币种来源、K 线与指标开关、风控（仓位/杠杆/置信度）、多层过滤（Layer1/2/3）、动态止盈止损、系统执行开仓/AI 仅开仓等。 | `store/strategy.go`（StrategyConfig 及子结构）；前端策略编辑与保存。 |
| **提示词** | System/User Prompt 结构、Schema（含 trend_view 等）、输出格式约定、AI 仅辅助时的约束说明。 | `kernel/engine.go`：BuildSystemPrompt、BuildUserPrompt、Schema；策略中的 PromptSections、CustomPrompt。 |

## 六、主链路数据流简图（与您提出的架构对应）

```
获取量化数据     →  fetchMarketDataWithStrategy + OI/资金流/排行
       ↓
量化数据分析     →  pipeline 规则计算 + 可选 AI（trend_view/摘要/regime/risk_alert）
       ↓
过滤机制        →  RunPipeline：Layer1 → Layer2 → Layer3 + 方向过滤 → ToSubmitSymbols
       ↓
判断方向        →  GetSystemEntryList(DirectionLong/Short, AllowLong/Short)
       ↓
开仓执行        →  系统按列表与策略默认参数开多/开空（或 AI 开仓模式用 AI 输出）
       ↓
止盈止损机制    →  checkDynamicStopLossTakeProfit（含 trend_view 调节）
       ↓
平仓            →  交易所平仓 + 记录与同步
```

**底层逻辑**贯穿全链路（Go 代码）；**策略参数**决定每层开关与阈值；**提示词**只影响 AI 辅助部分（分析输出与约束），不改变系统执行开平仓的规则。

## 八、以币安为主 + 四项 AI 辅助的完善优化（近期落地）

- **币安衍生数据**：策略中可开启「币安衍生数据」（多空比、资金费率、Taker 买卖比），使用币安 fapi 公开接口拉取，写入 Context 并格式化进 User Prompt，供 AI 与过滤参考；前端策略编辑中已提供开关。
- **AI 四项辅助**：在「系统执行开仓」模式下，AI 除 trend_view 外，可输出可选 `<analysis>`，包含 **market_summary**（本周期市场摘要）、**market_regime**（市场状态）、**risk_alert**（为 true 时本周期不执行系统开仓）；解析后写入 FullDecision，执行层根据 risk_alert 决定是否跳过系统开仓。
- **执行与风控**：risk_alert 为 true 时仅跳过本周期系统开仓并记日志，不影响持仓的止盈止损检查；trend_view 仍用于调节止损确认周期。

以上与「获取量化数据 → 量化数据分析 → 过滤机制 → 方向判断 → 止盈止损 → 平仓」的主链路一致，AI 仅作辅助、开平仓由系统执行。
