# 策略、代码逻辑与提示词整体分析

本文档从「是否生效」「是否合理」两方面，梳理当前策略配置、执行链路与提示词的一致性。

---

## 一、配置来源与生效路径

| 环节 | 数据来源 | 生效位置 |
|------|----------|----------|
| 策略配置 | 策略工作室保存 → DB `strategies.config` (JSON) | 交易员启动时 `LoadUserTradersFromStore` → `strategy.ParseConfig()` → `StrategyConfig` |
| 风险控制 | `StrategyConfig.RiskControl` | `DynamicStopLoss` / `DynamicTakeProfit` / `AIOnlyEntry` 等 |
| 策略引擎 | `kernel.NewStrategyEngine(config.StrategyConfig)` | 与 AutoTrader 同生命周期，共用同一份 config |
| 提示词 | `e.config`（同上 StrategyEngine） | `BuildSystemPrompt` / `BuildUserPrompt` / `formatStrategyDynamicSLTP` |
| 动态 SL/TP | `at.strategyEngine.GetConfig().RiskControl` | `checkDynamicStopLossTakeProfit()` 内创建 StopLossChecker / TakeProfitChecker |

**结论**：策略配置**单源**（DB 策略 JSON），加载后注入 StrategyEngine 与 AutoTrader；提示词与 SL/TP 检查器共用同一 `GetConfig().RiskControl`，**配置层面一致、会生效**。

---

## 二、AI 仅开仓（ai_only_entry）

| 项目 | 是否生效 | 说明 |
|------|----------|------|
| 配置 | ✅ | `RiskControl.AIOnlyEntry`，前端「AI 仅开仓」勾选 → 保存到策略 JSON |
| 提示词 | ✅ | `BuildUserPrompt` 中若 `AIOnlyEntry==true` 注入中英约束：「对已有持仓一律输出 hold，不要输出 close_long/close_short」 |
| 执行 | ✅ | `runCycle` 执行 AI 决策前：若 `ai_only_entry==true` 且动作为 `close_long`/`close_short`，**不执行**并记日志 "AI close xxx skipped (ai_only_entry=true, strategy handles exit)" |
| 平仓实际由谁做 | ✅ | 由每周期先执行的 `checkDynamicStopLossTakeProfit()`（动态止损/追踪止损/分层止盈等）触发平仓 |

**结论**：AI 仅开仓**生效且合理**——提示词约束行为，执行层屏蔽 AI 平仓，真实平仓来自策略 SL/TP。

---

## 三、动态止损 / 止盈（含分层止盈）

### 3.1 创建与触发顺序

- 每周期 `runCycle` 内**先**执行 `checkDynamicStopLossTakeProfit()`，**再**拉取行情、调用 AI、执行 AI 决策。
- 因此：**策略 SL/TP 优先于 AI 决策执行**，逻辑合理。

### 3.2 分层止盈（Scaled Take Profit）

| 项目 | 是否生效 | 说明 |
|------|----------|------|
| 配置 | ✅ | `DynamicTakeProfit.ScaledEnabled` + `ScaledLevels`；前端「启用分批止盈」+ 档位表 |
| 执行 | ✅ | 有档位即视为启用（`ScaledEnabled==nil` 时也检查），与「有档位即启用」的修正一致 |
| 检查顺序 | ✅ | 止盈内部**先检查分层、再检查固定**，避免固定与第一档同比例时直接全平、看不到分层 |
| 提示词 | ✅ | `formatStrategyDynamicSLTP()` 与执行一致：有档位即展示「分层止盈: x%平y%」 |

**结论**：分层止盈**生效且合理**；提示词与执行均已统一为「有档位即启用」。

### 3.3 平仓原因写入与展示

- 策略在**发出平仓单前**对持仓写入 `close_reason`（如 `system:tp:scaled`、`system:sl:trailing`）。
- OrderSync 将持仓标为 CLOSED 时**保留已有 close_reason**（不覆盖为 sync）。
- 若 DB 中 symbol 为「无 USDT」而配置为「带 USDT」，`SetPendingCloseReasonBySymbol` 会 fallback 更新，避免漏写。
- 前端：`sync`/`unknown` 显示「交易所同步」，仅 `manual` 显示「手动」；有 `inferred_close_reason` 时展示「推断：系统止盈/止损」。

**结论**：在已修复 symbol 兼容与保留原因的前提下，**平仓原因链生效且合理**。

## 四、提示词与执行一致性

| 提示词内容 | 对应逻辑 | 一致性 |
|------------|----------|--------|
| 「AI 仅开仓」：对已有持仓一律 hold | 执行层跳过 AI 的 close_long/close_short | ✅ |
| 「追踪止损与分层止盈由策略执行」 | checkDynamicStopLossTakeProfit 先于 AI 执行；分层/固定顺序已调整 | ✅ |
| 「分层止盈: x%平y%」 | 有档位即展示；执行端有档位即检查 | ✅（已统一） |
| 最大持仓数、仓位价值等硬约束 | BuildSystemPrompt 中的 Hard Constraints | ✅ |
| 本周期策略触发的平仓列表 | StrategyTriggeredCloses 注入 User Prompt | ✅ |

**结论**：当前提示词与执行逻辑**对齐**，无已知冲突。

## 五、潜在注意点与建议

1. **AI 仅开仓默认值**  
   - 默认 `ai_only_entry` 为 false，需用户在策略中勾选「AI 仅开仓」才会启用。  
   - 若希望「仅开仓 + 策略平仓」为默认行为，可在默认/优化策略模板中把 `AIOnlyEntry` 设为 true，或在前端默认勾选。

2. **固定止盈与分层同时开启**  
   - 已改为先检查分层、再检查固定，一般能先触发分层。  
   - 若固定百分比 ≤ 第一档，建议关闭固定止盈或把固定设得高于最后一档，避免语义重叠。

3. **历史订单无具体原因**  
   - 修复前产生的记录可能仍为「交易所同步」；新平仓会带 `system:tp`/`system:sl` 或推断原因。  
   - 需「真正原因」时依赖同期决策记录的推断逻辑（见 `docs/平仓类型显示说明.md`）。

4. **策略热更新**  
   - 策略修改后需**重启交易员**（或重新加载）才会载入新 config；运行中不自动热更。

---

## 六、小结

- **策略与代码**：配置单源、加载后贯穿 StrategyEngine 与 SL/TP 检查器，**生效**。  
- **提示词**：与 AI 仅开仓、分层止盈、策略执行顺序一致，**合理且已与执行统一**。  
- **分层止盈**：有档位即启用、先于固定止盈检查、提示词展示档位，**生效且合理**。  
- **平仓原因**：预设原因保留、symbol 兼容、前端与推断展示，**链路过关**。

若出现「配置了但感觉没生效」的情况，可优先排查：① 是否重启交易员加载新策略；② 日志中「分层止盈: 已启用」与 `scaled_levels` 数量；③ 是否勾选「AI 仅开仓」且期望由策略完全负责平仓。
