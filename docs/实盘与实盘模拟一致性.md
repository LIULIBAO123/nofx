# 实盘与实盘模拟一致性约定

## 原则

**实盘**与**实盘模拟**在以下方面必须保持一致，任何功能修改需**同时适用于两者**：

- **AI 提示词**：同一套 `BuildSystemPrompt` / 止盈止损专用提示词，不按 `IsSimulation` 分支。
- **AI 分析行为**：`<analysis>` 必填项（如 `market_regime`、`scenario`、`risk_alert`）、分析顺序建议、输出结构一致。
- **周期逻辑**：AI 周期、系统周期、止盈止损分析周期的调度与输出记录（思维链）一致。
- **看板与接口**：状态、决策、持仓、最新分析、方向池、周期输出历史等 API 与前端看板共用同一套逻辑与展示；仅数据来源为「当前选中的交易员」不同（实盘列表 vs 模拟列表）。

## 允许的差异

- **执行层**：实盘走交易所真实下单与成交；实盘模拟走 PaperTrader 纸面成交，不发出真实订单。
- **资金与账户**：实盘使用交易所实际余额；实盘模拟使用虚拟初始资金与本地恢复的持仓/已实现盈亏。
- **未运行时的回退**：模拟交易员未启动时，状态接口可返回 DB 静态信息；实盘未运行时返回 404。

## 实现位置

| 层级       | 说明 |
|------------|------|
| `kernel/engine.go` | 提示词构建不区分实盘/模拟，回测/实盘/模拟共用。 |
| `trader/auto_trader.go` | `Run()` 内 AI 周期、系统周期、止盈止损周期及输出记录不按 `IsSimulation` 分支；仅创建 Trader 实现（交易所 vs PaperTrader）与部分初始化（如余额拉取）不同。 |
| `api/server.go` | 状态、决策、持仓、最新分析等接口对实盘与模拟交易员一视同仁，返回结构一致。 |
| `web/App.tsx`、`TraderDashboardPage` | 看板数据请求与展示统一用 `isDashboard = currentPage === 'trader' \|\| currentPage === 'simulation'`，同一组件、同一 API、同一刷新策略。 |

新增功能或修改提示词/周期/看板时，请确保实盘与实盘模拟均覆盖，避免仅对一方做分支实现。
