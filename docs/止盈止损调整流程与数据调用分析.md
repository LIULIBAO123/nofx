# 止盈止损调整流程与数据调用完整分析

本文档描述当前系统中「止盈止损调整」的完整流程、触发时机，以及各环节调用的数据来源。

---

## 一、整体结构：两条并行链路

止盈止损相关逻辑分为两条相对独立、又相互配合的链路：

| 链路 | 作用 | 间隔/触发 |
|------|------|------------|
| **1. SL/TP 参数调整（AI 分析）** | 根据 5 种场景（choppy_hold / trend_ride / lock_profit / trend_weakening / high_vol_hold）产出每仓位的 **建议参数**（trail_aggressiveness、atr_mult_sl、lock_profit_pct 等），写入内存供执行层使用 | 由 **SLTPAnalysisInterval** 控制（如 3 分钟），仅当 `0 < SLTPAnalysisInterval < ScanInterval` 时启用 |
| **2. SL/TP 执行检查** | 按当前持仓、策略边界与 AI 调节后的参数，**实际判断是否触发止盈/止损并下单平仓** | 固定 **20 秒**（`sltpCheckInterval`），由独立 goroutine 定时执行 |

两者关系简要说明：

- **调整链路**：只做「拉数据 → 建 prompt → 调 AI → 解析 position_sl_tp_adjustments → 写入内存」；不写主决策记录、不发起开平仓。
- **执行链路**：只做「读持仓 + 读策略配置 + 读 AI 调节结果 → 算止损/止盈条件 → 满足则平仓」；不调 AI。
- 执行时用到的「每仓位的有效 SL/TP 配置」= 策略基础配置 + 策略档位（SL/TP Profile）+ **AI 调节结果**（在策略边界内生效）。

## 二、流程 1：SL/TP 参数调整（AI 分析周期）

### 2.1 触发条件与调度

- **入口**：主循环 `Run()` 内，当 `useSLTPAnalysis == true` 时，按 `nextSLTP = lastSLTPTick + SLTPAnalysisInterval` 调度。
- **条件**：`config.SLTPAnalysisInterval > 0` 且 `config.SLTPAnalysisInterval < config.ScanInterval`（即必须小于主 AI 周期，例如主周期 10 分钟、SL/TP 分析 3 分钟）。
- **配置来源**：前端/API 的 `sltp_analysis_interval_minutes` → `TraderManager` 转为 `config.SLTPAnalysisInterval`（`time.Duration`）。

### 2.2 执行函数：`runSLTPAnalysisCycle(scheduledAt time.Time)`

步骤概览：

1. **拉取持仓**
   - `at.trader.GetPositions()`  
   - 数据源：交易所 API 或 PaperTrader 内存（实盘/模拟一致）。
   - 无持仓则直接 return，不调 AI。

2. **为每个持仓组装 SLTPPositionInfo 与 Baseline**
   - 从持仓中读取：symbol、side、entryPrice、markPrice、quantity、leverage、unRealizedProfit、updateTime 等（兼容交易所与纸面格式）。
   - **计算**：pnlPct（基于保证金）、holdMinutes（当前时间 − updateTime）。
   - **拉取 K 线并计算 ATR**：
     - `at.marketClient.GetKlines(symbol, "15m", 50)`  
     - 数据源：行情接口（如 CoinAnk 等）。
     - `kernel.CalculateATR(klines, 14)` 得到该仓位标的的 ATR，写入 `SLTPPositionInfo.ATR`。
   - **策略边界**（来自 `at.strategyEngine.GetConfig().RiskControl`）：
     - 若启用 DynamicStopLoss：ATRMultiplierMin/Max、ConfirmCycles、以及 SL Profile（若该仓位有 `positionSLProfile[posKey]`）的对应字段。
     - 若启用 DynamicTakeProfit：LockProfitPercent 边界、TP Profile 的 LockProfitPercent。
     - 当前追踪档位：`positionTrailAgg[posKey]`（来自开仓时或此前 AI 主周期/本周期写入的 positionTPProfile、positionSLProfile、positionTrailAgg）。
   - 将上述边界写入 `info.ATRMultMin/Max`、`LockProfitPctMin/Max`、`ConfirmCyclesBase`、`TrailCurrent`，并生成 `baselinesToStore[posKey]`。

3. **读取 regime / scenario（上周期 AI 主决策缓存）**
   - `at.lastAIDecisionMu.RLock()` → `at.lastAIDecisionCache.MarketRegime`、`Scenario`。
   - 数据来源：**上一轮主 AI 周期**（runCycle）的 FullDecision 解析结果，在 `runCycle` 内赋值 `at.lastAIDecisionCache = aiDecision`。
   - 用于在 prompt 中告诉 AI 当前「市场 regime / scenario」，便于 5 种场景判断。

4. **拉取本周期实时市场数据，生成「当前市场上下文」**
   - 若 `at.strategyEngine != nil`：  
     `summary = at.strategyEngine.BuildLiveMarketSummaryForSLTP()`  
   - 否则或拉取失败时，回退：  
     `summary = at.lastMarketSummaryForSLTP`（主周期/系统周期里 `BuildCurrentCycleSummaryForSLTP(ctx)` 的缓存）。
   - **BuildLiveMarketSummaryForSLTP() 内部**：
     - **BTC 行情**：`e.FetchMarketData("BTCUSDT")` → 即 `market.Get("BTCUSDT")`（K 线等），得到 1h/4h/24h/7d 涨跌、MACD、RSI 等。
     - **Coinglass 全量 SL/TP 用数据**：`e.FillCoinglassDataForSLTP(ctx)`，详见下表。
   - **FormatMarketContextForSLTP(ctx)** 将上述 ctx 格式化为多行文本，作为 prompt 中的「Current cycle market context」。

5. **调用 AI**
   - `kernel.RunSLTPOnlyAnalysis(at.mcpClient, list, regime, scenario, summary)`  
   - 内部：`BuildSLTPOnlyPrompts(positions, regime, scenario, currentCycleSummary)` 生成 systemPrompt + userPrompt；再 `callAIWithCaching(mcpClient, sys, user, "")` 请求大模型。
   - AI 只输出 `<analysis>{ "position_sl_tp_adjustments": [ ... ] }</analysis>`，不包含主决策（不开平仓、不写主决策记录）。

6. **解析并写入内存**
   - `ParsePositionSLTPAdjustmentsFromRawResponse(raw)` 得到 `[]PositionSLTPAdjustment`。
   - 写入 `at.positionSLTPAdjustment[posKey]`，并刷新 `at.positionSLTPBaseline[posKey]`（来自本轮的 baselinesToStore）。
   - 更新 `at.lastSLTPCycleOutput`，并 `at.appendSLTPCycleOutput(adj, scheduledAt)` 写入思维链，供前端「止盈止损调整」板块展示。

### 2.3 SL/TP 分析周期内「调用的数据」汇总

| 数据类型 | 来源 | 说明 |
|----------|------|------|
| 持仓列表 | `trader.GetPositions()` | 交易所或 PaperTrader，含 symbol/side/entry/mark/quantity/leverage/unrealizedPnl/updateTime 等 |
| 每仓 15m K 线 | `marketClient.GetKlines(symbol, "15m", 50)` | 用于计算该标的 ATR，写入 prompt 与 baseline |
| 策略边界与档位 | `strategyEngine.GetConfig().RiskControl` + `positionSLProfile` / `positionTPProfile` / `positionTrailAgg` | ATR 倍数范围、锁利比例范围、确认周期、当前追踪档位 |
| regime / scenario | `lastAIDecisionCache.MarketRegime` / `Scenario` | 上一轮主 AI 周期解析结果（缓存） |
| 当前市场上下文（实时） | `BuildLiveMarketSummaryForSLTP()` | 见下「实时市场数据」表；失败则用 `lastMarketSummaryForSLTP` 缓存 |

**BuildLiveMarketSummaryForSLTP → FillCoinglassDataForSLTP + BTC 行情（实时市场数据）**：

| 数据项 | 接口/来源 | 说明 |
|--------|-----------|------|
| BTC 1h/4h/24h/7d、MACD、RSI | `FetchMarketData("BTCUSDT")` → market.Get | 行情数据 |
| 强平 1h/4h/24h（多/空 USD） | Coinglass: GetLiquidationAggregatedHistory("BTC","1h",24) | 聚合强平量 |
| OI 变化（BTC 1h/4h%） | Coinglass: GetOpenInterestExchangeList("BTC") | 用于趋势/衰竭判断 |
| 资金费率（BTC 多所） | Coinglass: GetFundingRateExchangeList("BTC") | 多所加权 |
| 多空比（BTC 全账户+大户） | Coinglass: GetGlobalLongShortAccountRatioHistory + GetTopLongShortAccountRatioHistory | 写入 CoinglassLongShortMap / BinanceLongShortMap |
| 恐惧贪婪 | Coinglass: GetFearGreedHistory(1) | 情绪指数 |
| BTC 市值占比 | Coinglass: GetBitcoinDominance() | 市场结构 |
| 山寨季 | Coinglass: GetAltcoinSeasonHistory(1) | 周期环境 |
| ETF 资金流（BTC/ETH） | Coinglass: GetETFBitcoinFlowHistory(7) / GetETFEthereumFlowHistory(7) | 近期净流入 |
| 鲸鱼指数 | Coinglass: GetWhaleIndexHistory("Binance","BTC","1h",1) | 大户行为 |
| CGDI / CDRI | Coinglass: GetCGDIIndexHistory("BTC",1) / GetCDRIIndexHistory("BTC",1) | 多空扩散/衍生品风险 |
| 强平热力图关键价位 | Coinglass: GetLiquidationAggregatedHeatmap("BTC","24h") | 关键价位摘要 |

## 三、流程 2：SL/TP 执行检查（每 20 秒）

### 3.1 触发与入口

- **启动**：`Run()` 中若非网格策略则 `at.startDynamicSLTPMonitor()`，内部 `time.NewTicker(sltpCheckInterval)`，`sltpCheckInterval = 20 * time.Second`。
- **每次 tick**：调用 `at.checkDynamicStopLossTakeProfit(nil, "")`（无主周期传入的 trendView 时传 nil；主周期内可能传入 trendViewByPosKey 与 globalScenario，见下）。
- **主周期内也会调用**：  
  - `runCycle` 末尾：`checkDynamicStopLossTakeProfit(trendViewByPosKey, globalScenario)`（带本周期 AI 的 trend_view 与 scenario）；  
  - `runSystemCycle` 末尾：`checkDynamicStopLossTakeProfit(nil, "")`。  
  因此执行检查既被 20 秒定时驱动，也会在每次主周期结束时执行一次。

### 3.2 执行函数：`checkDynamicStopLossTakeProfit(trendViewByPosKey, globalScenario)`

步骤概览：

1. **开关与配置**
   - 若未配置策略引擎或未启用 DynamicStopLoss / DynamicTakeProfit，直接 return。
   - 读取 `riskConfig.DynamicStopLoss`、`DynamicTakeProfit` 作为 base 配置。

2. **拉取持仓**
   - `at.trader.GetPositions()`  
   - 与 SL/TP 分析周期相同数据源；无持仓则 return。

3. **对每个仓位**
   - 解析 symbol、side、entryPrice、markPrice、quantity、leverage、unrealizedPnl、liquidationPrice、updateTime（含兼容纸面/交易所格式）。
   - **入场时间**：优先持仓里的 updateTime；若无则用 `positionFirstSeenTime[posKey]`；再否则查 DB `store.Position().GetOpenPositionBySymbol` 或 `GetOpenPositions` 取 EntryTime。用于最小持仓时间、追踪止损的「入场后最高/最低价」等。
   - **有效 SL/TP 配置**：  
     base 配置 + 该仓位 SL/TP Profile（`positionSLProfile`/`positionTPProfile`）+ `positionTrailAgg` 应用在 TrailingLevels 上。
   - **应用 AI 调节**：  
     `at.positionSLTPAdjustment[posKey]`（即 runSLTPAnalysisCycle 或主周期 AI 写回的 position_sl_tp_adjustments）  
     - 若存在：覆盖/修正 trail_aggressiveness、ATR 倍数（在策略 min/max 内）、lock_profit_pct（1~5% 内）。
   - **最小持仓**：若未满 MinHoldMinutes（SL/TP 配置或 Profile），跳过该仓位本轮的止盈/止损判断。
   - **峰值盈亏**：从 `at.peakPnLCache[posKey]` 读取，并用当前 pnlPct 更新峰值（用于追踪止损、分层止盈等）。
   - **分层止盈已触发档位**：`at.getScaledLevelsTaken(posKey)`，用于 TakeProfitChecker。

4. **K 线与技术指标（每仓位）**
   - `at.marketClient.GetKlines(symbol, tf, 50)`，tf 默认 "15m"（可由 stopLossConfig.KlinesTimeframe 指定，仅允许 15m/1h）。
   - `kernel.CalculateATR(klines, 14)`、`kernel.CalculateATR(klines, 28)` → atr、atrLong。
   - 入场后最高价（多）/最低价（空）：基于 K 线 OpenTime >= entryTimeMs 的 High/Low。
   - `kernel.FindSupportLevel` / `FindResistanceLevel`（或配置用 EMA20 替代）。

5. **先止盈、后止损**
   - **止盈**：`takeProfitChecker.CheckTakeProfit(...)`，若触发则 `executeTakeProfit`（并写入平仓原因、是否含 AI 调节等）；trailing_tp 可能受 TrailingTPConfirmMinutes 约束。
   - **止损**：`stopLossChecker.CheckStopLoss(...)`；若启用 ConfirmMinutes，则用 `slFirstTriggeredAt[posKey]` 做确认时长；触发则 `executeStopLoss`。
   - 锁定利润（LockProfitPercent）后，若价格回到入场价另一侧，会走 breakeven 止损逻辑。

### 3.3 执行检查阶段「调用的数据」汇总

| 数据类型 | 来源 | 说明 |
|----------|------|------|
| 持仓列表 | `trader.GetPositions()` | 与分析周期相同 |
| 入场时间 | 持仓字段 / `positionFirstSeenTime` / DB `GetOpenPositionBySymbol` 或 `GetOpenPositions` | 最小持仓、追踪止损区间 |
| 策略 + 档位 + AI 调节 | `strategyEngine.GetConfig().RiskControl`、`positionSLProfile`/`positionTPProfile`/`positionTrailAgg`、`positionSLTPAdjustment` | 有效 SL/TP 配置 |
| 峰值盈亏 | `peakPnLCache[posKey]` | 内存缓存，本函数内会更新 |
| 分层已触发档位 | `getScaledLevelsTaken(posKey)` | 内存/持久化（视实现） |
| 每仓 K 线 | `marketClient.GetKlines(symbol, tf, 50)`，tf 多为 15m | 用于 ATR、支撑/阻力、入场后极值 |
| 可选：trend_view / scenario | 参数 `trendViewByPosKey`、`globalScenario`（仅主周期 runCycle 传入） | 调节 SL 确认速度（reversing 更快） |

## 四、配置与间隔汇总

| 项 | 配置/常量 | 说明 |
|----|-----------|------|
| SL/TP 分析周期 | `SLTPAnalysisInterval`（如 3 分钟） | 来自 `sltp_analysis_interval_minutes`，需 >0 且 < ScanInterval 才启用 |
| SL/TP 执行检查间隔 | `sltpCheckInterval = 20 * time.Second` | 代码常量，独立 goroutine 固定 20 秒 |
| 主 AI 周期 | `ScanInterval`（如 10 分钟） | 主周期会写 lastAIDecisionCache、lastMarketSummaryForSLTP，并调用一次 checkDynamicStopLossTakeProfit |

```
┌─────────────────────────────────────────────────────────────────────────────┐

└─────────────────────────────────────────────────────────────────────────────┘
                                        ↓
┌─────────────────────────────────────────────────────────────────────────────┐
│  SL/TP 执行检查（每 20 秒 + 主周期末各一次）                                   │

│  1. GetPositions() → 持仓列表                                                 │
```

## 六、小结

- **止盈止损调整**：由 **SL/TP 分析周期**（如 3 分钟）驱动，拉取持仓、每仓 15m K 线（ATR）、策略边界、上一轮主周期的 regime/scenario、以及 **本周期实时市场数据**（BTC 行情 + Coinglass 全量 SL/TP 用数据），拼成多行市场上下文后调 AI，得到 position_sl_tp_adjustments 写入内存并展示在思维链。
- **止盈止损执行**：由 **20 秒定时 + 主周期末** 驱动，只读持仓、策略、AI 调节结果和每仓 K 线，不调 AI；满足条件即平仓。
- 所有「调用到的数据」已在上文表格中按流程列出；若需扩展数据源或调整间隔，可据此定位到具体函数与接口。
