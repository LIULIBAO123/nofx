# 多层过滤与方向池策略：设计与部署方案

本文档为在 nofx 上实现「多层过滤 + 方向池 + AI 只分析 / 系统执行 + 实时价格」的策略提供设计方案与分阶段部署计划，便于你按阶段实现和上线。

**实现状态（可运行版本）**：已在 `kernel/pipeline.go` 实现三层过滤与方向池逻辑，并在 `GetFullDecisionWithStrategy` 中接入；多空雷达 API 从 `kernel.GetPipelineState(traderID)` 读取实时状态。默认策略（`GetDefaultStrategyConfig`）已启用 `strategy_mode: multilayer_filter` 及 `multilayer_filter` 配置。

---

## 一、目标策略回顾

| 要素 | 目标行为 |
|------|----------|
| **AI 职责** | 只分析量化数据，输出方向、强度、可靠度、入场时机等；不直接下单、不平仓。 |
| **系统职责** | 币种过滤（三层）、方向池维护、开仓/平仓、止盈/止损（单独策略）全部由系统执行。 |
| **第一层** | 16 项条件全过才进入候选（入场时机 now/soon、量能、OI、长短周期对齐、流向、涨跌榜、可靠度、大户/全市场多空等）。 |
| **第二层** | 至少 6 因子 + 可靠度≥0.67 + 入场信心≥31%（技策略）。 |
| **第三层** | 开单前：OI 对齐 + 入场时机强度 + 自定义因子全过；**入场时机 <5 分钟**。 |
| **方向分析** | 趋势、动能、多周期（15m/1h/4h 至少两周期一致）；多/空方向池由 AI 分析结果填充。 |
| **实时价格** | 获取实时价格以更好掌握盈亏；止盈/止损检查使用最新价。 |

## 二、在 nofx 中的整体架构

### 2.1 现有流程（简化）

```
GetCandidateCoins() → buildTradingContext() → [无候选则只做 SL/TP] 
  → GetFullDecisionWithStrategy() → 解析 trend_view → checkDynamicStopLossTakeProfit() 
  → 执行开/平仓（AIOnlyEntry 时不执行 AI 的 close）
```

### 2.2 目标流程（引入多层过滤与可选方向池）

```
1. 币种源（现有 CoinSource）
      ↓
2. 【新增】第一层预过滤（N 项规则，可配置 16 项或精简版）
   - 数据：K 线方向、OI、量能、流向、涨跌榜、可靠度/信心（来自规则或 AI 轻量输出）
   - 输出：通过第一层的候选列表 + 每项不达标统计（便于前端展示）
      ↓
3. 【可选】方向池模式：AI 仅输出「方向+强度+可靠度+入场时机」，写入多/空池；
   或保持现有模式：AI 直接输出 open_long/open_short
      ↓
4. 【新增】第二层过滤（通过第一层的候选）
   - 至少 M 因子通过 + 可靠度≥R + 入场信心≥C（配置项）
   - 输出：待提交列表
      ↓
5. buildTradingContext（仅对「待提交」候选拉全量数据，节省 Token）
      ↓
6. AI 决策（若为方向池模式则只做方向/强度/时机；否则保持现有全量决策）
      ↓
7. 【新增】第三层开单前校验
   - OI 对齐、入场时机强度、自定义因子、**信号年龄 <5 分钟**
   - 通过才真正提交订单
      ↓
8. checkDynamicStopLossTakeProfit（【增强】检查前拉取最新 mark 价，实时价格）
      ↓
9. 执行开仓/平仓（现有逻辑，AIOnlyEntry 下不执行 AI 的 close）
```

### 2.3 与现有 nofx 的兼容

- **策略类型**：在 `StrategyConfig` 中增加 `strategy_mode: "classic" | "multilayer_filter"`（或通过 feature flag 控制）。  
  - `classic`：保持当前行为，不启用多层过滤与方向池。  
  - `multilayer_filter`：启用第一/二/三层过滤与入场时机校验；是否启用方向池可再设子开关。
- **止盈/止损**：继续使用现有 `DynamicStopLoss` / `DynamicTakeProfit`，无需重复造轮子，仅在「检查前取价」上增强实时性。
- **AI 仅开仓**：现有 `ai_only_entry` 已满足「平仓由系统执行」；多层过滤仅约束「谁可以进入候选、谁可以开单」。

## 三、配置设计（扩展策略 JSON）

以下为建议的配置扩展，便于你按阶段加字段而不破坏现有策略。

### 3.1 多层过滤开关与模式

```json
{
  "strategy_type": "ai_trading",
  "strategy_mode": "classic",
  "multilayer_filter": {
    "enabled": true,
    "direction_pool_mode": false,
    "layer1": { ... },
    "layer2": { ... },
    "layer3": { ... }
  }
}
```

- `strategy_mode`: `"classic"` | `"multilayer_filter"`
- `multilayer_filter.enabled`: 是否启用多层过滤。
- `multilayer_filter.direction_pool_mode`: 是否启用方向池（AI 只填多/空池，再由系统按池+二层/三层决定开单）。先实现 `false`，后续再加方向池逻辑。

### 3.2 第一层（Layer1）配置

```json
"layer1": {
  "required_all": true,
  "items": [
    { "id": "entry_timing", "enabled": true, "allowed": ["now", "soon"] },
    { "id": "volume_ok", "enabled": true },
    { "id": "oi_ok", "enabled": true },
    { "id": "long_tf_aligned", "enabled": true },
    { "id": "short_tf_aligned", "enabled": true },
    { "id": "flow_aligned", "enabled": true },
    { "id": "price_ranking_aligned", "enabled": true },
    { "id": "reliability_min", "enabled": true, "value": 0.4 },
    { "id": "whale_direction_aligned", "enabled": true },
    { "id": "market_direction_aligned", "enabled": true }
  ],
  "max_signal_age_minutes": 5
}
```

- `required_all`: 是否要求全部启用项通过才进入候选。
- `items`: 可配置 16 项或精简 10 项；每项 `id` 对应一段规则逻辑（见下节）。
- `max_signal_age_minutes`: 第三层会用到「信号年龄 <5 分钟」的阈值，这里统一配置。

说明：第一层不达标统计（按币种、按条件）可在执行层用 map 记录，供 API/前端展示「第一层16项不达标统计」。

### 3.3 第二层（Layer2）配置

```json
"layer2": {
  "min_factors": 6,
  "reliability_threshold": 0.67,
  "entry_confidence_threshold_pct": 31
}
```

- 因子列表可与第一层共用同一批检查项，通过数量 ≥ `min_factors` 即通过第二层。
- 可靠度、入场信心若暂无 AI 输出，可用规则近似（例如多周期一致数、OI 方向与价格同向等打分为 0–1）。

### 3.4 第三层（Layer3）配置

```json
"layer3": {
  "oi_aligned_required": true,
  "entry_timing_strength_min": 0.5,
  "custom_factors_required": true,
  "max_signal_age_minutes": 5
}
```

- 开单前最后一次校验；不通过则不提交订单，只记录原因。

### 3.5 实时价格（用于止盈/止损）

```json
"realtime_price": {
  "enabled": true,
  "fetch_before_sltp_check": true,
  "source": "exchange_mark"
}
```

- `fetch_before_sltp_check`: 在 `checkDynamicStopLossTakeProfit` 前拉取一次最新 mark 价（或订阅推送），用该价格做 SL/TP 判断与盈亏展示。

## 四、模块与代码落点

### 4.1 第一层预过滤

- **位置**：新包 `filter` 或 `kernel/filter.go`（与 kernel 同层，便于用 kernel 的 K 线/指标结果）。
- **输入**：候选列表（来自 `GetCandidateCoins`）、每标的的行情与量化数据（可从 `buildTradingContext` 的中间数据或单独拉取轻量数据）。
- **输出**：通过第一层的 symbol 列表 + 每标的未通过项列表（用于「第一层16项不达标统计」）。
- **依赖**：K 线多周期方向（4h/1h/15m 可沿用现有 formatMarketData 逻辑）、OI、量能、流向、涨跌榜（现有 provider/nofxos 等）、可靠度/入场信心（规则计算或占位 0.5）。

建议先实现 8–10 项可配置项，名称与「外部策略分析」文档一致（entry_timing, volume_ok, oi_ok, long_tf_aligned, short_tf_aligned, flow_aligned, price_ranking_aligned, reliability_min, whale_direction_aligned, market_direction_aligned）。  
**入场时机**：若暂无 AI 输出，可用「最近一次出现多周期同向的时间」与当前时间差 <5 分钟视为 now/soon。

### 4.2 第二层过滤

- **位置**：同一 `filter` 包，`Layer2Filter(candidates, layer1Passed, config)`。
- **输入**：通过第一层的候选 + 每标的因子通过情况 + 可靠度/入场信心（规则或占位）。
- **输出**：通过第二层的待提交列表。

### 4.3 第三层开单前校验

- **位置**：`trader/auto_trader.go` 中「执行开仓」前；或 `trader` 包内新函数 `ValidateLayer3(symbol, side, ...)`。
- **输入**：当前订单参数、OI 对齐结果、入场时机强度、自定义因子、信号时间。
- **逻辑**：`max_signal_age_minutes` 内且 OI/强度/自定义因子全过才返回 true，否则记录原因并拒绝开单。

### 4.4 方向池（可选，第二阶段）

- **位置**：新表或内存结构 `DirectionPool(Long []SymbolWithScore, Short []SymbolWithScore)`；AI 输出改为「仅方向+强度+可靠度+时机」，由 engine 或新模块写入池。
- **与开单衔接**：仅从「通过第二层」且出现在方向池对应方向上的标的里取待提交，再经第三层后开单。  
可放在「第一阶段」之后再做，避免首版过于复杂。

### 4.5 入场时机与信号年龄

- **字段**：在决策结果中增加 `entry_timing: "now"|"soon"|"later"` 和 `signal_time`（或使用决策记录时间）。
- **存储**：若采用方向池，可在池条目中存 `signal_time`；否则在当次 cycle 的决策里带出，开单时用当前时间 − signal_time 与 `max_signal_age_minutes` 比较。

### 4.6 实时价格

- **位置**：`checkDynamicStopLossTakeProfit` 开头；或 `kernel/position_manager` 中做 SL/TP 判断前。
- **实现**：对当前持仓的 symbol 调用交易所 `GetPositions` 或单独行情接口取最新 mark 价，覆盖 context 中的 mark 价再计算盈亏与触发条件。若交易所无单独 ticker，可保持「每周期拉取」但将「SL/TP 检查频率」提高（例如独立 goroutine 每 30s 检查一次并用最新一次 GetPositions 结果）。

## 五、分阶段实现与部署计划

### 阶段 0：准备（当前即可做）

- 在 `store/strategy.go` 中为 `StrategyConfig` 增加可选字段：
  - `StrategyMode string`（如 `classic` / `multilayer_filter`）
  - `MultilayerFilter *MultilayerFilterConfig`（见上 JSON 结构）。
- 在 `RiskControlConfig` 或单独结构中增加 `RealtimePrice RealtimePriceConfig`。
- 保持默认 `strategy_mode == "classic"` 且 `MultilayerFilter == nil`，保证现有策略不受影响。
- **部署**：仅合并配置结构，不启用新逻辑；重新编译部署即可。

### 阶段 1：第一层预过滤 + 配置开关

- 实现 `filter` 包（或 `kernel/filter.go`）：
  - 实现 8–10 项可配置检查（entry_timing 用「多周期同向且最近一次时间」或占位），输出「通过列表 + 未通过项统计」。
- 在 `buildTradingContext` 之后、`GetFullDecisionWithStrategy` 之前插入：
  - 若 `strategy_mode == "multilayer_filter"` 且 `multilayer_filter.enabled`，则对 `ctx.CandidateCoins` 跑第一层过滤，并覆盖 `ctx.CandidateCoins` 为通过列表；同时把「未通过项统计」写入 record 或新字段供 API 展示。
- 配置：为你的交易员绑定一个策略，在策略 JSON 中设置 `strategy_mode: "multilayer_filter"`、`multilayer_filter.enabled: true`、`layer1` 如上。
- **部署**：编译 → 替换二进制/镜像 → 重启交易员；在界面或日志中确认「无候选」时是否因第一层过滤导致（通过未通过项统计排查）。

### 阶段 2：第二层过滤 + 第三层开单前校验

- 实现第二层：对第一层通过列表计算「因子通过数、可靠度、入场信心」（可靠度/信心可先用规则近似），过滤出待提交列表；仅对待提交列表调用 `buildTradingContext` 全量数据（或保持现有 build 一次，但在传给 AI 前只保留待提交）。
- 实现第三层：在 `auto_trader` 执行开仓前调用 `ValidateLayer3`，校验 OI 对齐、入场时机强度、自定义因子、信号年龄 <5 分钟；不通过则跳过该笔开仓并打日志。
- **部署**：同阶段 1；用小仓位或模拟盘验证「开单明显变少、且多为多周期+OI 同向」即说明生效。

### 阶段 3：实时价格用于止盈/止损

- 在 `checkDynamicStopLossTakeProfit` 开头：若配置 `realtime_price.enabled` 且 `fetch_before_sltp_check`，则对当前持仓 symbol 拉取最新 mark 价（如再调一次 GetPositions 或行情接口），更新到传入的 position 或 context 中，再执行原有 SL/TP 逻辑。
- **部署**：配置 `realtime_price.enabled: true`，重启；观察止盈/止损触发是否更贴近实盘价格。

### 阶段 4（可选）：方向池 + AI 只输出方向/强度/可靠度/时机

- 新增方向池数据结构与持久化（若需要跨周期）；修改 AI 提示词与解析，使 AI 只输出「标的、方向、强度、可靠度、入场时机」；engine 将结果写入多/空池；待提交列表 = 第二层通过 ∩ 方向池对应方向；再经第三层后开单。
- **部署**：单独开关 `direction_pool_mode`，与现有「AI 直接输出 open_long/open_short」二选一或分策略类型使用。

### 阶段 5（可选）：前端展示

- 第一层不达标统计、第二层通过率、第三层拒绝原因、方向池多/空列表与可靠度/时机，通过现有决策记录 API 或新 API 提供给前端「挂单流程信息」「多空雷达」类界面。

## 七、环境与运行

- **配置**：策略 JSON 存数据库（现有策略编辑接口）；或首次部署时导入一份「多层过滤」预设策略并设为该交易员使用。
- **环境变量**：无新增必须项；若 NofxOS/交易所 API 已有，则多层过滤使用的 OI、流向、涨跌榜等沿用现有配置。
- **扫描间隔**：建议与参考策略一致，例如 5 分钟或 15 分钟一周期；第三层「信号年龄 <5 分钟」会自然限制在最近一个周期内信号才开单。
- **实盘前**：先用模拟盘或小仓位跑 1–2 天，确认第一/二/三层过滤与预期一致、无误杀或漏杀后再放大仓位。

## 八、总结

- **设计**：在 nofx 中通过 `strategy_mode` + `multilayer_filter` 配置引入三层过滤（第一层 N 项全过、第二层 M 因子+可靠度+信心、第三层 OI+时机强度+自定义+信号年龄<5 分钟），可选方向池与实时价格增强止盈/止损。
- **兼容**：默认 `classic`，现有策略与 AI 仅开仓、动态止盈止损不变；新逻辑仅在选择 `multilayer_filter` 时生效。
- **实施**：分 0→1→2→3→4→5 阶段，先配置与第一层，再二/三层，再实时价格，再方向池与前端，便于你逐步实现与部署，并随时回滚到 classic。

若你希望从某一阶段开始落地（例如先只做「第一层 10 项 + 第三层 5 分钟」），可以指定阶段与当前代码分支，我可以按该阶段给出更具体的函数签名与调用位置补丁说明。

## 九、当前已落地的配置结构（阶段 0）

以下已加入代码，便于你直接使用或通过 API/数据库编辑策略 JSON：

- **StrategyConfig** 新增字段：
  - `strategy_mode`: `"classic"`（默认）| `"multilayer_filter"`
  - `multilayer_filter`: `MultilayerFilterConfig`（含 layer1/layer2/layer3、direction_pool_mode）
- **RiskControlConfig** 新增字段：
  - `realtime_price`: `RealtimePriceConfig`（enabled、fetch_before_sltp_check、source）
- **MultilayerFilterConfig**：`Layer1Config`（items、required_all、max_signal_age_minutes）、`Layer2Config`（min_factors、reliability_threshold、entry_confidence_threshold_pct）、`Layer3Config`（oi_aligned_required、entry_timing_strength_min、custom_factors_required、max_signal_age_minutes）

**启用方式**：在策略 JSON 中设置 `"strategy_mode": "multilayer_filter"` 并填写 `multilayer_filter.layer1` 等；当前仅配置生效，过滤逻辑需按阶段 1–3 实现后才会真正执行。阶段 0 仅保证配置可保存、可读取、不报错。
