# 盈亏比长期 0.5:1、无法达到 3:1 的原因分析

## 结论：**是参数设置问题**

当前「连续多周期因盈亏比达不到 3:1 而无法开仓」、且实际显示约 **0.5:1**，主要来自**策略/系统里用于构建 SL/TP 的参数组合**，和盈亏比计算公式无关。

---

## 一、系统开仓（Pipeline 触发的开仓）

系统在构建开仓的 SL/TP 时逻辑如下：

| 项目 | 来源 | 当前默认/回退值 |
|------|------|------------------|
| **止损 SL** | `DynamicStopLoss.InitialStopPercent`；若为 0 则用**代码回退** | 默认 **0** → 回退 **5%** |
| **止盈 TP** | `DynamicTakeProfit.ScaledLevels[0].ProfitPercent`（第一档）；若无则回退 | **2.5%**；回退 6% |

因此：

- 实际使用多为：**SL 距离 = 5%，TP 距离 = 2.5%**
- **盈亏比 = 2.5% ÷ 5% = 0.5:1**，必然小于 3:1

对应代码位置：

- `trader/auto_trader.go`：系统开仓时若 `InitialStopPercent == 0`，用 `pct := 0.05` 作为 SL 回退；TP 取第一档 2.5%（或 6% 回退）。

所以：**系统开仓的 0.5:1 是当前参数与回退值直接导致的，不是计算错误。**

---

## 二、AI 开仓

- SL/TP 由 **AI 在决策 JSON 里填的 `stop_loss`、`take_profit`** 决定。
- 若 AI 习惯给出「止损偏宽、止盈偏近」（例如接近 5% 止损 + 2.5% 止盈），算出来也会是约 0.5:1，同样会被 3:1 风控拒绝。

Prompt 里虽有「Risk-Reward Ratio: ≥1:3」的说明，但未强制「你给出的 stop_loss/take_profit 必须满足该比例」，因此行为上仍可能偏向宽止损、近止盈。

---

## 三、如何通过参数满足 3:1（不自动改单笔 SL/TP）

在**不**对单笔单子做「为凑 3:1 而收紧 SL」的前提下，只能通过**策略/系统参数**让「默认或常用组合」自然达到 ≥3:1。

### 方案 A：给「系统开仓」一个满足 3:1 的初始止损（推荐）

- 目标：系统开仓时，**用策略里的初始止损 + 第一档止盈** 就能达到 ≥3:1。
- 当前：第一档止盈 = **2.5%**，要求 3:1 → 止损距离应 ≤ 2.5%÷3 ≈ **0.833%**。
- 做法：
  - 在策略里把 **`DynamicStopLoss.InitialStopPercent`** 设为 **0.8～1.0**（即 0.8%～1%），  
    这样系统开仓会用「约 0.8%～1% 止损 + 2.5% 止盈」→ 盈亏比约 **2.5～3.1:1**，可满足 3:1。
  - 若希望严格 ≥3:1，可设 **InitialStopPercent = 0.8**（0.8%），则 2.5/0.8 ≈ 3.125:1。

注意：0.8% 止损较紧，容易被震荡扫掉，是否采用需结合品种波动率与回测。

### 方案 B：改系统开仓的「回退止损」比例（代码层）

- 当前：`InitialStopPercent == 0` 时，代码用 **5%** 作为 SL 回退 → 与 2.5% TP 组合成 0.5:1。
- 若希望**在不设 InitialStopPercent 时，系统开仓也能达到 3:1**，可把该回退从 5% 改为「与第一档 TP 和 MinRiskRewardRatio 一致」：
  - 例如：回退 SL% = 第一档 TP% ÷ MinRiskRewardRatio = 2.5% ÷ 3 ≈ **0.833%**。
- 这样**仅改的是「默认/回退参数」**，不是对每笔单子单独收紧 SL；逻辑上仍是「参数设置使默认组合满足 3:1」。

### 方案 C：提高第一档止盈（不推荐，会改变止盈结构）

- 若坚持系统开仓用 5% 止损，要 3:1 则需止盈距离 = 5%×3 = **15%**。
- 即把 `ScaledLevels[0].ProfitPercent` 提到 15%，会明显拉长第一档止盈，与当前 2.5%/6%/10% 分批止盈设计差异大，一般不推荐。

---

## 四、小结与建议

| 现象 | 原因 |
|------|------|
| 实际盈亏比常为 **0.5:1** | 系统开仓：SL 回退 5% + 第一档 TP 2.5%；AI 开仓：AI 常给宽止损+近止盈 |
| 是否计算错误？ | **否**，公式一致且正确，问题在「谁在设 SL/TP、设成多少」 |
| 是否参数问题？ | **是**：当前默认/回退的 SL 与 TP 组合天然是 0.5:1 |

建议优先做两件事：

1. **策略里**：若你接受略紧的初始止损，将 **`InitialStopPercent`** 设为 **0.8**（0.8%），使系统开仓在「第一档 2.5% 止盈」下自然达到 ≥3:1。
2. **代码（已实现）**：在 `InitialStopPercent == 0` 时，系统开仓的 SL 回退已改为 **第一档 TP% ÷ MinRiskRewardRatio**（例如 2.5%÷3≈0.83%），未配置初始止损时默认组合即为 3:1，不再使用原先的 5% 回退。这是「默认参数」的修正，不是对单笔单子做自动收紧。

这样即可在不「为满足 3:1 而单笔收紧其他参数」的前提下，通过**参数设置/默认回退公式**解决「连续多周期因盈亏比 0.5:1 达不到 3:1 而无法开仓」的问题。
