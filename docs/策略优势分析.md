# NOFX 策略优势分析

本文在系统整体分析基础上，从**入场与决策**、**风控与执行顺序**、**止损策略**、**止盈策略**、**参数与一致性**、**系统层面**六方面归纳当前策略的优势。

---

## 一、入场与决策层优势

- **多时间框架约束**：提示词要求 AI 按 4h → 1h → 15m 定趋势再入场，且「仅当 4h 与 1h 同向才考虑开仓」，减少逆势单；入场时机要求「做多优先支撑/回调、做空优先阻力/反弹」，避免追涨杀跌。
- **OI 与资金流**：策略可结合持仓量变化、机构/散户资金流做过滤，做多要求 OI 增加+价涨、做空 OI 增加+价跌，降低假突破参与度。
- **信心度与盈亏比**：提示中要求信心度 ≥60、盈亏比 ≥1:3，促使 AI 在质量不足时少开或不开仓。
- **策略执行与 AI 分工清晰**：系统明确「止盈止损由策略执行」，AI 对已有仓位以 hold 为主，避免与动态 SL/TP 重复或冲突；reasoning 中需写出止损价、止盈价、ATR 倍数与周期，便于事后核对。

---

## 二、风控与执行顺序优势

- **先止损后止盈**：每周期先执行 `checkDynamicStopLossTakeProfit()`，再拉行情与 AI 决策；同一仓位同一周期内先满足止损即平仓，不再做止盈检查，逻辑清晰、避免争议。
- **最小持仓统一**：SL 与 TP 共用「最小持仓时间」，取两者较大值（已统一预设为 10 分钟），未满不参与任何动态止损/止盈，减少开仓即平仓与噪音触发。
- **锁利与盈亏平衡**：达 `LockProfitPercent`（保证金%）后，回撤到入场价时由**止损侧**触发 breakeven 止损，保护已有浮盈；且执行顺序上先判 breakeven 再走五类止损，避免锁利后仍被普通止损价打穿。
- **执行顺序在 Prompt 中明确**：已采纳建议，在策略动态 SL/TP 段落中写明「先止损检查再止盈；止盈内为 分层→回撤→固定→ATR→阻力」，AI 与人工复盘时理解一致。

---

## 三、止损策略优势

- **五类组合、可配置**：初始固定（默认关）、追踪止损（分层）、ATR、支撑/阻力、从未浮盈+反向过大早退，可按需开启组合；trigger_logic 支持 any/all，默认 any 符合「先到先执行」直觉。
- **高波动宽容**：ATR 止损在高波动（当前 ATR > 长期 ATR×1.2）时使用 Max 倍数并可选多 1 个确认周期，减少单 K 线假跌破；与「震荡市拿住仓」的设计一致。
- **逆势早退**：从未浮盈+反向过大早退仅对「一路反向、从未绿过」的仓位生效，不收紧正常 ATR 线，可在不提高日常止损敏感度的前提下限制极端逆势亏损。
- **确认与时间**：支持按周期数（ConfirmCycles）或按真实分钟数（ConfirmMinutes）确认，满足条件持续成立才执行，降低毛刺触发。
- **可追溯**：平仓原因写入 `system:sl:initial/trailing/atr/support_resistance/breakeven/adverse_never_profit` 等，便于统计与复盘。

---

## 四、止盈策略优势

- **五类组合、分层优先**：分层 → 回撤止盈 → 固定 → ATR → 阻力/支撑；分层排第一且支持按档位部分平仓与已触发档去重，适合「有明确档位」时先落袋再博更高。
- **回撤止盈不依赖高挡位**：有盈利且从峰值回撤达标即触发，不要求必须涨到某固定%；ATR 与确认时长防震荡，适合「涨不到高挡就回落」时锁利。
- **与波动适配**：回撤止盈用 max(固定%, ATR%)；ATR 止盈可开「高波动用 Max 倍数」，目标随波动放大；阻力/支撑与 K 线结构一致。
- **按币种差异化**：回撤止盈支持山寨单独激活%与回撤%（非 BTC/ETH），便于主流与山寨不同波动下分别调参。
- **口径已明确**：止盈档位与回撤止盈均为**价格%**；锁定利润阈值为**保证金%**，已在 Prompt 与前端说明中写清，减少混淆。

---

## 五、参数与一致性优势

- **预设统一**：后端 GetDefaultStrategyConfig、前端 DynamicStopLossEditor/DynamicTakeProfitEditor 的 defaultConfig 与 kernel 回退默认已对齐关键项（min_hold 10、ATR TP max 4.0、高波动阈值 1.2、LockProfitPercent 2.5 等），新建策略与默认模板行为一致。
- **Prompt 与执行一致**：formatStrategyDynamicSLTP 输出的「有无/档位/倍数/阈值」与 kernel 实际使用一致；执行顺序已在 Prompt 中写明，便于 AI 与人工理解。
- **文档闭环**：止盈/止损参数预设与说明、系统整体分析、策略优势分析等文档形成闭环，后续改预设或顺序时可同步更新，避免再次出现前后端或 prompt 与代码不一致。

---

## 六、系统层面优势

- **配置单一来源**：策略来自 DB 绑定策略的 JSON，缺失字段由 kernel 回退，无多处「合并默认」带来的歧义；运行时不因 nil 崩溃。
- **回测与实盘对齐**：Trailing 峰值已改为自开仓以来的 running high/low，与实盘一致；SL/TP 检查顺序与数据源在回测与实盘一致。
- **可扩展**：策略结构支持多币种、多周期、多信号源（如 AI500、OI 排行）；SL/TP 类型与参数均可通过配置扩展，无需改核心循环。

---

## 七、小结

| 维度 | 优势要点 |
|------|----------|
| **入场** | 多周期共振、OI/资金流过滤、信心度与盈亏比约束、策略与 AI 分工清晰 |
| **风控** | 先止损后止盈、最小持仓统一、锁利 breakeven、执行顺序在 Prompt 中写明 |
| **止损** | 五类组合、高波动宽容、逆势早退、确认周期/分钟、可追溯 |
| **止盈** | 五类组合、分层优先、回撤不依赖高挡、波动与币种适配、价格%与保证金%口径明确 |
| **参数** | 预设统一、Prompt 与执行一致、文档闭环 |
| **系统** | 配置单一来源、回测与实盘对齐、可扩展 |

整体上，当前策略在**入场质量约束**、**风控顺序与锁利**、**止损/止盈多类型组合与防震荡**、**参数与口径一致性**以及**可追溯与可扩展**方面具备明确优势；已采纳的建议（执行顺序与口径说明写入 Prompt、前端锁利描述注明保证金%）进一步强化了可理解性与一致性。
