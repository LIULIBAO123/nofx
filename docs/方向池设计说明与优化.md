# 方向池设计说明与优化

本文档说明 nofx 多层过滤中的**方向池**（Direction Pool）设计、数据流、配置项与已实现的优化，以及后续可优化点。

---

## 一、方向池的角色

- **输入**：通过 Layer1 的标的列表（symbols）。
- **输出**：**DirectionLong**（做多池）、**DirectionShort**（做空池），每项为 `DirectionPoolItem`（标的、强度、可靠度、市场状态、时机等）。
- **用途**：
  1. 与 Layer2 通过的列表一起，经「允许做多/做空」过滤后得到 **ToSubmitSymbols**（待提交开仓列表）。
  2. 系统开仓时通过 **GetSystemEntryList(state, opts)** 从 ToSubmitSymbols 中解析出每个标的应开多还是开空（若同时在多空池则取 StrengthPct 更高的一侧）。
  3. Layer3 开单前校验 **EntryTimingStrengthMin** 时，用方向池中该标的的 **StrengthPct** 做门槛。
  4. 多空雷达 API 展示多/空池列表，供前端展示。

---

## 二、当前设计概览

### 2.1 归池规则（buildDirectionPools）

- 对每个标的取 `ctx.MarketDataMap[symbol]`，计算：
  - **多周期一致数 alignedCount**：4h/1h 涨跌同号 + 1h 与短趋势(价 vs EMA20) 同向，0~2。
  - **动能**：MACD 与 1h 涨跌同向（momentumOk）。
- **强侧**：alignedCount ≥ 1 且 momentumOk → StrengthPct = 70 + alignedCount×15，ReliabilityPct = 40 + alignedCount×15 + (RSI 合理时 +10)。
- **弱侧**：否则 → StrengthPct=50，ReliabilityPct=35。
- **方向归属**：
  - **SingleSideOnly == false（默认）**：按 1h 涨跌归入多或空（涨→多，跌→空）。
  - **SingleSideOnly == true**：分别计算「做多时的 StrengthPct」与「做空时的 StrengthPct」（含 applyDirectionBonus），归入**强度更高的一侧**，保证每标的只在一侧。

### 2.2 补强数据加成（applyDirectionBonus）

在基础 StrengthPct/ReliabilityPct 上，按以下数据做**加分**（不扣分）：

| 数据源 | 做多加成条件 | 做空加成条件 | 幅度（约） |
|--------|--------------|--------------|------------|
| Binance 多空比 | LongAccount > 0.5 | ShortAccount > 0.5 | Strength +5, Reli +3 |
| OI 排行 | 在 OI 增榜 | 在 OI 减榜 | Strength +5, Reli +3 |
| 净流入排行 | 在机构净流入榜 | 在机构净流出榜 | Strength +5, Reli +3 |
| 涨跌榜 | 在涨幅榜 | 在跌幅榜 | Strength +5, Reli +3 |
| 强平聚合 1h | 空头强平占比 > 55% | 多头强平占比 > 55% | Strength +2 |
| 资金费率 8h 均值 | \|费率\| ∈ [-0.01, 0.01] | 同上 | Strength +2, Reli +1 |
| Basis（永续-现货） | basis > 0 | basis < 0 | Strength +2, Reli +1 |

加成后 StrengthPct / ReliabilityPct 上限 100。

### 2.3 DirectionPoolItem 字段含义

| 字段 | 含义 | 当前赋值方式 |
|------|------|----------------|
| Symbol | 标的 | 输入 symbol |
| StrengthPct | 方向强度 0~100 | 多周期一致 + 动能 + 补强加成 |
| Score | 与 StrengthPct 一致，0~1 | StrengthPct/100 |
| MarketCondition | 市场状态 | strong_trend / trend / weak_trend（由 alignedCount 决定） |
| ReliabilityPct | 可靠度 0~100 | 同上 + 补强加成 |
| Timing | 入场时机 | 强侧 "now"，弱侧 "soon" |
| VolumePricePct | 量价比 | 固定 10（占位） |
| FromAI | 是否来自 AI | 固定 false（系统池） |

### 2.4 与 ToSubmit、开仓的衔接

- **ToSubmitSymbols** = Layer2 通过 ∩ （在 DirectionLong 或 DirectionShort 中）∩ 多空雷达允许方向。
- **GetSystemEntryList**：对 ToSubmitSymbols 中每个标的，若在多空两侧则取 StrengthPct 更高的一侧，输出 `open_long` / `open_short`。
- **Layer3**：开单前校验信号年龄、是否在 ToSubmit、OI 对齐（可选）、**EntryTimingStrengthMin**（用方向池中该标的的 StrengthPct）。

## 三、已实现的方向池配置与优化

### 3.1 配置项（DirectionPoolConfig）

在 `store.StrategyConfig.MultilayerFilter.DirectionPool` 下：

| 配置 | 类型 | 说明 |
|------|------|------|
| **min_strength_pct** | float64 | 仅将 StrengthPct ≥ 此值的标的放入方向池；0 表示不过滤。 |
| **single_side_only** | bool | 为 true 时每标的只归入多空池中**强度更高的一侧**（双侧计算 StrengthPct 后比较），避免同标的出现在两侧。 |
| **sort_by_strength** | bool | 为 true 时多/空池按 StrengthPct **降序**排列，且 **ToSubmitSymbols** 按强度降序，开仓与 API 展示优先高强度标的。 |

### 3.2 逻辑调整摘要

1. **buildOneDirectionItem(sym, md, ctx, isLong)**  
   为指定标的与方向（多/空）计算单项，统一计算 StrengthPct、ReliabilityPct、MarketCondition、Timing 并调用 applyDirectionBonus，供单侧归属与 SingleSideOnly 双侧比较使用。

2. **SingleSideOnly**  
   对每个标的分别计算「做多项」与「做空项」，只加入 StrengthPct 更高的一侧，保证每标的至多出现在一个池中。

3. **MinStrengthPct**  
   归池前过滤：仅当 StrengthPct ≥ 配置值时才加入对应池；未达标的标的不进入方向池，也不会进入 ToSubmitSymbols（因 ToSubmit 必须同时在 Layer2 通过且在方向池中）。

4. **SortByStrength**  
   - 对 DirectionLong、DirectionShort 按 StrengthPct 降序排序。  
   - 对 ToSubmitSymbols 按「该标的多空两侧最大 StrengthPct」降序排序，使开仓顺序与强度一致。

5. **补强数据**  
   applyDirectionBonus 已纳入 **Basis**、**资金费率 8h 均值**，与 Binance 多空比、OI/净流入/涨跌榜、强平聚合一致，用于方向池强度与可靠度加成。

6. **MarketCondition / Timing**  
   由 alignedCount 与 momentum 决定：alignedCount=2 → strong_trend、1 → trend、0 → weak_trend；强侧 Timing="now"，弱侧 Timing="soon"。

## 四、已实现的后续优化（全部落地）

| 项 | 实现说明 |
|----|----------|
| **VolumePricePct 真实化** | `volumePricePctFromMD(md)`：用 `IntradaySeries.Volume` 计算近期量/均量×10，上限 100，无数据时 10；在 `buildOneDirectionItem` 中赋值。 |
| **方向池权重/阈值可配置** | `DirectionPoolConfig` 增加 `StrengthBonusCap`、`ReliBonusCap`（0=不设限）；`applyDirectionBonus` 在累加后按上限裁剪。 |
| **与 Layer2 一致化** | `FilterPoolByLayer2`：为 true 时在 `buildDirectionPools` 内对每个标的调用 `evaluateLayer2`，仅通过 Layer2 的标的才进入方向池。 |
| **单标的强度平滑** | `EnableStrengthSmoothing`、`StrengthSmoothingWeight`；`directionStrengthCache` 按 traderID+symbol 存上一周期 StrengthPct；`applyStrengthSmoothing` 在 RunPipeline 归池后执行，smoothed = weight×last + (1-weight)×current，首周期用当前值。 |
| **API 与前端** | 雷达 API 已返回方向池（含 strength_pct、market_condition、timing、volume_price_pct）；策略工作室新增「方向池」区块，可配置 min_strength_pct、single_side_only、sort_by_strength、filter_pool_by_layer2、enable_strength_smoothing、strength_smoothing_weight、strength_bonus_cap、reli_bonus_cap。 |

## 五、后续可扩展点

- **VolumePricePct 权重**：当前仅展示与均量比；若需参与排序或门槛，可在 GetSystemEntryList 或排序逻辑中引入 VolumePricePct。
- **各数据源加成开关**：当前仅做加成上限；若需按数据源开关（如关闭 Binance 多空加成），可在 DirectionPoolConfig 中增加 Enable* 等字段并在 applyDirectionBonus 中判断。
- **方向池与 Layer2 共用因子**：若希望方向池基础分与 Layer2 因子一致，可抽离共用因子计算函数，供 Layer2 与 buildOneDirectionItem 复用。

---

## 六、小结

- 方向池根据**多周期一致 + 动能**得到基础强度与可靠度，再通过 **applyDirectionBonus** 纳入 Binance 多空比、OI/净流入/涨跌榜、强平、资金费率 8h、Basis 等补强数据。
- **DirectionPoolConfig** 支持最低强度过滤、单侧归属、按强度排序；**ToSubmitSymbols** 在启用排序时按强度降序，与方向池顺序一致，便于优先开高强度标的。
- 上述「四、已实现的后续优化」已全部落地；「五、后续可扩展点」为可选增强。
