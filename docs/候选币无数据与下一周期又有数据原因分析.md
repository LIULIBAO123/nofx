# 候选币「无数据」与「下一周期又有数据」原因分析

## 一、现象

- **本周期**：AI 思维链里出现「4h/1h/15m 无数据，无法判断」「系统未提供这些币种的详细技术指标数据（如 EMA、MACD、RSI），无法进行多时间框架分析，故不能开仓」。
- **下一周期**：同样的候选币（如 BTC、ETH、SOL）又有了 K 线/技术数据，可以正常做多周期分析。

即：**行情/技术数据呈间歇性「有时无、有时有」**。

---

## 二、数据流简要

1. **候选列表**：每周期由 `GetCandidateCoins()` 得到（OI 榜、AI500、静态列表等），**每周期可能不同**。
2. **行情拉取**：`fetchMarketDataWithStrategy` 先为**持仓**拉 K 线，再按顺序为**候选币**拉 K 线（最多 `max_coins_in_prompt` 个）。
3. **数据来源**：普通币种用 **CoinAnk（或 Binance）** 的 K 线接口；逐币、逐周期调用。
4. **写入 Prompt**：只有 `MarketDataMap` 里**有数据**的币种才会在「Candidate Coins」里展示；**持仓币**只在「Current Positions」里展示，不重复出现在候选区块。

因此：**只要某个候选币本周期没进入 `MarketDataMap`，AI 就看不到它的 K 线/EMA/MACD/RSI，就会说「无数据」**。

---

## 三、为什么本周期会「无数据」

### 3.1 行情接口间歇失败（最常见）

- K 线来自外部接口（如 CoinAnk/Binance），**一次请求失败就不会把该币放入 `MarketDataMap`**。
- 可能原因：
  - 网络超时、抖动
  - 交易所/第三方限频（rate limit）
  - 接口短暂不可用
- 本周期：多个候选币请求失败 → 这些币在 Prompt 里没有技术数据 → AI 报「无数据」。
- 下一周期：请求恢复成功 → 同样候选币有数据 → 「又有数据」。

### 3.2 候选列表与展示逻辑

- **候选列表**每周期可能变化（OI 榜、资金流榜排名变化），顺序也可能变。
- 拉取时按**候选顺序**拉，且受 `max_coins_in_prompt` 限制，**前面的失败或跳过，后面的可能根本不会拉**。
- 若本周期排在前面的是「拉取失败」或「OI 过滤被跳过」的币，后面能拉到的币可能不足或为 0；下一周期顺序/名单变了，可能先拉到 BTC/ETH 等，就「又有数据」。

### 3.3 仅有持仓、无其他候选有数据

- 若本周期**只有持仓币**（如 FORMUSDT）拉取成功，则 `MarketDataMap` 里只有 1 个 symbol。
- 展示时：**持仓在「Current Positions」里展示；Candidate 区块只展示「非持仓且 MarketDataMap 里有数据」的币**，因此 Candidate 区块会为空。
- 但 OI/资金流等**排行榜**仍会列出 BTC、ETH、SOL 等，AI 会看到「排行榜有这些币，但候选区块没有它们的技术数据」→ 就会说「系统未提供这些币种的详细技术指标数据」「无数据」。

### 3.4 OI 过滤

- 候选币拉取成功后，若**持仓量（OI）低于阈值**（如 15M USD），该币会被**跳过、不加入 MarketDataMap**。
- 若本周期多个候选因 OI 低被过滤，候选区块就少或空；下一周期排名/名单变化，更多币通过 OI 过滤，就「又有数据」。

---

## 四、为什么「下一周期又会有」

- **接口恢复**：上一周期的超时/限频/故障在下一周期消失，请求成功，数据恢复。
- **候选名单/顺序变化**：下一周期 OI/资金流榜或信号源变化，优先拉到的币不同，或更多币被拉取并成功。
- **无持久化/无重试**：当前实现是「每周期重新拉、失败就跳过」，不缓存、不跨周期保留；所以**周期之间相互独立**，下一周期重新拉成功就会「又有」。

---

## 五、小结表

| 原因               | 本周期表现           | 下一周期表现     |
|--------------------|----------------------|------------------|
| 行情接口临时失败   | 多个/全部拉取失败    | 接口恢复后有数据 |
| 候选顺序/名单变化  | 先拉到的失败或被过滤 | 顺序变，先拉到成功 |
| 仅持仓有数据       | Candidate 区块为空   | 若有候选拉成功则有 |
| OI 过滤            | 多个候选被过滤掉     | 排名变，更多通过 |

---

## 六、可做的改进（建议）

1. **无候选数据时在 Prompt 中显式说明**  
   当本周期没有任何「非持仓」候选币拥有行情数据时，在 Candidate 区块加一句说明（中/英）：  
   「本周期暂无候选币种 K 线/技术数据（可能因行情接口暂时失败或候选列表为空），请仅基于当前持仓与排行榜信息决策。」  
   这样 AI 不会误以为「有候选但被隐藏」，减少误判。

2. **日志与监控**  
   - 每周期打日志：本周期请求失败的 symbol 数量、被 OI 过滤的数量、最终写入 Prompt 的候选数。  
   - 便于区分是「接口问题」还是「候选/OI 导致无数据」。

3. **可选：对主流币做保底拉取**  
   当本周期「非持仓」候选中有数据的不超过 0 或 1 个时，可**额外**对 BTCUSDT、ETHUSDT 做一次拉取并写入 `MarketDataMap`，保证至少有两个币有技术数据，减少「整周期无数据」的出现。

4. **可选：单次重试**  
   对 `GetWithTimeframes` 或底层 K 线请求失败时做**一次重试**（间隔 1～2 秒），降低偶发网络/限频导致的「本周期无数据」。

上述 1、2 可在现有架构下直接做；3、4 视需求与稳定性再加。
