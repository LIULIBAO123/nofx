# 止盈止损整体流程与逻辑分析

本文档从「开始」到「结尾」梳理止盈止损相关逻辑的完整流程，并标注已发现与已修复的逻辑问题。

---

## 一、流程总览（从开始到结尾）

```
开仓成功
    → 写入 positionFirstSeenTime[posKey]、positionTPProfile/SLProfile/TrailAgg[posKey] 等
    → 启动后或周期内：SL/TP 执行检查（每 20s）+ SL/TP 分析周期（每 SLTPAnalysisInterval）
        ↓
┌───────────────────────────────────────────────────────────────────────────────────┐
│ 1. SL/TP 分析周期（仅在有持仓时）                                                    │
│    runSLTPAnalysisCycle(scheduledAt)                                                │
│    → 拉持仓 → 拼 SLTPPositionInfo（含边界、当前生效参数、last_advice）              │
│    → 取 regime/scenario（上轮主周期缓存）、本周期实时市场 summary                    │
│    → 调 AI → 解析 position_sl_tp_adjustments → 写 positionSLTPAdjustment[posKey]   │
│    → 写 positionSLTPBaseline[posKey]、思维链                                       │
└───────────────────────────────────────────────────────────────────────────────────┘
        ↓
┌───────────────────────────────────────────────────────────────────────────────────┐
│ 2. SL/TP 执行检查（每 20s + 主周期/系统周期末各一次）                                │
│    checkDynamicStopLossTakeProfit(trendViewByPosKey, globalScenario)                │
│    → 拉持仓 → 每仓：入场时间、策略+Profile+AI 调节 → 有效 SL/TP 配置                 │
│    → 最小持仓检查 → 拉 K 线 → ATR、支撑/阻力、入场后极值                             │
│    → 先 CheckTakeProfit → 再 CheckStopLoss（含确认周期、trend_view/scenario 调节）  │
│    → 若触发 → executeTakeProfit / executeStopLoss → executeDecisionWithRecord       │
└───────────────────────────────────────────────────────────────────────────────────┘
        ↓
平仓成功（executeCloseLongWithRecord / executeCloseShortWithRecord）
    → 清理 posKey 相关：positionSLTPAdjustment、positionSLTPBaseline、positionTPProfile、
      positionSLProfile、positionTrailAgg、peakPnLCache、slConfirmCount、slFirstTriggeredAt 等
```

---

## 二、各阶段流程细节

### 2.1 开仓后：与 SL/TP 相关的初始化

| 步骤 | 位置 | 说明 |
|------|------|------|
| 写入 positionFirstSeenTime | executeOpenLongWithRecord / executeOpenShortWithRecord | `posKey = market.Normalize(decision.Symbol) + "_long"/"_short"`，用于后续最小持仓、追踪止损时间区间 |
| 写入 Profile / TrailAgg | 同上 | 若 AI 决策带了 TPProfile、SLProfile、TrailAggressiveness，写入 positionTPProfile、positionSLProfile、positionTrailAgg[posKey] |
| 写入 positionParamsMap | setPositionParams（开仓后调用） | 存止盈止损价格、ATR 等，供前端/API 展示；posKey 须与上述一致 |

**逻辑要点**：posKey 必须全局统一为 `market.Normalize(symbol) + "_" + strings.ToLower(side)`，否则分析周期写的 AI 调节、执行检查读的调节、平仓时清理会错位。

---

### 2.2 SL/TP 分析周期：runSLTPAnalysisCycle(scheduledAt)

| 步骤 | 数据/动作 | 说明 |
|------|------------|------|
| 1 | GetPositions() | 无持仓则直接 return，不调 AI |
| 2 | 每仓拼 SLTPPositionInfo | symbol/side 用 Normalize + 小写 side 得到 posKey；entry/mark/pnlPct/holdMinutes；GetKlines(symbol,"15m",50) → ATR |
| 3 | 策略边界 | RiskControl + positionSLProfile/TPProfile/TrailAgg → ATRMultMin/Max、LockProfitPctMin/Max、ConfirmCyclesBase、TrailCurrent |
| 4 | 当前生效参数 | 若 positionSLTPAdjustment[posKey] 存在，填 AppliedTrailAggressiveness、AppliedATRMultSL、AppliedLockProfitPct、LastAdvice |
| 5 | regime / scenario | lastAIDecisionCache（上一轮主周期），非本 SL/TP 周期 |
| 6 | 市场上下文 summary | BuildLiveMarketSummaryForSLTP()（本周期实时）；失败则用 lastMarketSummaryForSLTP |
| 7 | RunSLTPOnlyAnalysis(...) | 建 prompt、调 AI、解析 position_sl_tp_adjustments |
| 8 | 写回内存 | 仅对 AI 返回的仓位写 positionSLTPAdjustment[posKey]、positionSLTPBaseline[posKey]；未返回的仓位保留旧调节 |

**逻辑要点**：

- regime/scenario 来自「上一轮主周期」，与「本周期实时 summary」不同步，属设计取舍（主周期负责 regime，SL/TP 周期用实时数据做 5 种场景）。
- AI 若未返回某仓位，该仓位沿用上一轮调节，不会被动清空。

---

### 2.3 SL/TP 执行检查：checkDynamicStopLossTakeProfit(trendViewByPosKey, globalScenario)

| 步骤 | 数据/动作 | 说明 |
|------|------------|------|
| 1 | GetPositions() | 与分析周期同源 |
| 2 | 每仓 posKey | **必须** `market.Normalize(symbol) + "_" + side`，与分析周期、开仓、平仓一致 |
| 3 | 入场时间 | 持仓 updateTime → positionFirstSeenTime[posKey] → DB GetOpenPositionBySymbol/GetOpenPositions |
| 4 | 有效 SL/TP | base + Profile（positionSLProfile/TPProfile/TrailAgg）+ **positionSLTPAdjustment[posKey]** 应用（边界内） |
| 5 | 最小持仓 | holdDurationMs < minHoldMs 则跳过该仓止盈/止损判断 |
| 6 | 峰值与分层 | peakPnLCache[posKey]、getScaledLevelsTaken(posKey) |
| 7 | K 线与 ATR | GetKlines(symbol, tf, 50) → ATR(14)/ATR(28)、入场后最高/最低价、支撑/阻力 |
| 8 | 先止盈后止损 | CheckTakeProfit → 若触发 executeTakeProfit；CheckStopLoss → 确认周期（含 ConfirmCyclesDelta、trend_view、scenario）→ 若触发 executeStopLoss |
| 9 | 清理 | 仅对「当前仍存在的持仓」保留 slConfirmCount/slFirstTriggeredAt/tpTrailingFirstTriggeredAt；已不存在的 posKey 从这些 map 中 delete |

**逻辑要点**：

- trendViewByPosKey / globalScenario 仅在主周期 runCycle 末尾传入；20s 定时与 runSystemCycle 末尾传入为 nil / ""，此时不做 trend_view/scenario 对确认周期的调节。
- 执行检查不调 AI，只读已有配置与 AI 调节结果。

---

### 2.4 平仓：executeStopLoss / executeTakeProfit → executeDecisionWithRecord → executeClose*WithRecord

| 步骤 | 说明 |
|------|------|
| 设置平仓原因 | setPendingCloseReason；若为 AI 调节触发则 SetPendingCloseReasonAndDetailBySymbol(..., triggerDetail) |
| 执行平仓 | executeCloseLongWithRecord / executeCloseShortWithRecord；内部 posKey = market.Normalize(decision.Symbol) + "_long"/"_short" |
| 清理该 posKey | positionSLTPAdjustment、positionSLTPBaseline、positionTPProfile、positionSLProfile、positionTrailAgg、positionKeyLevels、peakPnLCache、slConfirmCount/slFirstTriggeredAt（在 executeStopLoss 执行后由 20s 循环的「清理已不存在仓位」逻辑也会删）、positionParamsMap 等 |

**逻辑要点**：平仓时必须用与开仓/分析/执行检查一致的 posKey 做删除，否则会留下「幽灵」调节或基线，影响 API 展示与下一仓同 symbol+side 的复用（若存在复用）。

## 三、已发现并修复的逻辑问题

### 3.1 posKey 不一致（已修复）

**问题**：  
部分路径用 `symbol + "_" + side`（symbol 来自交易所/纸面原始格式），部分用 `market.Normalize(symbol) + "_" + side`。若交易所返回小写 "btcusdt"，则会出现：

- 分析周期写入：positionSLTPAdjustment["BTCUSDT_long"]
- 执行检查读取：positionSLTPAdjustment["btcusdt_long"] → 读不到，AI 调节不生效
- 平仓清理：delete(positionSLTPAdjustment["btcusdt_long"]) → 删不到，造成残留

**修复**：  
所有使用 posKey 的地方统一为 `market.Normalize(symbol) + "_" + strings.ToLower(side)`（side 已小写处仅用 `"_" + side`），涉及：

- checkDynamicStopLossTakeProfit：构建 posKey、currentPositionKeys
- buildTradingContext：posKey 用于 positionFirstSeenTime、peakPnLCache、currentPositionKeys
- GetPositions（API）：posKey 用于 positionParamsMap、positionSLTPAdjustment/positionSLTPBaseline 等展示
- executeCloseLongWithRecord / executeCloseShortWithRecord：posKey 用于所有 delete
- executeOpenLongWithRecord / executeOpenShortWithRecord：posKey 用于 FirstSeenTime、Profile、TrailAgg 等
- UpdatePeakPnL / ClearPeakPnLCache：内部 posKey 使用 Normalize(symbol) + "_" + ToLower(side)

---

### 3.2 平仓时未清理 positionSLTPBaseline（已修复）

**问题**：  
平仓时只删除了 positionSLTPAdjustment[posKey]，未删除 positionSLTPBaseline[posKey]，导致已平仓仓位仍可能出现在「原始→调整后」基线展示中，且长期占用内存。

**修复**：  
在 executeCloseLongWithRecord 与 executeCloseShortWithRecord 的清理块中，在 delete(positionSLTPAdjustment) 的同时对 positionSLTPBaseline 加锁并 delete(positionSLTPBaseline, posKey)，锁顺序与 runSLTPAnalysisCycle 一致（先 positionSLTPAdjustmentMu 后 positionSLTPBaselineMu）。

## 四、设计上的合理取舍（非缺陷）

| 项 | 说明 |
|----|------|
| regime/scenario 来自主周期 | SL/TP 分析周期不重新调主模型求 regime/scenario，只用上一轮主周期缓存 + 本周期实时 summary，减少调用与延迟；AI 可在 prompt 内根据 summary 自行推断当前状态。 |
| AI 未返回的仓位保留旧调节 | 若本轮只返回部分仓位的 position_sl_tp_adjustments，未返回的仓位保留上一轮调节，避免因单次漏返或限流导致调节被误清空。 |
| 20s 与主周期末都做执行检查 | 20s 保证及时触发；主周期末再查一次并带入 trend_view/scenario，兼顾实时性与主周期结论。 |
| 执行检查不区分「是否来自 AI 调节」的配置来源 | 执行层只认「当前有效配置」；是否由 AI 调节仅用于记录平仓原因与详情（triggerDetail），不改变执行逻辑。 |
