# 技术指标与 K 线参数设置说明

本文档说明策略中**技术指标**与**K 线数量/时间周期**应如何设置，才能让 AI 有足够数据做趋势判断；以及参数与**提示词/策略文案**的一致性建议。

---

## 一、参数与「足够数据」的关系

### 1.1 K 线数量（PrimaryCount / 主周期 K 线数量）

- **含义**：每个时间周期（5m、15m、1h、4h 等）拉取并**参与计算、写入 Prompt 的 K 线根数**。当前实现中，各周期共用同一个「K 线数量」配置。  
- **配置项**：策略 → 市场数据 / K 线配置中的 **K线数量**（对应 `primary_count`）；默认预设中有 30 或 100，界面若显示 20 多为用户自定义。
- **后端**：先向交易所拉取 **200 根**，再按配置的 `PrimaryCount` 取**最近 N 根**写入 Prompt；**指标（EMA/MACD/RSI/ATR 等）是在 200 根上算的**，所以「当前值」不依赖 N 的大小，只有「发给 AI 的 K 线序列长度」会随 N 变化。

**「足够数据」建议：**

| 目的 | 建议 K 线数量 | 说明 |
|------|----------------|------|
| **指标计算有效** | 任意（含 20） | 后端用 200 根计算，最新一根的 EMA/MACD/RSI/ATR 已可靠；与 N=20 或 50 无关。 |
| **多周期趋势判断** | **20**（Token/费用优先） | 见下「K=20 时的用法」。 |
| **更长序列给 AI 看** | 50～100 | 4h 有 50 根 ≈ 8 天历史在 Prompt 里，趋势视野更长，但 Token 与费用明显增加。 |

**K 线数量 = 20 时（Token / 费用优先）**

因 **AI 大模型 token 输入长度与费用** 将 K 线数量设为 20 是合理选择，无需强行提高。

- **指标当前值**：EMA20、EMA50、MACD、RSI、ATR 等均在服务端基于 **200 根** 计算，再随最近 20 根一起写入 Prompt，故 **当前这根 K 线的指标值是可信的**，不因「只发 20 根」而失效。
- **趋势参考**：Prompt 中已包含每个标的的 **1h / 4h 涨跌幅**（多周期涨跌），由后端按 200 根区间计算，用于「1h 偏多/偏空、4h 偏多/偏空」的定性，可与 20 根 K 线序列配合做趋势判断。
- **20 根的含义**：20 根 4h ≈ 3.3 天、20 根 1h ≈ 20 小时、20 根 15m ≈ 5 小时；对「近期结构、当前状态」一般够用，更长趋势可依赖 **当前指标 + 1h/4h 涨跌幅** 综合判断。

**结论**：  
- **以 Token/费用优先、K 线数量=20**：保持 20 即可；趋势判断依赖「当前指标值（基于 200 根）+ 各周期 1h/4h 涨跌幅」与最近 20 根序列，**无需为趋势而强行改成 50**。  
- 若**不介意 Token 与费用**、希望 AI 看到更长 K 线历史，再考虑将 K 线数量提高到 50～100。

### 1.2 技术指标参数

当前策略/界面中常见指标及与「趋势判断」的对应关系如下。

| 指标 | 界面/配置参数 | 建议值 | 与提示词/Schema 的对应 |
|------|----------------|--------|-------------------------|
| **EMA** | 周期列表，如 `20,50` | **20, 50** | Schema 与提示词中大量使用「EMA20」「EMA50」定趋势、结构破坏；**保持 20 与 50** 可避免与文案不一致。 |
| **RSI** | 周期列表，如 `7,14` | **7, 14** | 提示词中常用 RSI7/RSI14、超买超卖区间；保持 7 与 14 即可。 |
| **MACD** | 多数为固定或留空 | **(12,26,9) 固定** | 后端 `market/data.go` 使用固定 12/26；若界面留空即表示用默认，**无需在策略里改**；提示词中「MACD」不写具体周期即可。 |
| **ATR** | 周期列表，如 `3,14` 或 `14` | **14** 或 **3,14** | 策略中 ATR 用于止损/止盈倍数；Schema 常写「ATR周期 14」；若加 3 可做短周期波动参考，主周期建议保留 14。 |
| **BOLL** | 周期，如 `20` | **20** | 布林带周期 20 与常见用法一致；若需与「20 周期中轨」等表述一致，保持 20。 |

**要点：**

- 指标**周期**与提示词/Schema 中写死的「EMA20」「EMA50」「RSI14」「ATR周期 14」等**保持一致**，AI 推理与数据一致，避免混淆。
- 若你将来要改成例如 EMA 10/30，需**同步改** Schema 和策略中所有「EMA20」「EMA50」的表述，否则会出现「数据是 EMA10/30，提示词还在说 EMA20/50」的不一致。

## 二、时间周期选择（与多周期趋势判断）

- **提示词/Schema** 明确采用「**4h 定方向、1h 确认、15m 入场**」的多周期框架。
- **建议**：  
  - 至少勾选 **15m、1h、4h**（若主周期为 15m，则 15m 为主、1h/4h 为辅助）。  
  - 5m 可作为更细的入场周期，但会增加数据量；若主周期已是 15m，5m 可选。  
- 这样 AI 拿到的数据与提示词中的「4h/1h/15m」一致，便于做趋势与结构判断。

---

## 三、参数设置后，策略与提示词是否需要变化？

### 3.1 不需要改的情况（推荐）

- **K 线数量**：保持 **20**（Token/费用优先）或改为 50～80（更重视长序列），**都不需要**改 Schema/提示词。  
  - 20 时趋势依赖「当前指标（200 根计算）+ 1h/4h 涨跌幅」；50+ 时 AI 多看到更长 K 线序列，表述仍为「多周期 K 线」「EMA/RSI/MACD」等，无需改文案。
- **指标周期与现有文案一致**：  
  - 保持 EMA=20,50、RSI=7,14、ATR=14、BOLL=20，MACD 用默认。  
  - 此时**策略说明与提示词不用改**，因为数据与文案一致。

### 3.2 需要同步改的情况

- **你改了指标周期**（例如 EMA 改为 10,30、RSI 改为 14,28）：  
  - **Schema / 策略说明 / 提示词**里所有写死的「EMA20」「EMA50」「RSI7」「RSI14」等，都要改成对应新周期（如「EMA10」「EMA30」），否则 AI 会按「20/50」理解，而实际数据是 10/30，容易错判。
- **你改了时间周期组合**（例如去掉 4h、只留 1h 和 15m）：  
  - 提示词中「4h 定方向」「先看 4h」等表述就不成立，需要改为「1h 定方向」或相应调整多周期逻辑，否则会与数据不符。

**建议**：  
- 若以「Token/费用可控 + 趋势判断」为主，**K 线数量=20 并保持指标周期 20,50 / 7,14 / 14 / 20** 即可，**策略与提示词无需改**；趋势依赖当前指标与 1h/4h 涨跌幅。  
- 若不介意 Token、希望 AI 看到更长 K 线历史，可将 K 线数量提高到 50～80，同样无需改文案。  
- 若将来要自定义指标周期或时间框架，再按上面规则**同步改**策略与提示词。

---

## 四、推荐配置小结（与当前提示词一致）

| 配置项 | 推荐值 | 说明 |
|--------|--------|------|
| **K 线数量** | **20**（Token/费用优先）或 **50～80**（更重视 Prompt 内长序列） | 20 时：当前指标基于 200 根计算仍可靠，趋势可结合 1h/4h 涨跌幅；50+ 可拉长 AI 可见 K 线历史，但 Token 与费用上升。 |
| **时间周期** | 至少 **15m、1h、4h**；主周期可为 15m 或 5m | 与「4h 定方向、1h 确认、15m 入场」一致。 |
| **EMA** | **20, 50** | 与 Schema/提示词中 EMA20、EMA50 一致。 |
| **RSI** | **7, 14** | 与 Schema/提示词中 RSI7、RSI14 一致。 |
| **MACD** | 保持默认（留空或 12,26,9） | 后端固定 12/26，无需在策略里改；提示词不写具体周期即可。 |
| **ATR** | **14** 或 **3, 14** | 主周期 14 与「ATR周期 14」一致；3 可选。 |
| **BOLL** | **20** | 与常见「20 周期布林」表述一致。 |

按上表设置后，**无需修改**策略与提示词；若之后你改了指标周期或时间框架，再按第三节「需要同步改」的部分处理即可。
