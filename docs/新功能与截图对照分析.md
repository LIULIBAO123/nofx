## 三、未完全实现或仅占位/配置的功能

### 3.1 第一层 16 项：部分为占位逻辑

| 条件 ID | 说明 | 当前实现 |
|---------|------|----------|
| entry_timing | 入场时机须为 now/soon | 占位：无信号时间则直接通过 `return true` |
| volume_ok | 量能达标 | ✅ 有实现：近期量 vs 均值 |
| oi_ok | OI 达标 | ✅ 有实现：OI 存在且 >0 |
| long_tf_aligned / short_tf_aligned | 长/短周期方向对齐 | 占位：有价格与 EMA20 则通过，未做真实多周期方向判断 |
| flow_aligned | 流向与方向一致 | 占位：通过 |
| price_ranking_aligned | 涨跌榜与方向一致 | 占位：通过 |
| reliability_min | 可靠度达到门槛 | 占位：通过 |
| whale_direction_aligned | 大户多空与方向一致 | 占位：通过 |
| market_direction_aligned | 全市场多空与方向一致 | 占位：通过 |
| trend_strength, rsi_zone, macd_signal, volume_trend, oi_trend, funding_ok | 其余项 | 占位：通过 |

即：**仅 volume_ok、oi_ok 有真实判断；其余项多为「无数据则通过」或直接通过，与截图中的「16 项严格过滤」在数据与逻辑上尚未完全对齐。**

### 3.2 第二层

- **可靠度、入场信心**：当前为固定值（如 0.7、50），非来自 AI 或规则化计算，因此「可靠度≥0.67、入场信心≥31%」在数据源上未与截图一致。
- **6 因子**：用可计算因子数量近似（价格趋势、量能、RSI、MACD、OI、涨跌等），逻辑已接上，但因子定义与截图是否一致待产品确认。

### 3.3 第三层

- **OI 对齐、入场时机强度、自定义因子、信号年龄 <5 分钟**：配置结构已有（`Layer3Config`），但**开单前校验**未在 `auto_trader` 中调用（无 `ValidateLayer3`），且无信号时间戳，**信号年龄 <5 分钟**未真正生效。

### 3.4 方向池

- **多/空池**：由当前行情（价格 vs EMA20）划分，**非 AI 输出**；截图为「AI 分析量化数据填入方向池」，即方向池应由 AI 驱动，当前为规则占位。
- **强度、评分、市况、可靠度、时机、量价**：部分为固定占位（如 100、1、trend、50、20m、10），与真实 AI/量化结果未对接。

### 3.5 实时价格（用户补充）

- **配置**：`RealtimePriceConfig`（enabled、fetch_before_sltp_check、source）已在 `RiskControlConfig` 中定义。
- **执行**：`checkDynamicStopLossTakeProfit` **未**在检查前根据该配置拉取最新 mark 价，即「SL/TP 检查前拉取实时价」**未实现**。

### 3.6 多空雷达配置持久化

- **雷达配置**（允许做多/做空、HeatScore、ATR% 等）：当前为**内存 map**（`radarConfigMap`），未写入数据库或策略 JSON，重启丢失。
- **「设置为默认值」**：仅前端按钮，未与后端策略或默认配置关联。

### 3.7 与执行联动

- **允许做多/做空、HeatScore、可靠度门 等**：仅用于前端展示与雷达 API 的默认配置，**未**在 `pipeline` 或 `engine` 中参与过滤与开单逻辑（即不参与实际是否开多/开空、是否过滤候选）。

## 五、总结表：是否都已加入

| 大类 | 截图上的功能 | 是否都已加入 | 说明 |
|------|--------------|--------------|------|
| 多空雷达页面与导航 | 独立页、交易员选择、无候选提示 | ✅ 是 | 已实现 |
| 主控与方向 | 预设/手动/平仓、允许多空、AI 自动分析 | ✅ 是 | 已实现（默认值按钮仅 UI） |
| 技策略参数 | HeatScore、ATR%、资金临界%、可靠度门、方向分位/问 | ✅ 是 | 已实现（未参与 pipeline 过滤） |
| 挂单候选区 | 排除已持仓、挂单上限% 等文案 | ✅ 是 | 文案与占位已实现，无真实候选接口 |
| 方向池表格 | 多/空表、标的/强度/评分/市况/可靠度/时机/量价、自动下发撤单 | ✅ 是 | 已实现，数据来自 pipeline 占位规则 |
| 挂单流程信息 | 管线描述、数量、第一层不达标、按币种不达标、流程阶段、放宽第一层 | ✅ 是 | 已实现，数据来自 pipeline 实时状态 |
| 第一层 16 项 | 16 项条件名与统计 | ⚠️ 部分 | 配置与统计有，仅量能/OI 有真实逻辑，其余占位 |
| 第二层 | 6 因子 + 可靠度 + 入场信心 | ⚠️ 部分 | 逻辑有，可靠度/信心为固定值 |
| 第三层 | OI 对齐 + 信号年龄 <5 分钟 | ❌ 否 | 配置有，执行层未调用，信号年龄未实现 |
| 方向池由 AI 驱动 | AI 分析填入多/空池 | ❌ 否 | 当前为规则（价格 vs EMA20）占位 |
| 实时价格 | SL/TP 前拉最新价 | ❌ 否 | 仅配置存在，未在 checkDynamicStopLossTakeProfit 中使用 |
| 雷达配置持久化 | 保存到 DB/策略 | ❌ 否 | 仅内存，重启丢失 |
| 止盈/止损单独策略 | 系统执行、非 AI | ✅ 是 | 沿用原有动态止盈止损 + ai_only_entry |

**结论**：  
- **界面与流程**：截图中的多空雷达板块、挂单流程信息、方向池表格、技策略参数、主控与方向开关等，**都已经加入**，并能展示 pipeline 的实时状态。  
- **数据与逻辑**：第一层多数项为占位、第二层可靠度/信心非真实数据、第三层未接入执行、方向池非 AI 驱动、实时价格未接入 SL/TP、雷达配置未持久化。  
因此可以概括为：**截图上的「界面与流程」已基本加入；「严格 16 项 + 第二/三层 + AI 方向池 + 实时价格 + 雷达配置持久化」尚未完全实现或仅配置/占位。**
