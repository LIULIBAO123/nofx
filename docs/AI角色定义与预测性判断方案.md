# AI 角色定义与预测性判断方案

本文档分析当前 AI 的定位局限，说明「实时判断 + 预测性分析」的必要性，并给出让 AI 在开仓、持仓、止盈、止损、平仓场景下做出更正确判断的可行方案。

---

## 一、当前 AI 的定位与局限

### 1.1 当前行为

- **输入**：当周期快照——K 线、指标、OI、资金流/涨跌榜、多空比、资金费率、强平等，均为**当前或已发生**的数据。
- **输出**：基于上述快照的**即时判断**——如 trend_view（趋势仍在/震荡/反转）、开仓建议、market_summary、market_regime、risk_alert。
- **本质**：AI 在做**「当前状态识别」**：根据此刻数据给结论，**没有显式要求对「接下来会怎样」做推断**。

### 1.2 局限

| 场景 | 仅靠「实时状况」的不足 | 若有「预测/前瞻」可改进之处 |
|------|------------------------|-----------------------------|
| **开仓** | 只知道当前多空共振，不知道趋势能否延续、是否接近关键阻力/支撑 | 结合「未来 1～2 根 K 或本 session 预期」决定是否开、仓位大小、止损距离 |
| **持仓** | trend_view 只描述「当下」趋势/震荡/反转，不包含「接下来更可能延续还是反转」 | 预期延续→可放宽追踪止损或加长持有；预期反转→提前收紧或建议减仓 |
| **止盈** | 仅看当前浮盈与阻力，容易过早止盈或过晚 | 若有「上方空间有限 / 即将回调」的预期，可更合理选择部分止盈或移动止盈 |
| **止损** | 仅根据当前跌破/波动做 reversing，易在震荡中误判 | 区分「假跌破后回升」与「真反转」，可减少无谓止损 |
| **平仓** | 平仓时机多依赖规则（SL/TP），缺乏「何时主动了结更优」的前瞻 | 预期 session 结束或波动放大前主动平仓，可改善盈亏结构 |

结论：**仅「实时状况」不足以在开、持、止盈、止损、平仓上一致地做对决策；需要增加「基于数据的预测性判断」**，并与现有规则结合使用。

---

## 二、目标：双维判断（实时 + 预测）

让 AI 同时输出两类信息：

1. **实时判断**（保留）：当前趋势/震荡/反转、多空共振、风险状态等。
2. **预测性判断**（新增）：对未来一段时间（如 1～2 根 K、本 session、或到下一关键时间点）的**预期**——方向、幅度、关键价位、概率或情景（bull/base/bear），以及**依据**（哪些数据支持该预期）。

这样系统与人工可以：
- 用「实时」做即时风控与状态分类；
- 用「预测」调节开仓意愿、持仓周期、止盈/止损的紧松、以及是否主动平仓。

---

## 三、实现预测性判断的可行办法

### 3.1 从「数据输入」上支持预测

预测需要**领先/可推断未来的信息**，而不仅是当前价格。可用的数据与用法：

| 数据类别 | 当前是否已有 | 如何支撑「预测」 |
|----------|--------------|------------------|
| 多周期 K 线 + 指标 | 有 | 4h/1h 趋势 + 15m 结构可推断「短期延续或回调」；RSI/MACD 背离、量价背离可提示反转概率 |
| OI 变化 + 价格 | 有 | OI 增+价涨/跌 可推断多空力量是否持续；OI 减+价涨 常预示空头平仓、反弹可能减弱 |
| 资金流 / 涨跌榜 | 有 | 机构流向、板块强弱可推断资金是否继续流入/流出，从而推断短期方向与持续性 |
| 资金费率 + 多空比 | 有 | 极端费率/多空比常预示短期反向波动（逼空/逼多），可作为「未来 1～2 周期」的修正项 |
| 强平聚合 | 有 | 近期强平多/空可推断后续波动与情绪释放方向 |
| 历史相似形态（可选） | 部分可做 | 若后续有「相似 K 线/形态」检索，可给出「历史上类似形态后 N 根 K 的统计」作为参考 |
| 波动率/regime（可选） | 可算 | ATR、波动分位数、regime（趋势/震荡/高波）可约束「预期幅度与置信度」 |

**建议**：在现有 Context 中**显式整理并写入 prompt** 的「预测相关摘要」——例如：「当前 4h/1h 同向、OI 增+价涨、资金费率中性、强平偏空」→ 便于 AI 写出「短期延续偏多，但需关注上方阻力」类句子。不一定要新接口，先把已有数据按「对未来的含义」做简短归纳即可。

### 3.2 从「提示词与输出结构」上要求预测

- **在系统/用户提示中明确要求**：  
  - 在给出 action/trend_view 之前或同时，必须有一句「**近 1～2 根 K（或本 session）的预期**」：方向、关键位、以及主要依据（如：4h 未破前高、量能萎缩、OI 仍在增等）。  
  - 可选：要求对持仓标的给出「**延续 / 反转 / 震荡**」的**概率或情景**（如：延续 60%、反转 25%、震荡 15%），便于下游做参数调节。

- **结构化输出中增加「预测」字段**（便于解析与后续逻辑）：  
  - 在 `<analysis>` 或新块 `<outlook>` 中增加，例如：  
    - **near_term_outlook**：一段话描述未来 1～2 根 K 或本 session 的预期。  
    - **key_levels**（可选）：预期关键支撑/阻力或目标区间。  
    - **scenario**（可选）：如 `bull` / `base` / `bear` 或 `continuation` / `reversal` / `range`，用于与 trend_view 区分（一个偏当前，一个偏预期）。  

这样 AI 的「预测」被固定成可解析、可落库、可参与规则或展示的格式，而不是只藏在长文本里。

### 3.3 从「执行与风控」上使用预测

- **开仓**：若 AI 给出「短期延续」且置信度高，可保持或略放宽开仓条件；若给出「即将回调/反转」，可提高开仓门槛或缩小仓位。  
- **持仓**：现有 trend_view 已用于调节 SL 确认周期；若再解析出 **scenario/near_term_outlook**，可增加一层：例如 `reversal` + 高置信 → 进一步缩短确认周期或建议减仓。  
- **止盈/止损**：若 AI 预期「上方空间有限」或「即将反转」，可优先部分止盈或收紧追踪；若预期「假跌破后回升」，可对 SL 增加一次确认或放宽容忍。  
- **平仓**：若 AI 预期「本 session 难有趋势」或「波动将放大」，可输出建议「主动减仓/平仓」，由系统或人工决定是否执行。

实现上可**分阶段**：先只解析并展示/落库；再对部分字段（如 scenario、risk_alert）做简单规则（如 reversal + risk_alert → 本周期不新开、或缩短 SL 确认）。

### 3.4 从「思维链」上引导预测

- 在 prompt 的「决策流程」中增加一步：  
  - **「在给出 action 前，先基于多周期、OI、资金流、费率等，写出未来 1～2 根 K（或本 session）的预期（方向、关键位、主要依据），再据此决定开/平/持与 trend_view。」**  
- 这样模型会被强制先「预测」再「决策」，减少仅凭当前快照就下结论的情况。

## 四、推荐落地方案（分步）

### 第一步：提示词与输出结构（不改执行逻辑）

- 在 **BuildSystemPrompt / BuildUserPrompt** 中：  
  - 增加「预测性判断」说明：要求 AI 在给出 action/trend_view 时，**必须**写出「近 1～2 根 K 或本 session 的预期」及依据。  
  - 在 **Output Format** 中增加可选块 **`<outlook>`**（或扩展现有 `<analysis>`），要求输出：  
    - **near_term_outlook**：一句话预期。  
    - **scenario**（可选）：continuation / reversal / range。  
    - **key_levels**（可选）：1～2 个关键位。  
- 在 **parseFullDecisionResponse**（或单独解析函数）中解析上述字段，写入 **FullDecision** 或新结构体，并落库/展示。

效果：AI 开始稳定输出「预测」，且可被系统与人工使用，无需立刻改执行逻辑。

### 第二步：Context 中增加「预测相关摘要」（可选）

- 在 **buildTradingContext** 或组装 user prompt 时，根据 **MarketDataMap、OI、资金流、费率、强平** 等，生成一两句**系统侧摘要**（如：「4h/1h 同向多；OI 增+价涨；费率中性；近 1h 强平偏空」），写入 prompt。  
- 不改变现有数据结构，只增加一段固定格式的文本，帮助 AI 快速抓住「对未来的含义」。

### 第三步：执行与风控使用预测（可选）

- 读取 **FullDecision** 中的 **scenario / near_term_outlook / risk_alert**：  
  - 若 **scenario=reversal** 且 **risk_alert=true**：本周期不新开仓（已有逻辑可复用 risk_alert）。  
  - 若 **trend_view=reversing** 且 **scenario=reversal**：可将 SL 确认周期再减 1（需在 stop_loss 逻辑中增加可选分支）。  
- 不在第一步就做，避免行为突变；等预测输出稳定后再接规则。

### 第四步：历史形态/统计（中长期）

- 若有 K 线历史与形态匹配能力，可增加「相似形态后 N 根 K 的统计」作为 prompt 或内部参考，进一步强化「数据驱动的预测」而非纯语言模型推断。

## 五、小结

| 维度 | 做法 |
|------|------|
| **定义** | AI 同时做「实时状况判断」+「基于数据的预测性判断」，并在开/持/止盈/止损/平仓中结合使用。 |
| **数据** | 沿用现有多周期、OI、资金流、费率、强平等，在 prompt 中显式整理「对未来的含义」；可选增加波动率/regime、历史形态。 |
| **提示词** | 强制要求「先写近 1～2 根 K 或本 session 的预期与依据，再给 action/trend_view」；输出中增加 near_term_outlook、scenario、key_levels。 |
| **执行** | 先解析并展示/落库；再视需要让 scenario、outlook、risk_alert 参与开仓门槛、SL 确认周期、止盈策略等。 |

按上述步骤，可以在不大改架构的前提下，把 AI 从「只分析当前实时状况」升级为「实时 + 预测」双维判断，从而在开仓、持仓、止盈、止损、平仓场景下支持更合理的决策。
