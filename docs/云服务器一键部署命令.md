# 云服务器一键部署命令

本文档给出**首次部署**与**后续更新**的一键命令。脚本**只拉取预构建镜像**（GitHub Container Registry），**不在服务器上构建**，部署通常 1–3 分钟完成。

---

## 镜像来源说明

- 后端/前端镜像由 GitHub Actions 在每次推送到 `dev` 时构建并推送到 **ghcr.io**。
- 安装脚本会克隆仓库（获取 `docker-compose.prod.yml` 与配置）、拉取上述镜像并启动，**不在服务器上下载 Go/Node 或执行构建**。
- 若拉取镜像报 404/403，请确认 CI 已成功跑完「Build and Push Docker Images」且仓库为 public；若镜像为 private，需先执行：`docker login ghcr.io -u 用户名 -p PAT`。

---

## 环境要求

- 已安装 **Docker** 与 **Docker Compose**
- 已安装 **git**（脚本会克隆 dev 分支并构建）
- 若未安装 Docker：`curl -fsSL https://get.docker.com | sh`（按系统选择官方安装方式）

---

## 一、首次部署

在**空目录**下执行（默认安装到 `$HOME/nofx`）：

```bash
curl -fsSL https://raw.githubusercontent.com/LIULIBAO123/nofx/dev/install.sh | bash
```

或指定安装目录（目录需为空）：

```bash
# 示例：安装到 /opt/nofx
sudo mkdir -p /opt/nofx
sudo chown $(whoami):$(whoami) /opt/nofx
curl -fsSL https://raw.githubusercontent.com/LIULIBAO123/nofx/dev/install.sh | bash -s -- /opt/nofx
```

执行后会：克隆 dev 分支 → 生成 .env 与 RSA 密钥 → **拉取预构建镜像** → 启动服务。完成后访问 **http://服务器IP:3000**，API 为 **http://服务器IP:8080**。

---

## 二、后续更新

在**已安装过的目录**下执行，会拉取最新代码与最新镜像并重启服务。

### 方式 A：上次安装时目录内已有 .git（推荐）

直接在该目录下再次执行安装脚本，并传入当前路径：

```bash
cd $HOME/nofx
curl -fsSL https://raw.githubusercontent.com/LIULIBAO123/nofx/dev/install.sh | bash -s -- $HOME/nofx
```

若安装在其他路径，替换为实际路径即可，例如：

```bash
cd /opt/nofx
curl -fsSL https://raw.githubusercontent.com/LIULIBAO123/nofx/dev/install.sh | bash -s -- /opt/nofx
```

### 方式 B：上次安装为“旧版无 .git”，脚本已自动克隆到 nofx-src

则应用目录在 **nofx-src** 下，更新时应对该子目录执行：

```bash
cd $HOME/nofx/nofx-src
curl -fsSL https://raw.githubusercontent.com/LIULIBAO123/nofx/dev/install.sh | bash -s -- $HOME/nofx/nofx-src
```

（若当时安装在 `/opt/nofx`，则把 `$HOME/nofx` 换成 `/opt/nofx`。）

## 常用运维命令

在应用目录（即 `$HOME/nofx`、`/opt/nofx` 或 `.../nofx-src`）下执行：

```bash
cd <安装目录>

# 查看日志
docker compose logs -f

# 重启服务
docker compose restart

# 停止服务
docker compose down

# 再次执行“后续更新”命令即可更新到最新并重启
```

---

## 验证后端版本

确认是否为预设 v3.0：

```bash
curl -s http://127.0.0.1:8080/api/health
```

若返回中包含 `"preset_version":"3.0"`，说明当前后端已是预设 v3.0；在策略页使用紫色星星「一键生成」即可得到预设策略 v3.0。

## 常见问题

### 注册时出现「Server error」或「REGISTRATION_ERROR」

1. **看后端日志**（在安装目录下执行）  
   `docker compose logs nofx --tail 100`  
   若有 `Failed to create user`、`database is read-only`、权限错误等，多半是 **data 目录不可写** 或 SQLite 文件权限问题。  
   处理：保证挂载的 `./data` 目录可写（如 `chmod 755 data`），且后端容器用户有写权限。

2. **看浏览器请求**  
   打开开发者工具 → Network，再点一次「CREATE_ACCOUNT」。  
   - 若 **/api/register 请求未发出或跨域失败**：确认访问的是 **http://服务器IP:3000**（经 nginx 转发到后端），不要直接访问 8080 再在页面里用相对路径调接口。  
   - 若 **状态码 500**：看 Response 里是否有 `{"error":"..."}`，该内容会显示在页面上；若没有 JSON，说明后端可能 panic，以第 1 步日志为准。

3. **确认服务在跑**  
   `docker compose ps` 中 `nofx`、`nofx-frontend` 均为 Up；`curl -s http://127.0.0.1:8080/api/health` 返回 `{"status":"ok",...}`。
