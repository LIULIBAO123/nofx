# 是否需要加入其他交易数据来增强对市场的判断

本文档基于当前 nofx 已接入的数据，列出**现有数据清单**，并给出**可补充数据建议**、**用途**与**落地优先级**，便于在「过滤机制 + 方向判断 + AI 辅助分析」中增强对市场的判断。

---

## 一、当前系统已使用的交易数据

### 1.1 行情与技术指标（交易所 / market 层）

| 数据类型 | 说明 | 策略开关 / 落点 |
|----------|------|------------------|
| K 线 | 多周期（如 15m/1h/4h）、OHLCV | `Klines.PrimaryTimeframe`、`SelectedTimeframes`、`PrimaryCount` |
| EMA | 周期可配（如 20、50） | `EnableEMA`、`EMAPeriods` |
| MACD | 动能 | `EnableMACD` |
| RSI | 超买超卖 | `EnableRSI`、`RSIPeriods` |
| ATR | 波动率，用于动态止损/止盈倍数 | `EnableATR`、`ATRPeriods` |
| 布林带 | 可选 | `EnableBOLL` |
| 成交量 | 量能 | `EnableVolume` |
| 持仓量 OI（单标的） | 交易所合约 OI | `EnableOI` |
| 资金费率（单标的） | 永续合约资金费率 | `EnableFundingRate` |

### 1.2 量化与排行（NofxOS）

| 数据类型 | 说明 | 策略开关 / 落点 |
|----------|------|------------------|
| AI500 币池 | 评分选币 | 币种来源 `UseAI500`、`ai500_limit` |
| OI 排行 | 全市场 OI 增加/减少排行（1h/4h/24h） | `EnableOIRanking`、`OIRankingDuration`、`OIRankingLimit` |
| 资金流排行 NetFlow | 机构/个人、期货流入流出 Top/Low | `EnableNetFlowRanking`、`NetFlowRankingDuration`、`NetFlowRankingLimit` |
| 涨跌榜 Price Ranking | 全市场涨幅/跌幅排行（多周期） | `EnablePriceRanking`、`PriceRankingDuration`、`PriceRankingLimit` |
| 单币量化数据 | 单标的 OI、资金流、多周期涨跌幅等 | `EnableQuantData`、`EnableQuantOI`、`EnableQuantNetflow`；Layer1 中 flow_aligned、price_ranking_aligned 等 |

### 1.3 币安衍生数据（以币安为主，公开接口无需 Key）

| 数据类型 | 说明 | 策略开关 |
|----------|------|----------|
| 多空比（全账户+大户） | 币安 U 本位全账户/大户多空比，period 可配（5m/15m/1h/4h） | `EnableBinanceLongShortRatio`、`BinanceLongShortPeriod` |
| 资金费率（当前/下一档） | 币安永续资金费率与标记价 | `EnableBinanceFundingHistory` |
| Taker 买卖比 | 币安 Taker 多空比，period 可配 | `EnableBinanceTakerVolume`、`BinanceTakerPeriod` |

拉取与落点：`trader/auto_trader.go` buildTradingContext 中按策略开关拉取；写入 `Context.BinanceLongShortMap`、`BinanceFundingMap`、`BinanceTakerMap`；`kernel/engine.go` 的 `formatBinanceDerivativesForAI` 写入 User Prompt 供 AI 分析。

### 1.4 其他

| 数据类型 | 说明 |
|----------|------|
| 账户与持仓 | 余额、持仓、标记价、未实现盈亏等（buildTradingContext） |
| 外部数据源 | 策略中 `ExternalDataSources`：通用 API/Webhook，可按 JSON 路径解析 |

## 二、建议补充的数据类型（增强市场判断）

在**不改变「系统执行开仓、AI 仅辅助」**的前提下，以下数据可用于：  
- 过滤层（Layer1/Layer2）或方向池的**额外条件**；  
- **AI 辅助分析**的输入（市场摘要、regime、risk_alert）；  
- **风控/熔断**（如异常波动、流动性骤降时收紧或暂停开仓）。

| 建议数据 | 用途简述 | 优先级 | 落地方式简述 |
|----------|----------|--------|----------------------|
| **多空比 / 大户多空比** | 市场情绪、与 OI/资金流交叉验证；过滤或方向池可增加「多空比与方向一致」类条件。 | 高 | NofxOS 若提供则直接接；否则由交易所 API（如 Bybit 多空比）拉取，写入 Context，供 pipeline/提示词使用。 |
| **爆仓/强平数据（清算量）** | 识别挤空/挤多、波动加剧；可作为 regime 或 risk_alert 输入，必要时收紧过滤或暂停开仓。 | 高 | 部分交易所或第三方提供；可先接「全市场/分多空」汇总，再考虑 per-symbol。 |
| **主动买卖/吃单方向（Taker Buy Sell）** | 订单流方向，短周期方向确认；可作 Layer1 或方向池的辅助条件。 | 中高 | 交易所 K 线或深度/成交接口；需聚合为周期级指标（如 15m 内 taker buy%），写入 market.Data 或 Context。 |
| **资金费率历史/预测下一档** | 极端费率往往预示反转或趋势延续；可用于过滤（如 funding_ok 增强）或 AI 摘要。 | 中 | 当前已有当前费率；可增加「近 8h 均值」「下一档预测」等字段或单独接口。 |
| **BTC/ETH 占比、山寨季节指数** | 宏观环境：BTC 主导 vs 山寨轮动；可调节候选池或过滤松紧（如山寨季节时放宽山寨过滤）。 | 中 | 可从 NofxOS 或公开 API 获取；写入 Context 单一字段，供策略或 AI 使用。 |
| **永续-现货价差（Basis）** | 期货溢价/贴水，与资金费率互补；可用于趋势/情绪判断。 | 中 | 交易所现货与永续价格计算；可仅对 BTC/ETH 或主要标的。 |
| **交易所稳定币流入流出** | 资金进出意图；偏宏观，可作为 regime 或 AI 摘要的输入。 | 低 | 需链上或第三方数据；若 NofxOS 有则可接。 |
| **波动率曲面/期权 Put-Call（若有）** | 若未来涉及期权或需情绪/恐慌指标，可作补充。 | 低 | 依赖期权数据源；可后续扩展。 |

## 三、优先级与实施建议

1. **高优先级（建议优先考虑）**  
   - **多空比 / 大户多空比**：与现有 OI、资金流、涨跌榜形成「情绪+结构」三角，对方向判断与过滤都有帮助。  
   - **爆仓/清算量**：对识别极端行情、调节 regime 或 risk_alert 很有用，有利于风控与过滤松紧。

2. **中优先级（在数据源就绪时接入）**  
   - **Taker 买卖比例**：订单流维度，与 K 线/量能互补。  
   - **资金费率历史/预测**：在现有 `funding_ok` 基础上增强。  
   - **BTC 占比 / 山寨季节**：用于宏观过滤或 AI 摘要，实现成本低时可先上。

3. **落地方式统一建议**  
   - 新增数据尽量**先写入 `kernel.Context`**，再在 **pipeline（Layer1/Layer2/方向池）** 或 **BuildUserPrompt** 中按需使用。  
   - 若数据来自 NofxOS：在 `provider/nofxos` 增加接口与格式化，与现有 OI/NetFlow/Price 排行一致。  
   - 若来自交易所：在 `market` 或单独 provider 拉取，避免阻塞主循环；可短缓存（如 1 分钟）减少请求。

4. **与「AI 仅辅助」的配合**  
   - 新数据可同时用于：  
     - **规则层**：过滤条件、方向池打分；  
     - **AI 层**：提示词中增加一段「多空比/清算/资金费率摘要」等，供 AI 输出市场摘要、regime、risk_alert，**不参与开平仓决策**，只增强解释与预警。

---

## 四、小结

- **是否需要加入其他交易数据？**  
  **建议：是。** 在现有 K 线、技术指标、OI/资金流/涨跌榜的基础上，优先考虑**多空比**与**爆仓/清算量**，再视数据源情况补充 **Taker 买卖、资金费率历史/预测、BTC 占比/山寨季节** 等，能明显增强对市场状态与异常行情的判断，并更好支撑过滤、方向判断与 AI 辅助分析。  
- 新增数据应**统一进入 Context → 规则 + 提示词**，并保持「开平仓由系统执行、AI 仅辅助」的边界不变。
