# 策略止盈止损分析与「趋势相反时亏损偏大」的解决办法

本文档梳理当前止盈/止损的代码结构、提示词，分析「币种趋势与 AI 开仓方向相反时亏损金额偏大」的原因，并给出**不收紧止损**（保持震荡市设计理念）下的改进思路与可选实现。

---

## 一、当前止盈/止损代码结构

### 1.1 执行顺序与数据流

- **入口**：每周期 `runCycle` 内**先**执行 `checkDynamicStopLossTakeProfit()`，再拉行情、调 AI、执行 AI 决策。
- **数据**：仓位来自 `at.trader.GetPositions()`（实盘/模拟一致）；ATR、K 线来自 `marketClient.GetKlines(symbol, "15m", 50)`；最高价/最低价自入场后 K 线计算，用于追踪止损。
- **最小持仓**：`MinHoldMinutes` 内不触发动态止损/止盈，避免「开仓即平仓」。
- **确认周期**：止损可配置 `ConfirmCycles`（连续 N 周期满足才执行），高波动时自动多要求 1 周期，减少单根 K 线假跌破。

### 1.2 止损（kernel/stop_loss.go + store 配置）

| 类型 | 说明 | 何时触发 |
|------|------|----------|
| **InitialStopPercent** | 固定百分比止损 | 可选；>0 时启用，价格触及即触发 |
| **TrailingStop** | 分层追踪止损 | 仅当**曾有过浮盈**后，从峰值回撤超过档位% 才触发；从未盈利则不会触发 |
| **ATR 止损** | 入场价 ± 倍数×ATR | 价格触及即触发；高波动时可配置为用更大倍数、多 1 确认周期 |
| **SupportResistance** | 支撑/阻力止损 | 价格跌破支撑（多）或升破阻力（空）时触发 |

### 1.3 止盈（kernel/take_profit.go）

| 类型 | 说明 |
|------|------|
| **ScaledTakeProfit** | 分层止盈：达档位% 按比例部分平仓，先于固定止盈检查 |
| **FixedPercent** | 固定百分比止盈，达则全平 |
| **ATR 止盈** | 入场价 ± 倍数×ATR 达则止盈 |
| **Resistance** | 阻力位止盈（空头为支撑） |

### 1.4 提示词中的止盈/止损（kernel/prompt_builder.go、engine.go、schema）

- 明确写「止盈止损由策略自动执行」；AI 仅开仓时对已有持仓一律 `hold`。
- 策略动态 SL/TP 配置通过 `formatStrategyDynamicSLTP` 注入（最小持仓、追踪止损档位、ATR 倍数范围、分层止盈档位等）。
- 震荡市指引：止损 2.0–2.5× ATR 拿住持仓，止盈 2.5–3× ATR 盈利即出；结构破坏（如 1h 收盘跌破/升破 EMA20）时可建议平仓；明确反转可先平再反手。

## 二、为什么「趋势与开仓相反」时亏损会偏大？

1. **止损设计是「宽」的**  
   为满足震荡市波动，策略与提示词都建议用较宽 ATR（如 1.5–2.5×），以便在区间内不被洗出。这是有意为之。

2. **追踪止损只在「有过浮盈」后生效**  
   追踪止损逻辑是：先达到某档盈利阈值，再从**峰值**回撤一定% 才触发。若开仓后价格**一路反向、从未浮盈**，则追踪止损**永远不会被激活**，只有 ATR 止损或固定初始止损会触发。

3. **结果**  
   当方向判断错误（趋势与开仓相反）时，没有「提前止错」的机制，价格会一直走到 ATR 止损（或初始止损）才平仓，单笔亏损 = 整个止损距离 × 仓位，因此**亏损金额会偏大**。  
   若再收紧 ATR 止损，又会在震荡市被频繁洗出，违背「满足震荡市波动从而盈利」的设计。

## 三、不收紧止损下的解决办法（设计思路）

以下方案均**不通过缩小现有 ATR/固定止损**来减亏，而是从「少开错仓」和「错仓早退」两方面入手。

### 3.1 开仓过滤：减少逆势开仓（推荐，提示词 + 执行约束）

- **思路**：在开仓前提高「趋势与方向一致」的门槛，减少「趋势与开仓相反」的笔数，从而在**不改变单笔止损宽度**的前提下降低总亏损。
- **做法**：
  - **多周期一致才开仓**：提示词中明确要求至少 2 个时间周期同向（如 15m 与 1h 同向）再开仓；单周期信号或趋势不明时不开仓或仅小仓位试探。
  - **结构/趋势确认**：仅在「回调到结构位（如 EMA、前高/前低）且趋势未破坏」时开仓，避免逆势追单。
- **实现**：以**提示词与 schema 约束**为主（见下节），无需改止损代码；若后续需要，可在执行层对「单周期/低置信度」开仓做仓位上限（如最大 50% 名义仓位）。

### 3.2 结构破坏提前退场（可选，策略层逻辑）

- **思路**：提示词已写「结构破坏（如 1h 收盘跌破/升破 EMA20）时可建议平仓」。在 **AI 仅开仓** 模式下，AI 的平仓建议被忽略，因此可增加**策略级**的「结构破坏退出」：不收紧 ATR 止损，但当更高周期结构破坏时提前平仓，减小逆势单的亏损。
- **做法**：在 `checkDynamicStopLossTakeProfit` 中，若策略开启「结构破坏退出」，则拉取 1h（或配置周期）K 线，计算 EMA20；若当前收盘价已跌破（多）或升破（空）EMA20，则触发平仓。与现有 ATR/追踪止损并列，作为**额外**退出条件。
- **实现**：需在策略配置中增加开关与周期（如 `structure_break_exit_enabled`、`structure_break_timeframe`），并在 kernel 或 auto_trader 中增加一次 EMA 计算与比较。不改变现有止损宽度。

### 3.3 「从未浮盈 + 反向幅度过大」提前退场（已实现）

- **思路**：在**从未出现过浮盈**的前提下，若价格已反向移动超过一定幅度（如 1.0–1.2× ATR），可视为「方向错误」而非「震荡回调」，允许提前止损，从而在不影响「曾有过浮盈」的持仓的前提下，限制纯逆势单的亏损。
- **特点**：不改变「有过浮盈」后的追踪止损与宽 ATR 逻辑；只对「从未绿过 + 反向达到 X×ATR」的仓位多一条退出路径，减小逆势单的亏损金额。
- **实现（已落地）**：策略配置 `dynamic_stop_loss.adverse_exit_when_never_profit_atr`（0 或未设=关闭；如 1.0、1.2 表示反向≥该倍数×ATR 时触发）。在 `StopLossChecker.checkAdverseExitWhenNeverProfit` 中判断：多单用入场后最高价≤入场价判定从未浮盈，空单用入场后最低价≥入场价判定；反向距离多单为入场价−当前价、空单为当前价−入场价；满足「从未浮盈且反向距离 ≥ 配置×ATR」时触发，类型为 `adverse_never_profit`，平仓原因写入 `system:sl:adverse_never_profit`。提示词中展示「从未浮盈+反向≥X×ATR早退: 开」；前端历史持仓平仓类型显示「从未浮盈+反向过大早退」。

### 3.4 按置信度/多周期对齐度缩小仓位（推荐，提示词 + 可选执行）

- **思路**：当趋势不够清晰或仅单周期支持时，**不禁止开仓**，但用较小仓位；这样单笔最大亏损 = 止损% × 较小仓位，总亏损可控。
- **做法**：提示词中要求 AI 在「多周期一致、结构清晰」时用正常仓位，在「单周期或趋势不明」时减小 `position_size_usd` 或降低杠杆；可选在执行层对低 confidence 或单周期开仓做名义仓位上限。
- **实现**：先通过提示词约束；若需硬性约束，再在解析 AI 输出或下单前按 confidence/理由做仓位上限。

## 四、已做的提示词增强（开仓过滤与逆势亏损控制）

在**不收紧止损**的前提下，在系统提示/策略说明中增加以下内容（具体见 kernel 内修改）：

- **开仓条件**：明确「多周期趋势一致再开仓；单周期或趋势不明时不开仓或仅小仓位」。
- **逆势亏损控制**：明确「避免逆势开仓导致亏损扩大；震荡市用宽止损拿住仓，但开仓前务必确认方向与多周期/结构一致」。
- **仓位与置信度**：明确「高置信度+多周期共振时用正常仓位；反之减小仓位或观望」。

上述修改仅影响 AI 的决策约束，不改变任何止损/止盈的数值或触发条件。

---

## 五、小结

| 问题 | 原因 | 不改止损的解决办法 |
|------|------|----------------------|
| 趋势与开仓相反时亏损偏大 | 宽 ATR 为震荡设计；追踪止损仅在有浮盈后生效；逆势单一路走到 ATR 才平 | ① 开仓过滤：多周期一致、结构确认再开；② 结构破坏退出（策略层）；③ 从未浮盈+反向超 X×ATR 可选的早退；④ 按置信度/多周期缩小仓位 |

当前优先通过**提示词**落实「开仓过滤」和「仓位与置信度」，在不改动止损逻辑的前提下降低逆势开仓频率与单笔风险；若仍需进一步压降逆势单亏损，再考虑实现「结构破坏退出」或「从未浮盈 + 反向 ATR 早退」的策略可选项。
