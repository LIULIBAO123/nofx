# 止盈止损参数合理性分析

本文档基于当前默认策略与代码逻辑，对动态止损/止盈参数做简要合理性分析，并给出可选的调优建议。

---

## 一、当前默认参数一览

### 1. 动态止损（DynamicStopLoss）

| 参数 | 默认值 | 说明 |
|------|--------|------|
| MinHoldMinutes | **10** | 开仓后 10 分钟内不触发（主周期 15m 下更稳） |
| InitialStopPercent | **8** | 8% 兜底硬止损，极端行情保护；日常仍以动态/ATR/追踪为主 |
| **追踪止损 L1** | 盈利 ≥2.5% 激活，回撤 1.5% 触发 | 早锁利润，止损线较紧 |
| **追踪止损 L2** | 盈利 ≥6% 激活，回撤 2.5% 触发 | 给趋势更多空间 |
| ATR 止损 | 倍数 1.5–2.5×，周期 BTC/ETH 20、山寨 14 | 随波动自适应 |
| 支撑/阻力止损 | 部分预设开启，缓冲 **0.8%** | 略放宽，减少假突破触发 |
| ConfirmCycles | 2 | 连续 2 周期满足才执行，减少假跌破 |
| ATR 高波动宽容 | 开启，阈值 1.2× 长期 ATR | 高波动时更宽容 |

### 2. 动态止盈（DynamicTakeProfit）

| 参数 | 默认值 | 说明 |
|------|--------|------|
| MinHoldMinutes | **10** | 与止损一致 |
| **分层止盈 1** | 盈利 4% 平 33%，并移动止损到盈亏平衡 | 早锁本、留仓位奔跑 |
| **分层止盈 2** | 盈利 7% 平 50% | 中段兑现 |
| **分层止盈 3** | 盈利 10% 平 100% | 全部兑现 |
| LockProfitPercent | **2.5%** | 盈利达 2.5% 后可将止损移到成本价，锁本更稳 |
| ATR 止盈 | 倍数 2.5–4.0× | 目标随波动放大 |
| 阻力位止盈 | 部分预设开启，缓冲 **0.5%** | 略放宽 |

---

## 二、合理性分析

### 1. 追踪止损层级

- **L1（2.5% 盈利，1.5% 回撤）**
  - 盈利 2.5% 后激活，允许从最高点回撤 1.5% 即触发。
  - 触发时止损价 ≈ 最高价 × (1 − 1.5%)，多数情况下仍在入场价之上，能锁住部分利润。
  - **结论**：合理，且回撤 1.5% < 盈利阈值 2.5%，不易出现“触发时已变亏损”。

- **L2（6% 盈利，2.5% 回撤）**
  - 盈利 6% 后激活，允许回撤 2.5%。
  - 触发时至少还有约 3.5% 利润空间，与“让利润奔跑”一致。
  - **结论**：合理。

- **风险点（用户自定义时需注意）**
  - 若某一层的 **TrailingPercent 大于或接近该层的 ProfitThreshold**，则从最高点回撤后，止损价可能落在**入场价下方**，触发时会出现**亏损出场**（如之前 PIPPIN 案例：回撤 5.25% 的一档，峰值约 3.74%，止损在入场下方）。
  - **建议**：自定义追踪档位时，尽量保证 **TrailingPercent < ProfitThreshold**，这样触发时止损线仍在成本之上，至少不亏。

### 2. 分层止盈（4% / 7% / 10%）

- 第一档 4% 即平 33% 并移止损到盈亏平衡，能较快锁定本金、降低“先盈后亏”。
- 7%、10% 两档逐步兑现，兼顾“拿住趋势”和“落袋为安”。
- **结论**：档位与比例合理，与 MinRiskRewardRatio（如 3:1）搭配使用问题不大。

### 3. LockProfitPercent = 2%

- 盈利达到 2% 即允许将止损移到成本价，与分层第一档（4%）配合，能较早避免由盈转亏。
- **结论**：合理，偏保守，适合震荡或波动较大的品种。

### 4. MinHoldMinutes = 5

- 5 分钟内不触发动态止损/止盈，避免因 1–2 根 K 线噪音刚开仓就被扫掉。
- 若主周期为 15m，5 分钟不足一根 K 线，可考虑 10–15 分钟以更稳；若为 5m/1m，当前值可接受。
- **结论**：基本合理，可根据主周期微调。

### 5. 连续确认与高波动宽容

- **ConfirmCycles = 2**：连续 2 个检查周期满足条件才执行止损，减少单根 K 线假跌破。
- **ATR 高波动宽容**：高波动时放宽 ATR 止损并多要求 1 个确认周期，减少噪音触发。
- **结论**：逻辑合理，有利于降低“过早止损”。

### 6. ATR 倍数区间

- 止损 1.5–2.5×、止盈 2.5–4.0×，止盈/止损倍数比 > 1，与“盈亏比 > 1”一致。
- 高波动时使用 2.5×（Max）放宽止损，已在代码中实现。
- **结论**：区间设置合理。

### 7. InitialStopPercent = 0

- 完全依赖 ATR/追踪/支撑阻力，无“最后一道”固定百分比止损。
- 优点：避免在剧烈波动时被固定止损反复扫掉。
- 缺点：若出现跳空或极端行情，没有硬性兜底。
- **建议**：若希望有兜底，可设一个较宽的 InitialStopPercent（如 8–10%）作为极端情况保护；若更信任动态逻辑，保持 0 亦可。

### 8. 支撑/阻力缓冲

- 止损侧缓冲 0.5%、止盈侧（阻力）0.3%，略紧，在噪音较大的标的上可能频繁触及。
- **建议**：若发现频繁被“假突破”扫掉，可适当调大到 0.5–1%。

## 三、总体结论与已采纳调优

| 项目 | 结论 | 已采纳默认 |
|------|------|------------|
| 追踪止损 L1/L2 默认档位 | 合理（回撤% < 盈利%） | 保持 2.5%/1.5%、6%/2.5%；自定义时勿设“回撤% ≥ 盈利%” |
| 分层止盈 4/7/10% | 合理 | 保持 |
| LockProfitPercent | 合理 | **2% → 2.5%**（已提高，锁本更稳） |
| MinHoldMinutes | 主周期 15m 下宜略长 | **5 → 10 分钟**（已改，减少开仓即触发） |
| ConfirmCycles + ATR 宽容 | 合理 | 保持 |
| ATR 倍数区间 | 合理 | 保持 |
| InitialStopPercent | 建议有兜底 | **0 → 8%**（已设，极端行情硬止损） |
| 支撑/阻力缓冲 | 略紧 | **支撑/阻力缓冲 0.5%→0.8%、阻力止盈 0.3%→0.5%**（已放宽） |

**整体**：上述调优已写入默认策略（`store/strategy.go` 两处预设）。新创建的策略将使用 10 分钟最小持仓、8% 初始兜底止损、2.5% 锁定利润、以及略放宽的支撑/阻力缓冲。自定义策略时仍须注意**追踪止损每档 TrailingPercent < ProfitThreshold**，避免“触发追踪却亏损出场”。后续若根据实盘/回测再调，可在此文档补充记录。
