# 各板块数据与数据源分析

本文梳理：**过滤机制**、**方向池**、**AI 实时**、**AI 预测**、**止盈止损调整**及**5 种场景**所用数据及其数据源。

---

## 一、过滤机制（多层过滤 Pipeline）

### 1.1 涉及数据

| 层级 | 数据项 | 用途 |
|------|--------|------|
| **第一层 Layer1（16 项）** | 入场时机、量能、OI、长/短周期对齐、流向、涨跌榜、可靠度、大户/全市场多空、趋势强度、RSI、MACD、量价/OI 趋势、资金费率 | 单项条件通过/不通过，未过则记入失败原因 |
| **第二层 Layer2** | 因子数、可靠度、入场信心% | 至少 N 因子通过 + 可靠度≥阈值 + 入场信心≥阈值 |
| **第三层** | 信号年龄、OI 多空对齐（可选） | 待提交列表、开多/开空时 OI 是否对齐 |

### 1.2 数据源（按条件/因子）

| 数据 | 数据源 | 代码位置 / 说明 |
|------|--------|------------------|
| **行情 / K 线**（价格、涨跌、量、EMA、RSI、MACD、OI 单标的） | **行情接口**（如 Binance）经 `market.GetWithTimeframes` | `kernel/engine.go` fetchMarketDataWithStrategy → `ctx.MarketDataMap`；`kernel/pipeline.go` checkLayer1Item 用 `ctx.MarketDataMap[symbol]` |
| **净流入排行**（机构合约流入/流出榜） | **nofxos**（GetNetFlowRanking） | `ctx.NetFlowRankingData`；flow_aligned、evaluateLayer2、applyDirectionBonus |
| **涨跌榜**（多周期涨幅/跌幅榜） | **nofxos**（GetPriceRanking） | `ctx.PriceRankingData`；price_ranking_aligned、market_direction_aligned、evaluateLayer2、applyDirectionBonus |
| **OI 排行**（增/减榜） | **nofxos**（GetOIRanking） | `ctx.OIRankingData`；whale_direction_aligned、evaluateLayer2、applyDirectionBonus、computeOIAligned |
| **资金费率**（单标的、用于 funding_ok） | **行情/交易所**（在 market.Data 内）或 **Binance**（GetPremiumIndex） | Layer1 funding_ok 用 `md.FundingRate`；Layer2 用 `ctx.BinanceFundingRateAvg8h` |

**小结**：过滤机制依赖 **行情（market）**、**nofxos（OI/净流入/涨跌榜）**、以及可选 **Binance 资金费率 8h 均值**；候选列表来自 `ctx.CandidateCoins`（由策略币池 + OI/净流入等配置生成）。

## 二、方向池（Direction Pool）

### 2.1 涉及数据

- **多/空归属**：每个标的进「多池」或「空池」，以及强度（StrengthPct）、可靠度（ReliabilityPct）、市场状态（strong_trend / trend / weak_trend）、时机（now/soon）、量价比（VolumePricePct）等。
- **加成**：用多空比、OI 排行、净流入、涨跌榜、强平、资金费率 8h、Basis 对强度/可靠度做加分（有上限）。

### 2.2 数据源

| 数据 | 数据源 | 说明 |
|------|--------|------|
| **4h/1h 涨跌、价格、EMA20、MACD、RSI、量能、OI（单标的）** | **行情**（market）→ `ctx.MarketDataMap` | `buildOneDirectionItem`：多周期同向、短周期趋势、动能 |
| **全账户/大户多空比** | **Binance**（GetGlobalLongShortAccountRatio、GetTopLongShortAccountRatio）或 **Coinglass**（启用时覆盖 BTC/ETH） | `ctx.BinanceLongShortMap` → `applyDirectionBonus` |
| **OI 排行**（增/减榜） | nofxos | `ctx.OIRankingData` → applyDirectionBonus |
| **净流入排行** | nofxos | `ctx.NetFlowRankingData` → applyDirectionBonus |
| **涨跌榜** | nofxos | `ctx.PriceRankingData` → applyDirectionBonus |
| **强平聚合**（1h 多/空 USD） | 币安 WS 或 **CoinAnk** 或 **Coinglass** | `ctx.LiquidationAgg` / `ctx.CoinglassLiquidation` → applyDirectionBonus |
| **资金费率 8h 均值** | Binance（GetPremiumIndex + 历史） | `ctx.BinanceFundingRateAvg8h` → applyDirectionBonus |
| **Basis（永续-现货价差）** | 计算自行情/Binance | `ctx.BasisMap` → applyDirectionBonus |

**小结**：方向池核心是 **行情 + 多周期/技术**；加成来自 **Binance/Coinglass 多空**、**nofxos 排行**、**强平**、**资金费率**、**Basis**。

## 三、AI 实时（输入给 AI 的“实时”数据）

AI 主流程（开平仓决策）每次调用时，User Prompt 里包含的“实时”数据即 **BuildUserPrompt** 所组装的全部内容，来源为当周期已写入的 Context。

### 3.1 涉及数据（按 Prompt 区块）

| 区块 | 数据内容 | 数据源 |
|------|----------|--------|
| **账户与持仓** | 权益、保证金、未实现盈亏、持仓列表（标的面、方向、入场价、标记价、强平价、分层止盈已触发等） | 交易所/交易层 → `ctx.Account`、`ctx.Positions` |
| **候选与方向池** | 候选列表、**系统方向池判定**（多/空及强度%） | Pipeline 输出 → `ctx.CandidateCoins`、`ctx.DirectionPoolLong/Short` |
| **行情与指标** | 每候选/持仓的 K 线摘要、4h/1h 方向、同向性、current_price、EMA20、MACD、RSI、OI（若启用） | 行情 → `ctx.MarketDataMap` → formatMarketData |
| **币安衍生** | 多空比、资金费率、Taker 买卖比（按标的） | Binance → `ctx.BinanceLongShortMap`、`BinanceFundingMap`、`BinanceTakerMap` → formatBinanceDerivativesForAI |
| **数据补强** | 资金费率 8h 均值、近 8 期费率、Basis、BTC 占比、强平聚合、Coinglass OI/资金/多空/强平/恐惧贪婪/山寨季/ETF 流等 | Binance/Coinglass/CoinAnk/外部占比 → formatDataStrengtheningForAI |
| **策略触发平仓** | 本周期内由策略（止损/止盈）触发的平仓 | 策略层 → `ctx.StrategyTriggeredCloses` |
| **近期订单与统计** | 近期成交、胜率、盈亏比、回撤等 | 交易/统计层 → `ctx.RecentOrders`、`ctx.TradingStats` |

**小结**：AI 实时 = 当周期 **Context 全量**：账户与持仓、候选与方向池、行情与指标、币安衍生、数据补强、策略平仓、近期订单与统计；**数据源** = 行情（market）、交易所（持仓/账户）、Binance、nofxos、Coinglass、CoinAnk、策略执行结果。

## 四、AI 预测（AI 输出用于系统的部分）

### 4.1 涉及数据（AI 的输入）

与「AI 实时」相同，即上节全部 Context 数据；此外 Prompt 中明确要求 AI 依据「多周期趋势、量能、OI/资金流、资金费率与强平」形成：

- **market_regime**（trend_up / trend_down / ranging / high_volatility / reversal）
- **scenario**（continuation / reversal / range）
- **near_term_outlook**、**key_levels**
- **symbol_predictions**：每标的 **predicted_direction**、**confidence**、**suggest_open** 等

### 4.2 数据源（与 AI 实时一致）

所有输入到 AI 的数据源见第三节；无额外独立数据源。系统侧使用预测时，会再结合 **方向池**（实时）与 **三条件共振** 规则做开仓判定。

---

## 五、止盈止损调整（SL/TP 专用 AI 分析）

### 5.1 涉及数据

仅对**当前持仓**做轻量分析，不涉及候选开仓；输入为「持仓 + 边界 + 上一周期 regime/scenario」。

| 数据 | 含义 | 数据源 |
|------|------|--------|
| **持仓快照** | 标的、方向、入场价、标记价、盈亏%、持仓时长、ATR、当前 trailing 状态 | 交易所/策略层 → 转为 `SLTPPositionInfo` |
| **边界 Bounds** | atr_mult_sl 范围、lock_profit_pct 范围、confirm_cycles_base | 策略配置（来自系统策略） |
| **regime / scenario** | 上一周期 AI 的 market_regime、scenario | 上一轮主周期 AI 决策缓存 → `lastAIDecisionCache` |

### 5.2 数据源小结

- **持仓与 ATR**：交易所 + 行情（mark、ATR 等）。
- **Bounds**：策略配置（store）。
- **regime / scenario**：**上一周期主流程 AI 输出**（缓存），不在此周期再拉新行情或新方向池。

---

## 六、止盈止损调整 + AI 实时 + AI 预测 + 5 种场景

### 6.1 “5 种场景”指什么

止盈止损调节的 **5 种建议类型**（在 `BuildSLTPOnlyPrompts` 的 systemPrompt 中约定）为：

| 场景 | 含义 | 典型建议 |
|------|------|----------|
| **choppy_hold** | 价格震荡，持仓持有 | 放宽（trail_aggressiveness=low 或 confirm_cycles_delta=+1） |
| **trend_ride** | 趋势 intact | 收紧（trail_aggressiveness=high） |
| **lock_profit** | 已有浮盈 | 在边界内建议 lock_profit_pct（如 2~3） |
| **trend_weakening** | 动能减弱 | 收紧或降低 lock_profit_pct |
| **high_vol_hold** | 波动放大但方向仍可接受 | confirm_cycles_delta=+1 或 atr_mult_sl 取上界 |

AI 根据「当前持仓 + 边界 + 上一周期 regime/scenario」判断当前更接近哪一种场景，并输出 `position_sl_tp_adjustments`（每仓位的 advice 及具体参数建议）。

### 6.2 各块数据与数据源（汇总）

| 板块 | 使用的数据 | 数据源 |
|------|------------|--------|
| **止盈止损调整** | 持仓、ATR、Bounds、regime、scenario | 交易所、行情、策略配置、上周期 AI 缓存 |
| **AI 实时** | 见第三节 | 行情、交易所、Binance、nofxos、Coinglass、CoinAnk、策略 |
| **AI 预测** | 同上（主流程 Prompt 全量） | 同上 |
| **5 种场景** | 仅 SL/TP 轻量 Prompt 内：持仓 + Bounds + regime + scenario | 同上；场景本身是 AI 在 5 类建议中做选择，不新增数据源 |

## 七、各板块：是否需要 新增 / 补强 / 替代（已应用）

以下按板块给出数据层面的建议；**打勾项已在代码中实现**，详见 `docs/最新数据源与提示词参数逻辑数据传递.md`。：**新增**（当前没有、建议增加的数据或数据源）、**补强**（已有但可叠加多源/多维度以增强）、**替代**（用更优数据源替换现有单一来源）。

### 7.1 过滤机制

| 建议类型 | 说明 | 建议动作 |
|----------|------|----------|
| **补强** ✅ | **资金费率**：目前用单所（行情/Binance）做 funding_ok；极端费率时单所易偏差。 | **已应用**：Layer1 funding_ok 在存在 CoinglassFundingMap 时同时校验多所费率区间。 |
| **补强** | **流向 / 净流入**：仅 nofxos 一家；无交叉校验。 | 可选 **Coinglass netflow-list**（若有）与 nofxos 对照，或作补强因子。 |
| **补强** | **涨跌榜 / OI 排行**：仅 nofxos。 | 若有 Coinglass 等价或全市场排名，可作补强；当前非刚需。 |
| **替代** | **多空比**：Layer1 未直接用多空比；方向池用 Binance。 | 过滤机制本身无需改；若希望「过滤前就考虑多空结构」，可**新增** Layer1 项「多空与方向一致」且用 **Coinglass 多所多空** 替代单所。 |
| **新增** | **入场时机 / 信号年龄**：已有时间维度的第三层。 | 无需新增数据；保持即可。 |

**小结（过滤机制）**：以 **补强** 为主——资金费率用多所/OI 加权补强；流向、排行可选项补强。**替代**仅在对「多空比参与过滤」有需求时，用 Coinglass 多所多空替代单所。

---

### 7.2 方向池

| 建议类型 | 说明 | 建议动作 |
|----------|------|----------|
| **替代 / 补强** ✅ | **多空比**：当前 Binance 单所；启用 Coinglass 时已对 BTC/ETH 用 Coinglass 覆盖。 | **已应用**：多所多空拉取 BTC/ETH + 候选最多 8 标；写入 BinanceLongShortMap 时 key 含 BTCUSDT/ETHUSDT 便于 pipeline 查找。 |
| **补强** | **强平**：当前币安 WS 或 CoinAnk 或 Coinglass 聚合金额。 | 用 **Coinglass 强平热力图/关键价位** 补强「价位维度」，便于后续做 key_levels / scenario（reversal）。 |
| **补强** | **资金费率 8h / Basis**：当前 Binance 或自算。 | 用 **Coinglass OI 加权资金费率**、**basis/history**（若有）补强，加成更贴近全市场成本。 |
| **新增** | **大户/鲸鱼指标**：方向池仅有「大户多空比」。 | 若有 **Coinglass whale-index / cgdi / cdri**，可**新增**为方向池加成项，强化趋势与反转信号。 |

**小结（方向池）**：**替代**：多空比可全面切多所（Coinglass）。**补强**：强平加价位维度、资金费率加 OI 加权/Basis 多源。**新增**：鲸鱼/多空扩散类指标（按需）。

### 7.3 AI 实时（输入给 AI 的实时数据）

| 建议类型 | 说明 | 建议动作 |
|----------|------|----------|
| **补强** | **行情与指标**：单交易所 K 线/指标。 | 保持主源；若有**多所聚合价格/量**（如 Coinglass 综合价），可作补强提示，非必须。 |
| **补强** | **多空/资金费率/Taker**：已支持 Binance + Coinglass（补强）。 | 维持「Coinglass 启用时写入 Context」；可考虑 **WSS 实时** 写入最新一条，减少延迟。 |
| **补强** | **强平**：当前为金额汇总。 | **Coinglass 强平热力图/关键价位** 写入 Prompt，补强 AI 对 key_levels / reversal 的判断。 |
| **新增** | **恐惧贪婪 / BTC 占比 / 山寨季 / ETF 流**：已接入 Coinglass 并写入数据补强。 | 已新增；保持即可。 |
| **新增** | **链上/期权/宏观**：当前未给 AI。 | **可选新增**：如 Coinglass 的 SOPR、NUPL、期权 max-pain、宏观日历等，用于 regime / risk_alert，按需接入。 |

**小结（AI 实时）**：以 **补强** 为主（强平价位、WSS 实时）；**新增**已包含恐惧贪婪/山寨季/ETF 等，其余链上/期权为可选新增。

### 7.4 AI 预测（输出被系统与三条件共振使用）

| 建议类型 | 说明 | 建议动作 |
|----------|------|----------|
| **补强** | 预测依赖的输入与「AI 实时」相同。 | 凡对 AI 实时的 **补强/新增**（多所多空、OI 加权费率、强平价位、恐惧贪婪、ETF 等），都会**间接补强 AI 预测**质量；无需单独为「预测」再加数据源。 |
| **替代** | 无。 | 预测逻辑不直接「替代」某数据源；仅依赖 Context 质量。 |

**小结（AI 预测）**：不单独做替代；通过 **提升 AI 实时输入（补强/新增）** 即可提升预测与三条件共振的稳定性。

### 7.5 止盈止损调整（SL/TP 专用分析）

| 建议类型 | 说明 | 建议动作 |
|----------|------|----------|
| **补强** | 当前仅：持仓、ATR、Bounds、上周期 regime/scenario。 | **补强**：可把**当前周期**的 regime/scenario 或**简要行情**（如 1h 方向、波动率）写入 SL/TP 专用 Prompt，避免完全依赖「上一周期」缓存。 |
| **新增** | 5 种场景判断缺少「实时波动/情绪」维度。 | **可选新增**：当前周期 **恐惧贪婪** 或 **强平热度** 等 1～2 项，供 AI 区分 high_vol_hold / choppy_hold。 |
| **替代** | 无。 | 持仓/Bounds 来源固定；无需替代。 |

**小结（止盈止损调整）**：以 **补强** 为主（当前周期 regime/行情或波动）；**可选新增**少量情绪/强平类数据，便于 5 种场景判断。

### 7.6 5 种场景（choppy_hold / trend_ride / lock_profit / trend_weakening / high_vol_hold）

| 建议类型 | 说明 | 建议动作 |
|----------|------|----------|
| **补强** | 场景判断仅基于：持仓 + Bounds + 上周期 regime/scenario。 | 与「止盈止损调整」一致：**补强**当前周期行情或波动/情绪，使 choppy / trend / high_vol 区分更准。 |

| **替代** | 无。 | 场景为分类标签，不涉及数据源替代。 |

**小结（5 种场景）**：**补强**当前周期信息即可；**可选新增**波动/强平热度等短句，无需替代。

## 九、小结

- **过滤机制**：依赖 **行情 + nofxos（OI/净流入/涨跌榜）+ 可选 Binance 资金费率**，对候选做 Layer1/2/3 与 OI 对齐。
- **方向池**：以 **行情** 为主算多空与强度，用 **Binance/Coinglass 多空、nofxos 排行、强平、资金费率、Basis** 做加成。
- **AI 实时 / AI 预测**：同一套 **Context**（账户、持仓、候选、方向池、行情、币安衍生、数据补强、策略平仓、订单与统计），数据源 = 行情、交易所、Binance、nofxos、Coinglass、CoinAnk、策略。
- **止盈止损调整**：仅用 **持仓、ATR、Bounds、上一周期 regime/scenario**，来源为交易所、行情、策略配置与 **上周期 AI 缓存**。
- **5 种场景**：在 SL/TP 分析中由 AI 根据上述止盈止损输入，在 choppy_hold / trend_ride / lock_profit / trend_weakening / high_vol_hold 中选一类并给出参数建议，不引入新数据源。
