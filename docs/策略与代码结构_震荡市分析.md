# 策略与代码结构：应对「震荡为主、趋势较少」的市场环境分析

本文档基于「**市场震荡情况最多，趋势环境少**」的假设，对当前 AI 交易策略与代码结构做整体分析，评估对震荡/趋势环境的匹配度，并给出可改进点。

---

## 一、当前策略与代码结构概览

### 1.1 核心逻辑定位

| 维度 | 当前设计 | 说明 |
|------|----------|------|
| **策略类型** | 趋势跟踪（Trend Following） | 多周期共振 + OI/资金流确认后才开仓 |
| **开仓条件** | 4h 定方向 + 1h 确认 + 15m 入场，且 4h 与 1h 同向 | 见 `store/strategy.go` 入场标准、`kernel/schema.go` 多时间框架指南 |
| **震荡/横盘** | 明确列为「观望」 | 多周期指南：**观望 = 4h 震荡 或 各周期方向不一致**；入场标准：**避免横盘震荡市场** |
| **默认行为** | 不确定时输出 wait | engine：若未解析到有效 JSON 则进入 safe wait；Prompt：if unsure, output a single wait decision |

### 1.2 与「震荡」相关的已有设计

- **市场状态识别**（schema.go）
  - **横盘震荡**：价格围绕 EMA20 波动 + MACD 接近 0 + RSI 40–60 + 1h 波动率 <2%。
  - **弱趋势/震荡市场**：止盈用 2.5–3.0× ATR，快速止盈避免回吐。
- **多时间框架**
  - **观望**：4h 震荡 **或** 各周期方向不一致 → 不开仓。
  - 示例 2（山寨币）：「1h 上升、OI 增加，但 **4h 震荡**」→ 止盈不宜过大（3×ATR）。
- **场景示例**（schema 场景 2、5）
  - 场景 2：假突破（4h 横盘、缩量、OI 减少）→ **wait**。
  - 场景 5：横盘观望（价格区间震荡、MACD 近 0、极低波动、OI 无变化）→ **wait**。
- **Prompt 提醒**
  - 震荡行情中频繁交易会累积手续费；默认 HOLD，仅在极端信号时建议平仓。
- **入场标准（策略预设）**
  - 「避免以下情况」中明确包含：**横盘震荡市场**。

### 1.3 与「趋势」相关的设计

- 开仓依赖：多周期同向 + OI 与价格同向 + 资金流确认 + 信心度 ≥ MinConfidence（如 75）+ 盈亏比 ≥ MinRiskRewardRatio（如 3:1）。
- 币种来源：AI500、OI Top/Low、涨跌幅榜等，偏动量和趋势环境。
- 止损止盈：ATR/追踪止损/分层止盈，按「趋势延续」假设给足空间（强趋势 3.5–4× ATR 止盈等）。

## 二、在「震荡为主」假设下的匹配度分析

### 2.1 做得好的地方（利于震荡市）

| 项目 | 说明 |
|------|------|
| **观望即主选项** | 4h 震荡或周期不一致时明确为「观望」，不开仓，与「震荡时少做」一致。 |
| **禁止横盘开仓** | 入场标准与避免清单中明确「横盘震荡市场」不开仓，减少震荡里追涨杀跌。 |
| **弱趋势快速止盈** | 弱趋势/震荡市场用 2.5–3.0× ATR 止盈、快速止盈，降低利润回吐。 |
| **反对频繁交易** | Prompt 多处强调震荡中频繁交易会累积手续费，默认 HOLD、交给策略执行 SL/TP。 |
| **假突破示例** | 场景 2 教 AI 在 4h 无趋势、缩量、OI 减少时选择 wait，降低假突破开仓。 |
| **Safe wait** | 解析失败或无有效决策时进入 wait，避免乱开仓。 |

整体上，**规则层面已经偏向「震荡 = 少做/不做」**：逻辑自洽，与「市场震荡最多」的假设不冲突。

### 2.2 可能不足或风险点

| 项目 | 说明 |
|------|------|
| **震荡识别依赖 AI 主观** | 「4h 震荡」没有在代码里用客观指标（如 ADX、布林宽度、区间幅度）强制判定，完全依赖 AI 对 K 线/EMA/MACD 的解读，易出现「看起来像趋势」的震荡被当成趋势。 |
| **趋势场景权重更高** | 场景示例中趋势突破、止盈、止损、反手等「有动作」的场景多，「横盘 wait」仅 1 个；若模型倾向「做点什么」，可能在高比例震荡环境中仍偏多开仓。 |
| **无「震荡时减仓/降杠杆」** | 当前只有「开/不开」，没有「震荡或方向不明时若已持仓则减仓或降杠杆」的规则或参数。 |
| **币种池偏趋势** | OI Top/Low、涨跌幅榜等在趋势/动量市更有效；纯震荡市没有专门「区间/波动率」选币，只是通过「不开仓」来应对。 |
| **MinConfidence 未按环境调** | MinConfidence（如 75）是全局的；若希望震荡市更保守，可以设想「识别为震荡时提高开仓门槛」，但目前无此分支。 |

### 2.3 小结：当前应对震荡环境如何

- **设计意图**：震荡 = 观望 + 不开新仓 + 持仓不频繁平仓，趋势 = 多周期共振才开仓。这与「震荡为主、趋势少」是**兼容**的。
- **主要风险**：  
  1）**误把震荡当趋势**（4h 震荡被读成弱趋势而开仓）；  
  2）**开仓频率仍偏高**（示例与模型偏好导致在边界情况多开仓）。  
- **结论**：策略和代码结构在「震荡为主」下**方向正确**，但**对震荡的约束主要靠 Prompt 与示例**，缺少「震荡优先」的强化和可选的结构化过滤（如 ADX/区间），仍有优化空间。

## 三、代码结构层面与震荡/趋势的对应关系

| 模块 | 作用 | 对震荡市的支撑 |
|------|------|----------------|
| **kernel/schema.go** | 市场状态（含横盘）、多周期规则、观望条件、弱趋势止盈、场景 2/5 | 定义「震荡=观望」、弱趋势快止盈、假突破/横盘 wait |
| **kernel/prompt_builder.go** | 角色、入场标准、避免横盘、耐心持仓、少频繁交易 | 明确禁止横盘开仓、强调震荡中不频繁交易 |
| **kernel/engine.go** | 注入约束（MaxPositions、MinConfidence）、提醒「sideways consolidation」避免、safe wait | 限制仓位与信心度、解析失败时 wait |
| **store/strategy.go** | 默认策略预设、入场标准文案、动态 SL/TP 参数 | 预设里写「避免横盘震荡市场」；SL/TP 不区分震荡/趋势（由 AI 选倍数） |
| **trader/auto_trader.go** | 执行开平仓、动态 SL/TP、AI 平仓确认 | 不区分行情类型；执行层与「震荡优先」无冲突 |
| **backtest/runner.go** | 回测 | 若回测数据中震荡段多，可用来检验「少开仓、少亏损」是否成立 |

当前**没有**单独「市场状态/震荡过滤器」模块：是否震荡、是否允许开仓，全部由 AI 在 Prompt/Schema 约束下判断。

## 四、改进建议（在保持现有架构下）

### 4.1 Prompt / Schema 层面（优先、低成本）

1. **强化「震荡优先」的默认**（已落实）
   - 在系统 Prompt（`kernel/prompt_builder.go`）顺势交易段增加：  
     「**多数时间为震荡或方向不明，默认应以观望为主；仅当多周期与 OI 明确指向同一趋势时才考虑开仓。**」（中英各一）
   - 在 Schema 多时间框架指南（`kernel/schema.go`）观望条增加：  
     「**市场多数时间为震荡，4h 震荡时本周期一律观望，不开新仓。**」（中英各一）
   - 降低「总想做一笔」的倾向，更符合震荡为主。

2. **增加「震荡/方向不明时 wait」的示例**
   - 在 schema 的 Trading Scenario 中再增加 1 个「4h 震荡 + 1h 略偏多但未形成趋势 → wait」的示例，与场景 5 形成呼应，提高 wait 的可见度。

3. **明确「4h 震荡」的操作定义**
   - 在 schema 市场状态或多周期指南中补充可操作描述，例如：  
     「4h 震荡：价格在 4h EMA20 上下反复、或 4h MACD 长期在 0 轴附近、或 4h 近期高低点区间 < 某比例；此种情况本周期一律观望，不开新仓。」

### 4.2 策略配置层面（可选）

4. **震荡市更保守的开仓门槛**
   - 若希望进一步压低震荡期的开仓，可把 **MinConfidence** 从 75 提到 80（或通过策略配置由用户选择），不改代码逻辑，只改默认或配置。

5. **弱趋势时降低仓位（若未来支持）**
   - 当前仓位由 AI 的 position_size_usd 与策略上限决定，没有「趋势强度 → 仓位系数」。若后续加「弱趋势/疑似震荡时仓位减半」等规则，可在 store 或执行层做系数，进一步适配「震荡多、趋势少」。

### 4.3 代码/结构层面（可选、需开发）

6. **可选：震荡过滤器（Regime Filter）**
   - 在准备给 AI 的上下文前，根据 4h（或 1h）计算简单指标：例如 4h ADX < 25 或 4h 布林宽度 < 某阈值 → 标记为 `regime: sideways`。
   - 将该标记注入 Prompt（如「当前 4h 被标记为震荡，请优先考虑 wait」），或在严格模式下：若 `regime == sideways` 且动作为 open_*，则强制改为 wait（需产品决策）。
   - 这样可在「震荡为主」下多一层客观约束，减少 AI 把震荡误判为趋势。

7. **回测验证**
   - 用历史数据中震荡占比较高的区间做回测，看：开仓次数是否明显减少、亏损是否多发生在「误判趋势」的几根 K 线。据此再微调 MinConfidence、示例数量或是否启用震荡过滤器。

## 五、总结表

| 维度 | 现状 | 与「震荡为主」的匹配 |
|------|------|----------------------|
| 开仓条件 | 多周期同向 + OI/资金流 + 高信心度 | ✅ 震荡时本应不满足，理论上有助于少开仓 |
| 震荡处理 | 观望、禁止横盘开仓、弱趋势快止盈 | ✅ 已显式支持「震荡 = 少做」 |
| 示例与权重 | 趋势/止盈/止损场景多，横盘 wait 少 | ⚠️ 可增加震荡 wait 示例、强化默认观望 |
| 震荡识别 | 完全依赖 AI 解读，无客观指标 | ⚠️ 可增加「震荡优先」文案；可选加 ADX/区间过滤 |
| 仓位/杠杆 | 不按行情类型区分 | ✅ 当前无冲突；可选做「弱趋势减仓」 |
| 执行与风控 | 动态 SL/TP、确认周期、反手等 | ✅ 与震荡/趋势划分解耦，无需改 |

**结论**：在「市场震荡情况最多，趋势环境少」的假设下，**当前策略与代码结构整体是适配的**：以趋势跟踪为主、在震荡时依靠「观望 + 禁止横盘开仓 + 弱趋势快止盈」来减少无效交易。主要改进空间在于：**在 Prompt/Schema 中进一步强化「震荡优先、默认观望」**，并视需要增加震荡判定示例或可选的客观震荡过滤，使行为更稳定地符合震荡为主的市场环境。

## 六、震荡市目标澄清：拿住持仓 + 盈利后平仓

若市场**以震荡为主**，单纯「震荡少开仓」会导致开仓机会很少。更合理的目标是：

- **在震荡市里仍然可以开仓**（例如在区间下沿/支撑附近做多、区间上沿/阻力附近做空），而不是一律观望。
- **开仓后的重点**：**拿住持仓**（不被区间内的正常波动洗出去），**盈利后平仓**（不贪大趋势，达到合理利润就出）。

即：**震荡市 = 在有利位置开仓 + 扛住震荡拿住仓 + 达到目标利润后平仓**。

### 6.1 如何「拿住持仓」

| 手段 | 说明 | 当前是否支持 |
|------|------|----------------|
| **止损不要太紧** | 震荡时价格会来回扫，止损过窄容易被震出 | ✅ 开仓时 AI 可选 2.0–2.5× ATR 止损；策略有 ATR 高波动宽容、ConfirmCycles |
| **连续确认再止损** | 单根 K 线跌破不立刻平仓，连续 N 周期满足才执行 | ✅ ConfirmCycles=2，高波动时多 1 周期 |
| **高波动宽容** | 波动大时自动用更宽 ATR 止损、多确认 1 次 | ✅ ATRToleranceEnabled + ATRHighMultiplier |
| **最小持仓时间** | 开仓后一段时间内不触发动态止损，避免刚进去就被洗出 | ✅ MinHoldMinutes=10 |
| **初始兜底止损** | 极端行情才触发，日常主要靠 ATR/追踪 | ✅ InitialStopPercent=8，宽兜底 |

结论：**拿住持仓**主要靠「开仓时设较宽止损（如 2.0–2.5× ATR）+ 系统已有连续确认与高波动宽容」。需要在 Prompt/Schema 中明确：**震荡市开仓时优先用止损区间上限（2.0–2.5× ATR），目标是在区间内扛住波动、拿住仓**。

### 6.2 如何「盈利后平仓」

| 手段 | 说明 | 当前是否支持 |
|------|------|----------------|
| **止盈目标现实** | 震荡市不追求大趋势，达到 2.5–3× ATR 或区间对侧即可止盈 | ✅ 弱趋势/震荡市场止盈 2.5–3.0× ATR 已在 Schema 中 |
| **分层止盈** | 第一档（如 4%）先兑现一部分并移止损到成本，锁利 | ✅ ScaledLevels 4%/7%/10%，首档 MoveStopToBreakeven |
| **锁定利润** | 盈利达 2.5% 后止损不低于成本，避免由盈转亏 | ✅ LockProfitPercent=2.5 |
| **追踪止损** | 盈利达 2.5% 激活 L1，回撤 1.5% 触发，锁住部分利润 | ✅ TrailingLevels L1/L2 |

结论：**盈利后平仓**由策略的分层止盈、LockProfit、追踪止损自动执行；AI 开仓时在震荡市应设**适中止盈（2.5–3× ATR）**，不贪大趋势，让系统在盈利后自动兑现。

### 6.3 震荡市开仓原则（建议写入 Schema/Prompt）

1. **可开仓**：4h 震荡时，若有清晰区间（支撑/阻力），可在**区间下沿附近做多、区间上沿附近做空**；不在区间中间或方向不明时追单。
2. **止损**：震荡市用**止损倍数偏上限**（2.0–2.5× ATR），避免被区间内正常波动洗出，便于拿住仓。
3. **止盈**：震荡市用**适中止盈**（2.5–3.0× ATR），盈利即落袋，不赌突破大趋势。
4. **持仓中**：交给系统连续确认、高波动宽容、追踪止损与分层止盈执行，不因单根 K 线或小幅回撤就建议平仓。

这样既保留震荡市的开仓机会，又强调「拿住仓 + 盈利后平仓」，与「市场以震荡为主」的假设一致。
