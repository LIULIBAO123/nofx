# 止盈策略实现与整体分析

本文档说明当前**动态止盈**的代码结构、四类止盈条件、数据流、提示词与参数逻辑，并做功能一致性检查。

---

## 一、执行入口与前置条件

- **入口**：与止损同在 `checkDynamicStopLossTakeProfit()` 内执行；对每个仓位**先做止损检查、再做止盈检查**（同一周期、同一批 K 线）。
- **仓位与数据**：仓位来自 `at.trader.GetPositions()`；K 线由**止损配置**的 `klines_timeframe` 决定（空则 "15m"），同一批 K 线用于 ATR、支撑/阻力（或 EMA20）、以及止盈的 `atr` 与 `tpLevel`（多单用 resistanceLevel，空单用 supportLevel）。
- **前置**：
  1. **最小持仓**：与止损共用「最小持仓时间」判断（取止损与止盈 `MinHoldMinutes` 的较大值），未满则本周期不参与任何动态止损/止盈。
  2. **锁利与 breakeven**：若策略配置了 `LockProfitPercent` 且当前浮盈已达该比例，则在止损分支中可能触发「回撤到入场价 → breakeven 止损」；止盈逻辑本身不直接使用 LockProfitPercent，仅与止损共用「已锁利」状态用于限制止损价。
  3. **止盈检查时机**：仅当**本周期未因止损触发而 continue** 时，才会执行 `takeProfitChecker.CheckTakeProfit`；即同一周期内**止损优先于止盈**。

---

## 二、五类止盈的检查顺序与触发条件

在 `kernel/take_profit.go` 的 `CheckTakeProfit` 中，按**固定顺序**依次检查，任一条件满足即返回该 signal（**仅支持「any」逻辑**，无「all」）。

| 顺序 | 类型 | 配置开关 | 触发条件（简要） | 说明 |
|------|------|----------|------------------|------|
| 1 | **分层止盈（Scaled）** | `ScaledEnabled` 或 有 `ScaledLevels` | 按档位顺序：当前价达到该档盈利%目标且该档**未已触发**（`ScaledLevelsTaken` 不包含该档），则触发该档并返回 `PartialPercent`=该档 `ClosePercent` | 先检查分层，便于部分平仓先于固定全平；已触发档位用 `position.ScaledLevelsTaken` 去重（容差 0.15%） |
| 2 | **回撤止盈（Trailing TP）** | `TrailingTPEnabled` | 浮盈≥激活阈值 且 从峰值回撤≥max(固定%, ATR比例%)；可选确认时长 | 不依赖涨到高挡位，在盈利回调前锁利；ATR 与确认防震荡 |
| 3 | **固定止盈（Fixed）** | `FixedEnabled` 且 `FixedPercent` 非空 | 多：当前价 ≥ 入场价×(1+百分比)；空：当前价 ≤ 入场价×(1−百分比) | 达则全平（PartialPercent=100） |
| 4 | **ATR 止盈** | `ATREnabled` 且 atr>0 | 多：当前价 ≥ 入场价 + 倍数×ATR；空：当前价 ≤ 入场价 − 倍数×ATR。倍数=(Min+Max)/2 | 全平；默认倍数 2.0–4.0 中点 |
| 5 | **阻力/支撑止盈** | `ResistanceEnabled` 且传入的 level>0 | 多：传入阻力位，且阻力>入场价，且当前价≥阻力×(1−缓冲%) 且当前价>入场价；空：传入支撑位，且支撑<入场价，且当前价≤支撑×(1+缓冲%) 且当前价<入场价 | 避免无效目标（阻力低于入场或支撑高于入场不触发） |

- **数据**：`currentPrice` 为 `markPrice`；`atr`、`resistanceLevel`/`supportLevel` 与止损共用（同一批 K 线、同一 `tf`）。
- **分层已触发记录**：由 `auto_trader` 的 `scaledLevelsTaken` 维护；每次执行分层止盈后 `addScaledLevelTaken(posKey, profitPct)`，全平或仓位关闭时 `clearScaledLevelsTakenForPosition(posKey)`。`PositionInfo.ScaledLevelsTaken` 在构建时由 `at.getScaledLevelsTaken(posKey)` 注入。

---

## 三、分层止盈的启用逻辑与顺序

- **启用**：与文档/止损侧一致，**有档位即视为分层止盈参与检查**：  
  `scaledEnabled := (ScaledEnabled != nil && *ScaledEnabled) || (len(ScaledLevels) > 0 && (ScaledEnabled == nil || *ScaledEnabled))`  
  即：显式开或仅配置了 `ScaledLevels` 都会检查。
- **顺序**：在 `CheckTakeProfit` 内**先检查分层、再检查固定**，因此当固定百分比与第一档接近时，会先触发分层部分平仓而非直接固定全平。
- **档位去重**：`isLevelTaken(position, level.ProfitPercent, "scaled")` 用 `position.ScaledLevelsTaken` 与 0.15% 容差判断该档是否已触发，避免同一档重复触发。

---

## 四、执行与平仓原因

- `executeTakeProfit` 根据 signal 的 `Type` 与 `PartialPercent`：  
  - 部分平仓：`decision.CloseQuantity = position.Quantity * (PartialPercent/100)`，下单后 `addScaledLevelTaken(posKey, profitPct)`。  
  - 全平：`clearScaledLevelsTakenForPosition(posKey)`。
- **平仓原因**：`close_reason = "system:tp:" + signal.Type`（如 `system:tp:scaled`、`system:tp:trailing_tp`、`system:tp:fixed`、`system:tp:atr`、`system:tp:resistance`）；每次执行（含部分平）都会 `SetPendingCloseReasonBySymbol`，便于 OrderSync 与前端展示。

---

## 五、提示词

- **策略动态 SL/TP 段落**：`kernel/engine.go` 的 `formatStrategyDynamicSLTP` 对止盈部分输出：最小持仓、分层止盈档位（有档位即展示）、ATR 止盈倍数、阻力位止盈、锁定利润阈值等，与当前策略配置一致。
- **系统原则**：提示词中写「分层止盈/追踪止损由策略执行」「止盈止损交给策略」等，与「先执行 checkDynamicStopLossTakeProfit、再执行 AI 决策」一致。

## 六、参数与默认值（概要）

| 参数 | 推荐默认 | 说明 |
|------|----------|------|
| `enabled` | true | 关闭则整块动态止盈不执行。 |
| `min_hold_minutes` | 5 或 10 | 与止损共用「最小持仓」上限，未满不触发。 |
| `fixed_enabled` / `fixed_percent` | false / 8 | 固定止盈可选；达则全平。 |
| `scaled_enabled` / `scaled_levels` | true / 档位表 | 有档位即参与检查；档位按顺序、已触发档不重复。 |
| `atr_enabled` / `atr_multiplier_min|max` | false / 2.5, 4.0 | 与 kernel getFloat64Value 默认一致。 |
| `resistance_enabled` / `resistance_buffer` | false / 0.5 | 阻力/支撑止盈。 |
| `lock_profit_percent` | 2.5 或 5 | 达此盈利后由**止损侧**将回撤到入场价判为 breakeven 止损。 |

止盈**不单独配置** K 线周期：与止损共用 `klines_timeframe`，同一循环内同一批 K 线。

---

## 七、与止损的协作关系

- **同周期同数据**：止盈与止损在同一函数、同一仓位循环内，共用 K 线（tf）、ATR、支撑/阻力（或 EMA20）、最小持仓。
- **顺序**：先止损检查（含确认周期/分钟），若触发则执行止损并 `continue`；否则再止盈检查，若触发则执行止盈。
- **锁利**：`LockProfitPercent` 在止损分支中用于 breakeven 判定与止损价限制，止盈只负责「达目标价/档位则平仓」，不直接读 LockProfitPercent。

---

## 八、功能是否均可正常工作

| 功能 | 条件 | 结论 |
|------|------|------|
| 最小持仓 | MinHoldMinutes 与止损取大，未满则跳过 | ✅ 与止损共用逻辑。 |
| 分层止盈 | ScaledEnabled 或 ScaledLevels 非空 | ✅ 有档位即检查；先于固定；已触发档用 ScaledLevelsTaken 去重。 |
| 固定止盈 | FixedEnabled 且 FixedPercent 非空 | ✅ 达则全平。 |
| ATR 止盈 | ATREnabled 且 atr>0 | ✅ 倍数取 (Min+Max)/2，与 kernel 默认一致。 |
| 回撤止盈 | TrailingTPEnabled，激活阈值+回撤达标，可选确认时长 | ✅ 峰值由 caller 传入；ATR 防震荡；确认时长在 auto_trader 中实现。 |
| 阻力/支撑止盈 | ResistanceEnabled 且 tpLevel>0 且目标有效 | ✅ 多=阻力>入场、空=支撑<入场才参与。 |
| 部分平仓 | signal.PartialPercent < 100 | ✅ 计算 CloseQuantity 并下单；ScaledLevelsTaken 更新。 |
| 平仓原因 | executeTakeProfit 写 close_reason | ✅ system:tp:scaled/fixed/atr/resistance；SetPendingCloseReasonBySymbol 每次执行都调用。 |

---

## 九、小结

- **结构**：止盈与止损同属 `checkDynamicStopLossTakeProfit`，共用 K 线周期与最小持仓；先止损后止盈，数据一致。
- **五类止盈**：分层（优先、可部分平）→ 回撤止盈 → 固定 → ATR → 阻力/支撑；任一触发即返回并执行，无「all」模式。
- **分层**：有档位即启用；档位按序、已触发档不重复；部分平仓后记录 ScaledLevelsTaken，全平或仓位关闭时清空。
- **提示词**：由同一策略 config 生成止盈相关说明，与执行逻辑一致。
- **功能**：最小持仓、分层/固定/ATR/阻力止盈、部分平仓与平仓原因写入均可正常工作；K 线周期与止损共用，无需单独配置。
