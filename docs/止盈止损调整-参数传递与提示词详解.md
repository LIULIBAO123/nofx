# 止盈止损调整：参数传递与提示词详解

本文档对「止盈止损调整」做详细分析：入口与流程、**参数传递**（输入从哪里来、输出如何被应用）、**提示词**（系统提示词、用户提示词、市场上下文的组成与含义）。

---

## 一、止盈止损调整流程概览

| 步骤 | 位置 | 说明 |
|------|------|------|
| 触发 | `trader/auto_trader.go` 主循环 | `useSLTPAnalysis && !now.Before(nextSLTP)` 时调用 `runSLTPAnalysisCycle(nextSLTP)` |
| 条件 | 配置 | `SLTPAnalysisInterval > 0` 且 `SLTPAnalysisInterval < ScanInterval`（如 3 分钟 < 10 分钟） |
| 无持仓 | runSLTPAnalysisCycle 开头 | `GetPositions()` 为空则直接 return，不调 AI |
| 拼输入 | runSLTPAnalysisCycle 循环 | 每仓 → `SLTPPositionInfo`（含边界、当前生效参数、last_advice）；汇总 regime、scenario、summary |
| 调 AI | kernel.RunSLTPOnlyAnalysis | BuildSLTPOnlyPrompts → callAIWithCaching → ParsePositionSLTPAdjustmentsFromRawResponse |
| 写回 | runSLTPAnalysisCycle 末尾 | 将 AI 返回的 `[]PositionSLTPAdjustment` 写入 `positionSLTPAdjustment[posKey]`，并更新 baseline、思维链 |

## 二、参数传递详解

### 2.1 输入：传给 AI 的数据从哪来

#### （1）每仓一条：`SLTPPositionInfo`（kernel/engine.go）

| 字段 | 含义 | 数据来源 |
|------|------|----------|
| `Symbol` | 标的（已归一化，如 BTCUSDT） | `market.Normalize(getPosStr(pos,"symbol",...))` |
| `Side` | long / short | 持仓 `side` 转小写 |
| `EntryPrice` | 入场价 | 持仓 `entryPrice` / `entry_price` |
| `MarkPrice` | 标记价 | 持仓 `markPrice` / `mark_price` |
| `PnlPct` | 未实现盈亏%（基于保证金） | `unrealizedPnl / marginUsed * 100` |
| `HoldMinutes` | 持仓分钟数 | `(nowMs - updateTime) / 60000`，updateTime 来自持仓或默认当前 |
| `ATR` | 14 周期 ATR | `marketClient.GetKlines(symbol,"15m",50)` → `kernel.CalculateATR(klines, 14)` |
| **策略边界** | | |
| `ATRMultMin` / `ATRMultMax` | ATR 止损乘数允许范围 | RiskControl.DynamicStopLoss.ATRMultiplierMin/Max；若该仓有 SL Profile 则用 Profile 的 ATRMultiplierMin/Max |
| `LockProfitPctMin` / `LockProfitPctMax` | 锁利比例允许范围（如 1~5%） | RiskControl.DynamicTakeProfit.LockProfitPercent 或 TP Profile 的 LockProfitPercent，限制在 [1,5] |
| `ConfirmCyclesBase` | 确认周期基数 | RiskControl.DynamicStopLoss.ConfirmCycles 或 SL Profile 的 ConfirmCycles |
| `TrailCurrent` | 当前追踪档位（策略/档位默认） | `positionTrailAgg[posKey]`，缺省 `"medium"` |
| **当前生效参数（上一轮 AI）** | | |
| `AppliedTrailAggressiveness` | 当前生效的追踪激进度 | `positionSLTPAdjustment[posKey].TrailAggressiveness` |
| `AppliedATRMultSL` | 当前生效的 ATR 止损乘数 | `positionSLTPAdjustment[posKey].ATRMultSL` |
| `AppliedLockProfitPct` | 当前生效的锁利% | `positionSLTPAdjustment[posKey].LockProfitPct` |
| `LastAdvice` | 上一轮 AI 建议场景 | `positionSLTPAdjustment[posKey].Advice`（如 choppy_hold） |

**说明**：`posKey = market.Normalize(symbol) + "_" + side`，与执行检查、平仓清理一致。边界与档位来自 `at.strategyEngine.GetConfig().RiskControl` + `positionSLProfile[posKey]` / `positionTPProfile[posKey]` / `positionTrailAgg[posKey]`（开仓时或此前 AI 写入）。

#### （2）regime、scenario

| 参数 | 含义 | 数据来源 |
|------|------|----------|
| `regime` | 市场状态（如 trend_up / ranging） | `at.lastAIDecisionCache.MarketRegime`（上一轮**主 AI 周期** runCycle 的 FullDecision 解析结果） |
| `scenario` | 场景（如 continuation / reversal） | `at.lastAIDecisionCache.Scenario` |

**注意**：regime/scenario 不是本 SL/TP 周期重新推理的，而是主周期缓存的；提示词中写为 "Last regime=... scenario=..."，供 AI 结合本周期市场上下文做 5 种场景判断。

#### （3）currentCycleSummary（本周期市场上下文）

| 来源 | 说明 |
|------|------|
| 优先 | `at.strategyEngine.BuildLiveMarketSummaryForSLTP()`：本周期实时拉取 BTC 行情 + Coinglass 数据，经 `FormatMarketContextForSLTP(ctx)` 生成多行文本 |
| 回退 | `at.lastMarketSummaryForSLTP`：主周期/系统周期里 `BuildCurrentCycleSummaryForSLTP(ctx)` 的缓存，当 BuildLiveMarketSummaryForSLTP 失败或未配置时使用 |

**BuildLiveMarketSummaryForSLTP 内部**：  
`ctx := &Context{}` → `FetchMarketData("BTCUSDT")` 填入 `ctx.MarketDataMap` → `FillCoinglassDataForSLTP(ctx)` 填入强平、OI、资金费率、多空比、情绪、ETF、鲸鱼、CGDI/CDRI、热力图关键价位等 → `FormatMarketContextForSLTP(ctx)` 输出多行字符串。

**FormatMarketContextForSLTP 包含的字段**（与提示词中说明一致）：  
BTC 1h/4h/24h/7d 涨跌、MACD、RSI；BTC 市值占比；Fear&Greed、AltcoinSeason；OI 1h/4h 变化；Funding BTC；L/S 多空比（全账户/大户）；强平 1h/4h/24h（多/空 USD）；CGDI、CDRI；WhaleIndex；ETF flow BTC/ETH；强平热力图关键价位。

### 2.2 输出：AI 返回什么、执行层怎么用

#### （1）AI 输出结构：`PositionSLTPAdjustment`（kernel/engine.go）

| 字段 | JSON 键 | 含义 | 执行层应用方式 |
|------|----------|------|----------------|
| `Symbol` | symbol | 标的 | 与 Side 一起拼 posKey，写回 `positionSLTPAdjustment[posKey]` |
| `Side` | side | long / short | 同上 |
| `Advice` | advice | 场景标签（choppy_hold / trend_ride / lock_profit / trend_weakening / high_vol_hold） | 仅用于展示与下一轮 prompt 的 LastAdvice；不参与执行公式 |
| `TrailAggressiveness` | trail_aggressiveness | low / medium / high | `checkDynamicStopLossTakeProfit` 中 `applyTrailAgg(effSL, adj.TrailAggressiveness)`，对 TrailingLevels 的 TrailingPercent 乘系数（high=0.8 收紧，low=1.2 放宽） |
| `ATRMultSL` | atr_mult_sl | 建议 ATR 止损乘数 | 与策略 min/max 比较，裁剪到 [minM, maxM] 后写回 `effSL.ATRMultiplierMin/Max`（同一值），用于 StopLossChecker |
| `LockProfitPct` | lock_profit_pct | 建议达到该盈利%后锁利 | 裁剪到 [1, 5] 后写回 `effTP.LockProfitPercent`，用于 TakeProfitChecker |
| `ConfirmCyclesDelta` | confirm_cycles_delta | 在基础 ConfirmCycles 上加减 | `requiredCycles = stopLossConfig.ConfirmCycles + adj.ConfirmCyclesDelta`，再限制在 [1, 3]，用于止损确认周期计数 |

**解析**：AI 原始响应中用 `<analysis>...</analysis>` 包裹 JSON；`ParsePositionSLTPAdjustmentsFromRawResponse(raw)` 提取 `position_sl_tp_adjustments` 数组，反序列化为 `[]PositionSLTPAdjustment`。只对 AI 返回的仓位写 `positionSLTPAdjustment`；未返回的仓位保留上一轮调节。

#### （2）Baseline 的写入（展示「原始→调整后」）

同一周期内，在写 `positionSLTPAdjustment[posKey]` 时，若存在本周期为该仓位算好的 `baselinesToStore[posKey]`，会同时写 `positionSLTPBaseline[posKey]`。Baseline 包含：Symbol、Side、TrailAggressiveness（= TrailCurrent）、ATRMultSL（边界中点或策略默认）、LockProfitPct（策略或 TP Profile 默认）、ConfirmCycles（= ConfirmCyclesBase）。用于 API/前端展示「调节前基线 vs 当前生效的 AI 调节」。

## 三、提示词详解

### 3.1 系统提示词（System Prompt）

**完整原文**（kernel/engine.go BuildSLTPOnlyPrompts）：

```text
You are a risk assistant. Output ONLY a JSON object inside <analysis></analysis>. No opening/closing decisions.
You will be given system strategy BOUNDS per position (atr_mult_sl range, lock_profit_pct range, confirm_cycles base). You MUST suggest values within these bounds only.
Rules for position_sl_tp_adjustments (one per position):
- choppy_hold: price choppy / ranging → loosen (trail_aggressiveness=low or confirm_cycles_delta=+1)
- trend_ride: trend intact → tighten (trail_aggressiveness=high)
- lock_profit: in profit → suggest lock_profit_pct within bounds (e.g. 2~3)
- trend_weakening: momentum fading → tighten or lower lock_profit_pct
- high_vol_hold: volatility spike but direction ok → confirm_cycles_delta=+1 or atr_mult_sl at upper bound
Current cycle market context (if provided) is real-time data for this cycle, possibly multi-line. It may include: BTC 1h/4h/24h/7d price change, MACD, RSI, dominance, Fear&Greed, AltcoinSeason, OI 1h/4h change, Funding, Long/Short ratio, Liquidation 1h/4h/24h (L/S USD), CGDI, CDRI, WhaleIndex, ETF flow, key levels. Use it to distinguish choppy vs trend vs high volatility and to choose the appropriate advice (choppy_hold / trend_ride / lock_profit / trend_weakening / high_vol_hold) per position.
When a position shows "current_applied (from previous AI)" with trail / atr_mult_sl / lock_profit_pct / last_advice, those are the parameters currently in effect (from your last adjustment). Use them to decide whether to keep or change; you may suggest the same or new values within bounds.
Output format: <analysis>{"position_sl_tp_adjustments":[{"symbol":"X","side":"long","advice":"choppy_hold","trail_aggressiveness":"low",...}]}</analysis>
```

**逐段说明**：

| 段落 | 作用 |
|------|------|
| 第 1 句 | 角色与输出形式：仅输出 `<analysis>` 内 JSON，不做开平仓决策 |
| 第 2 句 | 边界约束：每仓会给出 atr_mult_sl、lock_profit_pct、confirm_cycles 的边界，建议值必须在边界内 |
| Rules 5 条 | 5 种场景与参数建议的对应关系：choppy_hold→放宽/多确认；trend_ride→收紧；lock_profit→锁利比例 2~3；trend_weakening→收紧或降锁利；high_vol_hold→多确认或 atr_mult_sl 取上界 |
| Current cycle market context | 说明本周期市场上下文为实时、可能多行，列出可能包含的字段，并要求用其区分震荡/趋势/高波，为每仓选合适 advice |
| current_applied | 说明若某仓带有「current_applied (from previous AI)」及 trail/atr_mult_sl/lock_profit_pct/last_advice，表示当前正在使用的参数，可据此决定维持或微调，且仍须在边界内 |
| Output format | 约定 JSON 根键为 `position_sl_tp_adjustments`，每项含 symbol、side、advice、trail_aggressiveness 等 |

### 3.2 用户提示词（User Prompt）结构

用户提示由多行拼接而成（`userParts` 用 `\n` 连接）：

| 顺序 | 内容 | 代码逻辑 |
|------|------|----------|
| 第 1 行 | 固定说明 | `"Current positions (for SL/TP adjustment only). Suggest only within the given bounds:"` |
| 接下来每仓 1 行 | 仓位行 | 见下「仓位行格式」 |
| 再 1 行 | regime/scenario | `"Last regime=%s scenario=%s. Output only <analysis> with position_sl_tp_adjustments."` |
| 若 summary 非空 | 标题 + 多行市场上下文 | `"Current cycle market context (real-time, for choppy_hold / trend_ride / ...):"` + `currentCycleSummary`（多行） |

**仓位行格式**（每行一条仓位）：

- **基础信息**：`- {Symbol} {Side} entry={EntryPrice} mark={MarkPrice} pnl_pct={PnlPct} hold_mins={HoldMinutes} atr={ATR}`
- **可选 bounds**：若存在任意边界（ATRMultMin/Max、LockProfitPctMin/Max、ConfirmCyclesBase），则追加  
  `| bounds: atr_mult_sl [min, max], lock_profit_pct [min, max]%, confirm_cycles_base N`，若有 `TrailCurrent` 则加 `, trail_current=medium` 等，结尾 `(suggest within these bounds)`。
- **可选 current_applied**：若存在上一轮 AI 的任一生效参数，则追加  
  `| current_applied (from previous AI): trail=... atr_mult_sl=... lock_profit_pct=...% last_advice=...`

**示例（单仓）**：

```text
Current positions (for SL/TP adjustment only). Suggest only within the given bounds:
- BTCUSDT long entry=95000.0000 mark=95200.0000 pnl_pct=1.20 hold_mins=15 atr=1200.0000 | bounds: atr_mult_sl [1.20, 3.00], lock_profit_pct [1.0, 5.0]%, confirm_cycles_base 1, trail_current=medium (suggest within these bounds) | current_applied (from previous AI): trail=low atr_mult_sl=2.50 lock_profit_pct=2.0% last_advice=choppy_hold
Last regime=trend_up scenario=continuation. Output only <analysis> with position_sl_tp_adjustments.
Current cycle market context (real-time, for choppy_hold / trend_ride / lock_profit / trend_weakening / high_vol_hold):
BTC: 1h +0.50% 4h +1.20% 24h +2.00% 7d +3.50% | MACD 0.0012 RSI 58.00
BTC dominance 52.30%
Fear&Greed 65 Greed
...
```

### 3.3 市场上下文（currentCycleSummary）字段与来源

`FormatMarketContextForSLTP(ctx)` 按行输出的内容与数据来源对应关系：

| 行内容示例 | 数据来源（Context 字段） |
|------------|---------------------------|
| BTC: 1h %+ 4h %+ [24h 7d] \| MACD RSI | ctx.MarketDataMap["BTCUSDT"]：PriceChange1h/4h/24h/7d、CurrentMACD、CurrentRSI7 |
| BTC dominance %.2f%% | ctx.BTCDominancePct |
| Fear&Greed %d %s | ctx.FearGreedValue、FearGreedClassification |
| AltcoinSeason %d | ctx.AltcoinSeasonIndex |
| OI %s 1h %+ 4h %+ | ctx.CoinglassOISummaries（取首条，如 BTC） |
| Funding BTC %.4f%% | ctx.CoinglassFundingMap["BTC"] |
| L/S BTC 多% 空% 大户多% | ctx.CoinglassLongShortMap["BTC"]：LongAccount、ShortAccount、TopLongAccount |
| Liq 1h/4h/24h L/S USD | ctx.CoinglassLiquidation：Long1hUSD、Short1hUSD 等 |
| CGDI %.2f CDRI %.2f | ctx.CoinglassCGDI、CoinglassCDRI |
| WhaleIndex %.2f | ctx.CoinglassWhaleIndex |
| ETF flow BTC %.0f ETH %.0f | ctx.ETFFlowBTCRecent、ETFFlowETHRecent |
| Liq levels: ... | ctx.CoinglassLiquidationKeyLevels |

上述 ctx 在 `BuildLiveMarketSummaryForSLTP()` 中通过 `FetchMarketData("BTCUSDT")` 与 `FillCoinglassDataForSLTP(ctx)` 填充；无 Coinglass 或拉取失败时，回退到 `BuildCurrentCycleSummaryForSLTP(ctx)` 的单行摘要（BTC 1h/4h、Fear&Greed、AltcoinSeason、Liq 1h、CGDI/CDRI、Liq levels 等拼接成一行）。

## 四、执行层对调节结果的应用（小结）

| AI 输出字段 | 执行层使用位置 | 应用方式 |
|-------------|----------------|----------|
| TrailAggressiveness | checkDynamicStopLossTakeProfit → applyTrailAgg(effSL, adj.TrailAggressiveness) | 对 TrailingLevels 的 TrailingPercent 乘系数（high 0.8 / low 1.2 / medium 1.0） |
| ATRMultSL | 同上，写 effSL.ATRMultiplierMin/Max | 先裁剪到策略/Profile 的 [min,max]，再赋给 effSL，StopLossChecker 用其算止损距离 |
| LockProfitPct | 同上，写 effTP.LockProfitPercent | 裁剪到 [1, 5]，TakeProfitChecker 用其做锁利触发 |
| ConfirmCyclesDelta | 同上，止损确认周期计算 | requiredCycles = ConfirmCycles + ConfirmCyclesDelta，再限制在 [1,3]，与 trend_view、scenario 等一起决定需连续满足的周期数 |
| Advice | 不参与公式 | 仅写入 positionSLTPAdjustment，供下一轮 LastAdvice 与前端/日志展示 |

## 五、与主周期「分析」中 position_sl_tp_adjustments 的关系

主周期（runCycle）的 FullDecision 里若也包含 `position_sl_tp_adjustments`（主模型一次输出决策+调节），解析后同样会写 `positionSLTPAdjustment`（见 kernel 内 ParseAnalysisFromRawResponse 及调用处）。因此：

- **独立 SL/TP 周期**：仅调用 `RunSLTPOnlyAnalysis`，只产出 `position_sl_tp_adjustments`，不写主决策。
- **主周期**：若策略配置了主模型同时输出调节，则主周期也会更新同一批 `positionSLTPAdjustment`；与独立周期共用同一套「输入边界 + 当前生效参数」逻辑，执行层应用方式一致。
