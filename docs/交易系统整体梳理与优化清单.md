# 交易系统整体梳理与优化清单

本文档对 nofx 交易系统的**代码逻辑、交易策略、策略参数、提示词**做一次整体梳理，并标出需要优化或修改的项。

---

## 一、代码逻辑

### 1.1 主周期流程（trader/auto_trader.go）

| 环节 | 当前逻辑 | 状态 |
|------|----------|------|
| 构建上下文 | `buildTradingContext`：持仓、候选、行情、OI/NetFlow/Price 排行、币安多空/资金费率/Taker、数据补强（8h 资金费率、Basis、BTC 占比、强平聚合） | ✅ 已对齐 |
| 无候选时 | 仍执行 SL/TP 检查（无 trend_view），记录并跳过本周期 | ✅ 合理 |
| AI 决策 | `GetFullDecisionWithStrategy`：先跑 Pipeline 替换候选为 ToSubmitSymbols，再建提示词、调 AI、解析 | ✅ 已对齐 |
| 开仓来源 | **SystemExecutesEntry=false**：执行 AI 的 open_long/open_short；**true**：忽略 AI 开仓，用 `GetSystemEntryList(state, opts)` 系统开仓 | ✅ 逻辑正确 |
| SL/TP 顺序 | **先检查止盈、再检查止损**（同仓位内），避免「本可止盈却被追踪止损平仓」 | ✅ 已实现 |
| 系统开仓前 | Layer3 校验（信号年龄、待提交列表、OI 对齐、入场强度）、盈亏比校验 | ✅ 已实现 |

### 1.2 需优化/修改的代码逻辑

| 项 | 说明 | 建议 |
|----|------|------|
| **提示词中的 SL/TP 顺序描述** | `formatStrategyDynamicSLTP()` 仍写「先止损检查再止盈」，与实际执行顺序（先止盈再止损）相反 | **修改**：改为「先止盈检查再止损；止盈内为 分层→回撤→固定→ATR→阻力」 |
| **系统开仓 SL/TP 回退** | 系统开仓时若策略未设 InitialStopPercent，用 5%/6% 回退；若未对接 ATR/策略档位，可能与策略说明不一致 | 可选：系统开仓的 SL/TP 完全从策略首档分层+ATR 计算，避免硬编码 5%/6% |

## 二、交易策略

### 2.1 策略模式

| 模式 | 含义 | 开仓执行方 | 平仓执行方 |
|------|------|------------|------------|
| **classic** | 经典模式 | AI 建议 → 系统执行 | 策略 SL/TP（AI 不输出 close） |
| **multilayer_filter** | 多层过滤 | 若 SystemExecutesEntry=true → 系统按方向池开仓；否则仍按 AI 建议执行 | 策略 SL/TP |

### 2.2 与设计文档的一致性

- **「AI 仅作辅助」**：需同时满足 `strategy_mode=multilayer_filter` 且 **SystemExecutesEntry=true**。当前**默认策略与优化策略均未将 SystemExecutesEntry 设为 true**，因此默认仍是「AI 建议开仓、系统执行」。
- 若希望产品层面推荐「系统执行开仓」，可在**优化策略预设**中显式设置 `SystemExecutesEntry: true`，并在文案中说明与「AI 仅开仓」的区别。

### 2.3 需优化/修改的策略设计

| 项 | 说明 | 建议 |
|----|------|------|
| **预设与「AI 仅辅助」一致** | 默认/优化预设中 SystemExecutesEntry 均为 false | **可选**：在「优化策略」预设中设置 `SystemExecutesEntry: true`，与《系统详细架构》中「开平仓由系统规则执行」的描述一致 |
| **策略描述文案** | 默认策略描述为「AI 仅开仓」；若用户启用系统执行开仓，易与「仅开仓」混淆 | 在策略编辑页或说明中区分「AI 建议开仓」与「系统规则开仓」两种模式 |

## 五、汇总：必须修改 vs 建议优化

### 必须修改（与当前实现不一致）

1. **formatStrategyDynamicSLTP**  
   - 将「先止损检查再止盈」改为「**先止盈检查再止损**」；  
   - 止盈内部顺序保持：分层→回撤→固定→ATR→阻力。

### 建议优化（一致性 / 体验 / 文档）

1. **预设与「AI 仅辅助」一致**：在优化策略预设中设置 `SystemExecutesEntry: true`（可选）。  
2. **英文优化策略**：为 en 增加与 zh 对应的 PromptSections/CustomPrompt，或文档说明仅中文有增强。  
3. **默认策略方向池**：为默认策略增加 DirectionPool 默认配置（与优化策略一致），便于行为一致。  
4. **系统开仓 SL/TP**：系统开仓时 SL/TP 尽量从策略首档+ATR 计算，减少 5%/6% 硬编码（可选）。

## 六、已确认无需改动的部分

- Pipeline 与 GetSystemEntryList 逻辑、Layer1/2/3 与方向池、数据补强与多空雷达的集成。
- 先 TP 后 SL 的检查顺序（代码已正确）、TrailingStopOnlyAfterFirstScaledTP、AdverseExitWhenNeverProfitATR 默认 1.5。
- SystemExecutesEntry 为 true 时，Hard Constraints 与 User Prompt 中均正确约束「勿输出 open_long/open_short」及 <analysis> 可选块。
- 多周期下 IntradaySeries 已正确赋值，volume_ok/volume_trend 在多周期策略下有效。
