# AI「历史 + 实时 + 预测」所需数据与当前支持情况

## 一、AI 要做到「历史 + 实时 + 预测」需要哪些数据

### 1. 历史（用于理解过去走势、结构、情绪演变）

| 数据类型 | 用途 | 当前是否获取 | 说明 |
|----------|------|--------------|------|
| **多周期 K 线序列** | 价格/量能历史、趋势与结构 | ✅ 有 | 15m/1h/4h 等，每周期取最近 N 根（由 PrimaryCount 配置，默认 30，优化预设 100） |
| **K 线衍生序列** | EMA、MACD、RSI、量能随时间变化 | ✅ 有 | 各周期 TimeframeData 内含 EMA20/50、MACD、RSI7/14、Volume、ATR14 等 |
| **1h/4h 涨跌幅** | 近期多空强度摘要 | ✅ 有 | PriceChange1h、PriceChange4h（由主周期 K 线推算） |
| **OI 历史** | 持仓随时间变化、大户行为 | ❌ 无 | 仅有当前 OI（Latest/Average），无按时间序列的 OI 历史 |
| **资金费率历史** | 多空成本与情绪演变 | ⚠️ 部分 | 当前费率 + 近 8h 均值（Binance）；无更长时段序列 |
| **多空比历史** | 散户/大户情绪演变 | ❌ 无 | 仅当前快照（全账户+大户），无历史序列 |
| **净流入/涨跌榜历史** | 资金流向与热度演变 | ❌ 无 | 仅当前排名快照，无历史排名或流向序列 |
| **强平历史** | 爆仓潮与波动阶段 | ⚠️ 部分 | 近 1h/4h 聚合（币安 WS 或 CoinAnk）；无更早时段序列 |
| **更长周期摘要** | 日/周级趋势 | ⚠️ 依赖 K 线 | 4h 周期若 count 较大（如 100 根）≈ 16 天；无单独 24h/7d 统计字段 |

### 2. 实时（用于当下状态与规则过滤）

| 数据类型 | 用途 | 当前是否获取 | 说明 |
|----------|------|--------------|------|
| **当前价、最新 K 线** | 即时价格与当根 K 状态 | ✅ 有 | CurrentPrice、各周期最后一根 K 线 |
| **当前指标** | EMA20、MACD、RSI7 等 | ✅ 有 | 由主周期 K 线计算 |
| **当前 OI** | 持仓规模 | ✅ 有 | OpenInterest.Latest / Average |
| **当前资金费率** | 多空成本 | ✅ 有 | BinanceFundingMap、BinanceFundingRateAvg8h |
| **当前多空比** | 全账户/大户多空 | ✅ 有 | BinanceLongShortMap |
| **当前 Taker 买卖比** | 主动买卖力量 | ✅ 有 | BinanceTakerMap |
| **OI/净流入/涨跌榜** | 排名与流向 | ✅ 有 | OIRankingData、NetFlowRankingData、PriceRankingData |
| **永续-现货 Basis** | 期现价差 | ✅ 有（可选） | BasisMap |
| **BTC 占比** | 大盘结构 | ✅ 有（可选） | BTCDominancePct |
| **近 1h/4h 强平聚合** | 近期爆仓规模 | ✅ 有（可选） | LiquidationAgg |

### 3. 预测（AI 输出，非「数据」）

预测（near_term_outlook、scenario、key_levels、方向建议等）由 AI 基于**历史 + 实时**推断，不需要「未来数据」。  
要提升预测质量，需要给 AI 的输入尽量覆盖：**足够长的历史 + 完整的实时 + 明确的任务与格式约束**。

## 二、当前数据获取能力小结

- **已能支持「历史」的**  
  - 多周期 K 线及衍生序列（长度由 PrimaryCount 决定，默认 30，可配 100）：  
    - 15m×30 ≈ 7.5 小时、1h×30 ≈ 30 小时、4h×30 ≈ 5 天（4h×100 ≈ 16 天）。  
  - 1h/4h 涨跌摘要、资金费 8h 均值、强平 1h/4h 聚合。  

- **已能支持「实时」的**  
  - 行情、指标、OI、资金费、多空比、Taker、排行、Basis、BTC 占比、强平聚合等（见上表），均可作为「当下状态」输入 AI。  

- **目前不支持或仅部分支持的「历史」**  
  - OI 时间序列、资金费率时间序列、多空比时间序列、净流入/涨跌榜历史、更长周期（如 24h/7d）的独立统计。  

因此：  
- **实时**：当前数据获取**可以支持** AI 做实时分析。  
- **历史**：**部分支持**——K 线及衍生序列已有一定历史深度；OI/资金费/多空比/排行等**没有历史序列**，只有当前或短时聚合。  
- **预测**：无额外「未来数据」需求，依赖历史+实时输入与提示词设计；**在现有数据下可做预测**，但若补充上述历史序列，预测会更有依据。

## 三、若要更好支持「历史 + 实时 + 预测」可做的增强

1. **拉长 K 线可见历史（零/低成本）**  
   - 策略里将 `PrimaryCount` 提高（如 4h 用 100 根），或为「AI 专用」请求多取一段 bars（例如 4h 再取 50 根只给 AI 做上下文），这样 AI 看到的 4h 历史更长。  
   - 当前 CoinAnk 已拉 200 根，仅用其中 `count` 根；若配置 count 加大，或对部分 timeframe 传更大 count，即可在不改接口前提下增强历史。

2. **增加 24h/7d 级摘要（若接口有）**  
   - 若数据源提供 24h/7d 涨跌幅或成交量，可写入 Context 并加入 prompt，作为「更长历史」的简短摘要，供 AI 做趋势与预测。

3. **OI/资金费/多空比历史（需接口或存储支持）**  
   - 若交易所或第三方提供历史 OI、历史资金费率、历史多空比（按 1h/4h 等），可定期拉取并缓存，在构建 AI 上下文时附带「最近 24h/几天」的序列或摘要，供 AI 判断情绪与结构演变。  
   - 当前未实现，属于「有则能更好支持历史与预测」的增强项。

4. **强平历史**  
   - 已有 1h/4h 聚合；若需更长时间维度，需数据源支持或自建聚合存储。

## 四、已实现项（2025 更新，K 线根数保持 30、控制 token）

1. **24h/7d 摘要**  
   - `market.Data` 增加 `PriceChange24h`、`PriceChange7d`，在 `GetWithTimeframes` 内用已有 200 根 K 线（优先 4h，其次 1h）计算，**不增加 K 线根数**，仅多两个数字。  
   - Prompt 中在多周期涨跌行追加 `| 24h %+.2f%% 7d %+.2f%%`，预测参考摘要中 BTC 同样追加 24h/7d。

2. **资金费近 8 期**  
   - Context 增加 `FundingRateHistoryLast8 map[string][]float64`，在拉取资金费历史（`EnableBinanceFundingRateHistory`）时顺带写入近 8 期。  
   - 在「数据补强」段落输出一行紧凑的「资金费近 8 期（由旧到新）」供 AI 看趋势，不增 K 线 token。

3. **强平 24h**  
   - `LiquidationAggSnapshot` 增加 `Long24hUSD`、`Short24hUSD`。  
   - 币安 WS 强平聚合在 `aggregateForceOrderLocked` 中按 24h 窗口累加，Prompt 中在 1h/4h 后追加 `| 24h 多/空`（有数据时）。

4. **OI 历史**  
   - 未实现：若需可后续接 Binance `/futures/data/openInterestHist`，在 Context 中加简短摘要（如 24h 变化）再写入 prompt。

---

## 五、结论

- **历史**：当前主要依赖**多周期 K 线 + 衍生指标**，已有一定历史深度；已增加 **24h/7d 涨跌、资金费近 8 期、强平 24h**，**不增加 K 线根数**（默认 30 不变），仅增加少量 token。**OI/多空比/排行的历史序列**仍未获取。  
- **实时**：当前数据获取**可以支持** AI 做实时分析。  
- **预测**：在现有「历史+实时」基础上即可做预测；上述增强（24h/7d、资金费 8 期、强平 24h）已实现，OI 历史可后续按需接 Binance openInterestHist。
