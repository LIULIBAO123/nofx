# 过滤机制 16 项条件分析与优先级

本文档对 Layer1 的 16 项条件逐项分析：**是否合理**、**是否重复**、**数据依赖**，并给出**必须满足 / 强烈建议 / 可选**的优先级划分，作为「有依据放宽」的配置基础。

---

## 一、16 项条件逐项分析

| # | 条件 ID | 当前逻辑 | 数据依赖 | 合理性 | 重复/备注 |
|---|---------|----------|----------|--------|-----------|
| 1 | **entry_timing** | Layer1 恒为 true；实际在 Layer3 用信号年龄校验 | 无（L1 不判） | 合理（L1 占位） | 与 Layer3 信号年龄重复，L1 可视为占位 |
| 2 | **volume_ok** | 最新量能 ≥ 近期均量×0.5 | K 线量能 | ✅ 合理 | 见下 volume_trend |
| 3 | **oi_ok** | OI.Latest > 0 | 持仓量 | ✅ 合理 | 合约标的无 OI 不应开仓，**必须** |
| 4 | **long_tf_aligned** | 4h 与 1h 涨跌同号 | 4h/1h 涨跌幅 | ✅ 合理 | 多周期趋势一致，**核心** |
| 5 | **flow_aligned** | 机构流向榜与 1h 方向一致；不在榜则通过 | NetFlow 排行 | ✅ 合理 | 依赖外部数据；不在榜时当前为通过 |
| 6 | **price_ranking_aligned** | 涨跌榜与 1h 方向一致；不在榜则通过 | PriceRanking | ✅ 合理 | 与 market_direction_aligned **逻辑完全相同** |
| 7 | **reliability_min** | Layer2 可靠度 ≥ Value（如 0.4） | Layer2 计算 | ⚠️ 重叠 | 与 Layer2 的 ReliabilityThreshold 重复，属「提前门槛」 |
| 8 | **short_tf_aligned** | 价格 vs EMA20 与 1h 同向 | 价格、EMA20、1h | ✅ 合理 | 短周期结构对齐，**重要** |
| 9 | **whale_direction_aligned** | 大户 OI 榜与 1h 同向；不在榜则通过 | OI 排行 | ✅ 合理 | 依赖排行；不在榜通过 |
| 10 | **market_direction_aligned** | 涨跌榜与 1h 同向；不在榜则通过 | PriceRanking | ⚠️ 重复 | **与 price_ranking_aligned 实现完全一致**，可合并 |
| 11 | **trend_strength** | \|4h 涨跌\|≥0.2% 或 有价有 EMA | 4h、价格、EMA | ⚠️ 偏弱 | 第二分支几乎恒成立，实际多为「4h 有波动」 |
| 12 | **rsi_zone** | RSI 在 28~72 | RSI | ✅ 合理 | 避免极端超买超卖，**建议保留** |
| 13 | **macd_signal** | MACD 与 1h 同号 | MACD、1h | ✅ 合理 | 动量与方向一致 |
| 14 | **volume_trend** | 最新量能 ≥ 均量×0.5 | 同 volume_ok | ⚠️ 重复 | **与 volume_ok 逻辑相同**，可二选一 |
| 15 | **oi_trend** | OI.Latest > 0 | 同 oi_ok | ⚠️ 重复 | **与 oi_ok 完全相同** |
| 16 | **funding_ok** | \|资金费率\| < 0.01 | 资金费率 | ✅ 合理 | 避免极端费率成本，**必须** |

## 二、重复与冗余归纳

- **完全重复（可只保留其一）**  
  - **market_direction_aligned** 与 **price_ranking_aligned**：同一套 PriceRanking + 1h 方向，保留一项即可。  
  - **volume_trend** 与 **volume_ok**：均为「最新量 ≥ 均量×0.5」，保留一项即可。  
  - **oi_trend** 与 **oi_ok**：均为 OI.Latest > 0，保留一项即可。

- **与其它层重叠**  
  - **reliability_min**：与 Layer2 的 ReliabilityThreshold 含义重叠，Layer2 已做可靠度门槛时，Layer1 再设易重复过滤。  
  - **entry_timing**：在 Layer1 不判，实际在 Layer3 用信号年龄判，L1 仅占位。

- **结论**：16 项中去掉重复与占位后，**实质独立条件约 11～12 项**；若保留「至少 N 项通过」的放宽方式，应按「独立条件」计数或对重复项只计一次。

## 三、优先级划分（哪些必须满足）

### 3.1 必须满足（Tier1）—— 数据与成本底线

开仓前**必须**满足，否则不应进入候选（无数据、无结构、成本极端）：

| 条件 | 理由 |
|------|------|
| **oi_ok** | 合约标的无持仓量数据不宜开仓。 |
| **funding_ok** | \|费率\|过大时持仓成本高，易被收割，应直接排除。 |
| **long_tf_aligned** | 4h 与 1h 方向相反时，趋势不清晰，开仓方向依据弱。 |

建议：**Tier1 在任意放宽方案下都保持「必须全部通过」**，即这三项不参与「至少 N 项」的放宽，未过则直接淘汰。

### 3.2 强烈建议（Tier2）—— 结构一致性

与「多周期/结构/流动性」强相关，建议默认开启；放宽时仍建议优先保留：

| 条件 | 理由 |
|------|------|
| **short_tf_aligned** | 价格 vs EMA20 与 1h 同向，短周期结构支持方向。 |
| **volume_ok** | 量能不低于近期均量一半，避免无量假突破。 |
| **rsi_zone** | RSI 不在极端区，减少追顶杀底。 |
| **macd_signal** | MACD 与 1h 同向，动量与方向一致。 |

放宽策略：可纳入「至少 N 项」中的高权重项，或要求「Tier2 中至少通过 3 项」等。

### 3.3 可选/加分（Tier3）—— 排行与情绪

依赖外部排行或与 Tier1/2 有重叠，可作为加分项而非硬性必须：

| 条件 | 理由 |
|------|------|
| **flow_aligned** | 机构流向与 1h 同向；不在榜即通过，信息不完整时不宜作硬门槛。 |
| **price_ranking_aligned** | 涨跌榜与 1h 同向；与 market_direction 二选一即可。 |
| **whale_direction_aligned** | 大户 OI 与 1h 同向；不在榜即通过。 |
| **trend_strength** | 当前实现偏弱，多为「4h 有波动」；可保留作软性过滤。 |
| **reliability_min** | 与 Layer2 可靠度重叠，可仅在 Layer2 统一卡一道。 |
| **entry_timing** | L1 不判，仅占位；实际由 Layer3 判。 |
| **market_direction_aligned** | 与 price_ranking_aligned 重复，建议关闭其一。 |
| **volume_trend** | 与 volume_ok 重复，建议关闭其一。 |
| **oi_trend** | 与 oi_ok 重复，建议关闭其一。 |

## 四、推荐配置思路

### 4.1 分层规则（有依据放宽）

- **必过层（不可放宽）**  
  - 仅 **oi_ok**、**funding_ok**、**long_tf_aligned** 三项。  
  - 任一不通过 → 该币不进入后续 Layer1 计数与 Layer2。

- **Layer1 其余项（可做「至少 N 项通过」）**  
  - 去掉重复后，按「独立条件」计：例如保留 volume_ok（不保留 volume_trend）、oi_ok（不保留 oi_trend）、price_ranking_aligned（不保留 market_direction_aligned），再算上 short_tf_aligned、flow_aligned、whale_direction_aligned、trend_strength、rsi_zone、macd_signal、reliability_min、entry_timing 等。  
  - 建议：**至少通过 6～8 项**（在独立项约 11 项的前提下），既放宽又保留一定质量。

### 4.2 去重与精简（可选）

- 在策略配置中**默认关闭**以下一项以去重（保留另一项即可）：  
  - market_direction_aligned（保留 price_ranking_aligned）；  
  - volume_trend（保留 volume_ok）；  
  - oi_trend（保留 oi_ok）。  
- 这样「16 项」中有效独立项减少，**MinItemsToPass** 的 N 更容易解释（例如「在 12 个有效项中至少过 8 项」）。

### 4.3 优先级在配置中的体现（后续可实现）

- **Tier1**：在代码中单独校验，不通过不进入「至少 N 项」计数。  
- **Tier2 / Tier3**：参与「至少 N 项」计数；或为 Tier2 设「至少过 M 项」子要求。  
- 前端可展示「必过 3 项 + 其余至少 N 项」，便于理解与调参。

## 五、小结

| 类型 | 条件 | 建议 |
|------|------|------|
| **必须满足（Tier1）** | oi_ok, funding_ok, long_tf_aligned | 不参与放宽，未过即淘汰 |
| **强烈建议（Tier2）** | short_tf_aligned, volume_ok, rsi_zone, macd_signal | 默认开启，参与「至少 N 项」 |
| **可选/重复（Tier3）** | flow_aligned, price_ranking_aligned, whale_direction_aligned, trend_strength, reliability_min, entry_timing | 可选或与其它项合并 |
| **建议关闭其一** | market_direction_aligned（与 price_ranking 重复）, volume_trend（与 volume_ok 重复）, oi_trend（与 oi_ok 重复） | 减少重复、便于解释 N 项 |

在此基础上再做「过滤机制放宽」时，建议：  
1）先固定 **Tier1 三项必过**；  
2）其余独立项用 **「至少 N 项通过」**（如 6～8）；  
3）配置上去重（三对重复项各保留一项），使 N 有明确含义。
