# nofx 交易系统详细架构

本文档从**技术视角**描述 nofx 的模块划分、数据流、核心类型与运行时结构，与《nofx交易系统完整架构》中的业务链路互为补充。

---

## 一、架构概览与设计原则

- **定位**：实盘/模拟盘量化交易系统，支持多交易所、多策略、AI 辅助分析与系统规则执行。
- **核心原则**：AI 仅作辅助（趋势视图、市场摘要、regime、risk_alert）；开平仓由**系统规则**（多层过滤、方向池、止盈止损）执行。
- **运行形态**：单进程；内嵌 HTTP API、TraderManager 驱动多交易员周期循环、可选回测与网格等扩展。

**模块职责简述**：

| 模块 | 职责 |
|------|------|
| **api** | HTTP 接口、策略/交易员/回测/雷达的 CRUD 与查询、决策预览、静态资源与前端代理。 |
| **kernel** | 策略引擎（提示词、Context、数据拉取编排）、多层过滤与方向池（pipeline）、系统开仓列表（GetSystemEntryList）、决策解析（含 trend_view、analysis）。 |
| **market** | 多源 K 线、单标的 OI/资金费率、Get/GetWithTimeframes；供 kernel 与止盈止损使用。 |
| **store** | 策略/交易员/交易所/持仓/订单/决策/回测等持久化；StrategyConfig 为策略唯一结构定义。 |
| **trader** | 实盘/模拟盘适配器、AutoTrader 周期逻辑、buildTradingContext、执行开平仓与止盈止损。 |
| **manager** | 从 store 加载交易员、按配置创建 AutoTrader 与 Trader 实现、启停 runCycle。 |
| **provider** | 外部数据（NofxOS、币安、CoinGecko、CoinAnk 等）的 HTTP/WS 客户端。 |
| **mcp** | AI 调用统一接口，多后端（DeepSeek、OpenAI 等）。 |
| **backtest** | 历史 K 线回放、模拟账户、调用 kernel 同款决策与 SL/TP 逻辑。 |

## 三、运行时架构

```
                    ┌─────────────────────────────────────────────────────────┐
                    │                      main.go                              │
                    │  config · crypto · store · TraderManager · API · signal  │
                    └───────────────────────────┬─────────────────────────────┘
                                                │
        ┌───────────────────────────────────────┼───────────────────────────────────────┐
        │                                       │                                       │
        ▼                                       ▼                                       ▼
┌───────────────┐                    ┌──────────────────────┐                ┌─────────────────┐
│  api.Server   │                    │ manager.TraderManager│                │ backtest.Manager│
│  Gin HTTP     │◄──────────────────►│ LoadTradersFromStore│                │ RestoreRuns     │
│  策略/交易员   │                    │ Start/Stop trader    │                │ Run/Progress    │
│  回测/雷达    │                    │ 按 DB 配置建         │                │ 共享 MCP client │
│  前端静态     │                    │ AutoTrader+Trader    │                └─────────────────┘
└───────┬───────┘                    └──────────┬───────────┘
        │                                       │
        │ 读写策略、交易员、订单、决策            │ 每 trader 一个 goroutine
        ▼                                       ▼
┌───────────────┐                    ┌──────────────────────┐
│  store.Store  │                    │ trader.AutoTrader    │
│  SQLite/PG    │◄──────────────────│ runCycle() 定时       │
│  策略·交易员   │                    │  buildTradingContext │
│  持仓·决策    │                    │  GetFullDecisionWith  │
└───────────────┘                    │  Strategy → 执行开平仓 │
                                    │  checkDynamicStopLoss │
                                    │  TakeProfit           │
                                    └──────────┬───────────┘
                                               │
                                    ┌──────────▼───────────┐
                                    │ kernel.StrategyEngine │
                                    │ pipeline.RunPipeline  │
                                    │ GetFullDecisionWith   │
                                    │ Strategy              │
                                    └──────────┬───────────┘
                                               │
                                    ┌──────────▼───────────┐
                                    │ market · provider     │
                                    │ mcp.AIClient          │
                                    └──────────────────────┘
```

- **主进程**：初始化配置、DB、加密、TraderManager、BacktestManager、API Server；阻塞于信号，退出时 `TraderManager.StopAll()`。
- **API**：同步处理 HTTP；策略/交易员/回测/雷达等均通过 store 与 TraderManager 读写或驱动。
- **交易员**：由 TraderManager 为每个启用的交易员启动一个 goroutine，循环执行 `AutoTrader.runCycle()`（扫描间隔可配）。
- **回测**：独立请求触发，使用同一套 kernel 决策与 SL/TP 逻辑，数据来自历史 K 线。

## 四、核心数据结构

### 4.1 kernel.Context

单周期内**所有输入数据的容器**，由 `buildTradingContext` 与 kernel 内拉取逻辑共同填充，供 pipeline、提示词、解析使用。

| 字段类别 | 主要字段 | 说明 |
|----------|----------|------|
| 时间与运行 | CurrentTime, CallCount, RuntimeMinutes | 周期序号与运行时长 |
| 账户 | Account (TotalEquity, AvailableBalance, MarginUsedPct, PositionCount…) | 权益、仓位占比等 |
| 持仓与候选 | Positions, CandidateCoins | 当前持仓、本周期候选币（pipeline 可能替换为 ToSubmitSymbols） |
| 行情 | MarketDataMap[symbol]*market.Data | 多周期 K 线、EMA/MACD/RSI/ATR、OI、FundingRate |
| 量化与排行 | QuantDataMap, OIRankingData, NetFlowRankingData, PriceRankingData | NofxOS 单币量化与市场排行 |
| 币安衍生 | BinanceLongShortMap, BinanceFundingMap, BinanceTakerMap | 多空比、资金费率、Taker |
| 数据补强 | BinanceFundingRateAvg8h, BasisMap, BTCDominancePct, LiquidationAgg | 8h 费率均值、Basis、BTC 占比、强平聚合 |
| 其他 | RecentOrders, TradingStats, StrategyTriggeredCloses, BTCETHLeverage, AltcoinLeverage | 近期成交、统计、本周期策略平仓、杠杆配置 |

### 4.2 kernel.PipelineState

多层过滤与方向池的**输出状态**，供 API（雷达/状态页）与系统开仓使用。

| 字段 | 说明 |
|------|------|
| ToSubmitSymbols | 通过 Layer1/2/3 及方向过滤后的标的列表，可替代 Context.CandidateCoins |
| DirectionLong / DirectionShort | 每标的带分数（如 StrengthPct）的多/空池 |
| Layer1Pass/Layer2Pass 等 | 各层通过数量与失败统计（可选，便于排查） |

### 4.3 store.StrategyConfig

策略的**唯一配置结构**，存于 `strategies.config` JSON 中。

| 顶层/子结构 | 说明 |
|-------------|------|
| StrategyType | ai_trading / grid_trading |
| StrategyMode | classic / multilayer_filter |
| CoinSource | StaticCoins, UseAI500, UseOITop 等 |
| Indicators | Klines, EnableQuantData, OI/NetFlow/Price 排行、币安衍生、数据补强、ExternalDataSources、NofxOSAPIKey 等 |
| RiskControl | MaxPositions, 杠杆, SystemExecutesEntry, AIOnlyEntry, 动态止盈止损相关 |
| MultilayerFilter | Layer1/2/3 配置、DirectionPoolMode |
| RealtimePriceConfig | 止盈止损前是否拉实时价 |
| PromptSections, CustomPrompt | 提示词可编辑片段与自定义追加 |

### 4.4 kernel.FullDecision

单次 AI 决策的**完整输出**（含解析后的辅助字段）。

| 字段 | 说明 |
|------|------|
| Decisions | 每标的/持仓的 action（open_long/open_short/close_long/close_short/hold/wait）、杠杆、仓位、止损止盈等 |
| TrendView | posKey → trend_intact/choppy/reversing，供止盈止损确认周期调节 |
| MarketSummary, MarketRegime, RiskAlert | 可选 `<analysis>` 解析结果；RiskAlert 为 true 时本周期不系统开仓 |
| SystemPrompt, UserPrompt, RawResponse | 用于存档与调试 |

### 4.5 kernel.SystemEntry 与 GetSystemEntryList

- **SystemEntry**：`Symbol` + `Action`（open_long / open_short），表示系统规则给出的单笔开仓建议。
- **GetSystemEntryList(state, opts)**：由 `PipelineState` 的 ToSubmitSymbols、DirectionLong/Short 及 AllowLong/AllowShort 得出本周期应执行的开仓列表（每标的至多一个方向，同标的多空取分数高者）。

## 五、端到端数据流（单周期）

```
1. runCycle() 开始
       │
       ▼
2. buildTradingContext()
   · GetBalance / GetPositions（交易所或 Paper）
   · GetCandidateCoins()（静态/AI500/OI 排行）
   · 近期平仓、交易统计（store）
   · QuantData / OI / NetFlow / Price 排行（NofxOS，按策略开关）
   · 币安衍生（多空比、资金费率、Taker）
   · 数据补强（资金费率 8h、Basis、BTC 占比、WS 强平；可选 CoinAnk 清算）
       │
       ▼
3. GetFullDecisionWithStrategy(ctx, mcpClient, engine, …, opts)
   │
   ├─ 3.1 fetchMarketDataWithStrategy(ctx, engine)
   │      · 按策略 Klines 为持仓+候选拉 K 线 → MarketDataMap
   │
   ├─ 3.2 若 strategy_mode=multilayer_filter：
   │      RunPipeline(ctx, config, traderID, opts)
   │      · Layer1 → Layer2 → Layer3 → 方向过滤
   │      · 输出 state；ctx.CandidateCoins ← state.ToSubmitSymbols
   │
   ├─ 3.3 BuildSystemPrompt / BuildUserPrompt(ctx)
   │      · 使用 MarketDataMap、Quant、OI/NetFlow/Price、币安衍生、数据补强等
   │
   ├─ 3.4 callAIWithCaching(mcpClient, systemPrompt, userPrompt, runID)
   │
   └─ 3.5 parseFullDecisionResponse(…)
          · Decisions、TrendView、MarketSummary、MarketRegime、RiskAlert
       │
       ▼
4. 执行层（auto_trader）
   · 若 SystemExecutesEntry：忽略 AI 的 open_long/open_short
   · 若 RiskAlert：本周期不执行系统开仓
   · 否则：GetSystemEntryList(state, opts) → 对每项 executeOpenLong/ShortWithRecord（策略默认参数）
   · 对已有持仓：checkDynamicStopLossTakeProfit(trendViewByPosKey)
       │
       ▼
5. 策略触发的平仓写入 StrategyTriggeredCloses，供下一周期 AI 上下文
```

## 六、外部依赖与数据源

| 依赖类型 | 说明 |
|----------|------|
| **交易所** | Binance / Bybit / OKX / Bitget / Gate / Hyperliquid / Lighter / Aster / KuCoin 等，通过 trader 子包适配；余额、持仓、下单、平仓。 |
| **行情与指标** | CoinAnk 免费 K 线（按交易所/资产）；Hyperliquid（xyz 或交易所=hyperliquid）；Binance fapi（OI、premiumIndex）。 |
| **量化与排行** | NofxOS（AI500、OI/NetFlow/Price 排行、单币量化），需 NofxOSAPIKey。 |
| **币安衍生与补强** | Binance fapi 公开（多空比、资金费率、Taker、fundingRate 历史）、现货价；CoinGecko（BTC 占比）；币安 WS `!forceOrder@arr` 强平聚合。 |
| **AI** | MCP 抽象，后端可为 DeepSeek、OpenAI 等；提示词与解析在 kernel 内。 |
| **持久化** | SQLite 或 PostgreSQL，通过 store 访问。 |
| **前端** | 静态资源与 API 由 api 提供；策略/交易员/雷达等配置通过 API 读写 store。 |

## 七、策略模式与执行模式

| 维度 | 选项 | 说明 |
|------|------|------|
| **StrategyType** | ai_trading | 默认；周期内 buildContext → 拉 K 线 → pipeline（若启用）→ AI 决策 → 系统开仓/止盈止损。 |
| | grid_trading | 网格逻辑；由 auto_trader_grid 与 kernel.GridEngine 处理。 |
| **StrategyMode** | classic | 不做多层过滤；CandidateCoins 直接进 AI。 |
| | multilayer_filter | 跑 RunPipeline；CandidateCoins 被替换为 ToSubmitSymbols。 |
| **开仓执行** | SystemExecutesEntry=true | 开仓仅来自 GetSystemEntryList；AI 不输出 open_long/open_short。 |
| | AIOnlyEntry 等 | AI 可输出开仓，系统执行；平仓仍由止盈止损等规则执行。 |

## 八、部署与运行

- **单机单进程**：一个 nofx 进程内嵌 API 与所有交易员循环；无独立队列或消息总线。
- **配置**：.env 提供 DB、JWT、API 端口等；策略与交易员配置存 DB，通过 API 或迁移脚本写入。
- **扩展**：多交易员由 TraderManager 并发 runCycle；回测共享同一 kernel 与 MCP 客户端，数据来自 backtest 数据源。
