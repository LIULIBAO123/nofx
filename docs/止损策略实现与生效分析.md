# 止损策略实现与生效分析

本文档从执行顺序、数据来源、各类型触发条件与组合逻辑，说明当前止损策略的**整体实现效果**。

---

## 一、执行入口与前置条件

- **入口**：每周期 `runCycle` 内先执行 `checkDynamicStopLossTakeProfit()`，再拉行情、调 AI、执行开仓。
- **仓位来源**：`at.trader.GetPositions()`（实盘/模拟一致）。
- **前置**：
  1. **最小持仓时间**：`MinHoldMinutes` 内不参与任何动态止损/止盈；未满则本周期直接跳过该仓位，避免「开仓即平仓」。取止损与止盈配置中的较大值作为统一 min hold。
  2. **锁定利润后的盈亏平衡**：若策略配置了 `LockProfitPercent` 且当前浮盈已达该比例，则先检查「是否已回撤到入场价」：多单当前价 ≤ 入场价、空单当前价 ≥ 入场价 时，直接按**盈亏平衡止损**（breakeven）平仓，不再走下面五类止损。若未回撤到入场价，再走正常止损检查；且若某条止损触发，止损价会被限制在「不劣于入场价」（多不低于、空不高于）。

满足最小持仓且未触发 breakeven 止损时，才进入下面的**五类止损检查**。

---

## 二、五类止损的检查顺序与触发条件

在 `kernel/stop_loss.go` 的 `CheckStopLoss` 中，按**固定顺序**依次检查，每种条件满足则把对应 signal 加入列表，最后按「触发逻辑」决定是否真正触发。

| 顺序 | 类型 | 配置开关 | 触发条件（简要） | 说明 |
|------|------|----------|------------------|------|
| 1 | **初始固定止损** | `InitialStopPercent > 0` | 多：当前价 ≤ 入场价×(1−百分比)；空：当前价 ≥ 入场价×(1+百分比) | 按入场价固定比例，触及即满足；默认 0 表示不用 |
| 2 | **追踪止损（分层）** | `TrailingEnabled == true` 且 `TrailingLevels` 非空 | 先「曾有过浮盈」：多用入场后最高价、空用入场后最低价算峰值盈利%；再看是否从峰值回撤超过该档 `TrailingPercent` | **只有曾浮盈过才会触发**；从未浮盈则本项永远不触发 |
| 3 | **ATR 止损** | `ATREnabled == true` 且 `atr > 0` | 多：当前价 ≤ 入场价 − 倍数×ATR；空：当前价 ≥ 入场价 + 倍数×ATR。倍数：默认 (Min+Max)/2；高波动（当前 ATR > 长期 ATR×阈值）时用 Max，更宽 | 使用 15m K 线算 ATR(14)；高波动时更宽容 |
| 4 | **支撑/阻力止损** | `SupportResistanceEnabled == true` 且传入的 supportLevel > 0 | 多：当前价 ≤ 支撑×(1−缓冲%)；空：当前价 ≥ 阻力×(1+缓冲%) | 多单传支撑、空单传阻力；支撑/阻力由 15m 近期 K 线局部极值得到 |
| 5 | **从未浮盈+反向过大早退** | `AdverseExitWhenNeverProfitATR > 0` 且 `atr > 0` | 先判「从未浮盈」：多=入场后最高价≤入场价，空=入场后最低价≥入场价；再判反向距离：多=入场价−当前价，空=当前价−入场价；若 反向距离 ≥ 配置倍数×ATR 则触发 | 仅对「一路反向、从未绿过」的仓位多一条早退，不收紧正常 ATR 线 |

- **数据来源**：  
  - 价格：当前用 `markPrice`（盘口/标记价）。  
  - 入场后最高/最低：用 15m K 线中 `OpenTime >= 入场时间` 的 K 线的 High/Low 计算。  
  - ATR：15m K 线，ATR(14) 与 ATR(28)（高波动判断用）。  
  - 支撑/阻力：同批 15m K 线，`FindSupportLevel` / `FindResistanceLevel`，lookback 30。

---

## 三、触发逻辑（any / all）

- **any（默认）**：任一已启用且满足的止损条件触发，即返回**第一个**触发的 signal，后续不再合并；执行层按该 signal 平仓并写入对应 `close_reason`。
- **all**：仅当**当前周期**内满足的 signal 数量 ≥「已启用的条件总数」时，才返回一个合并的 `combined` signal 并执行；否则本周期不触发。  
  「已启用条件数」由 `countEnabledConditions()` 决定（Initial>0、Trailing 开、ATR 开、支撑阻力开、逆势早退开 各算 1）。

---

## 四、确认周期（ConfirmCycles）与高波动多确认

- 即使某条止损条件在本周期满足，也**不立刻平仓**，而是先给该仓位在内存里累加「连续满足周期数」。
- **requiredCycles**：来自配置 `ConfirmCycles`（如 2 表示需连续 2 周期满足）。若开启了**高波动宽容**且当前满足「当前 ATR > 长期 ATR×阈值」，则 requiredCycles 再 +1（多要 1 个确认周期）。
- 当「连续满足周期数」≥ requiredCycles 时，才真正调用 `executeStopLoss` 下单平仓，并清除该仓位的计数。
- 若本周期该条件**未满足**，则将该仓位的连续计数**清零**，下一周期重新累计。

因此：**单根 K 线或单次检查触及止损价，不一定会立刻平仓**，会视确认周期与是否高波动而延迟，减少噪音触发。

---

## 五、执行与平仓原因写入

- `executeStopLoss` 根据 signal 的 `Type` 生成 `close_reason`：  
  `system:sl:initial` | `system:sl:trailing` | `system:sl:atr` | `system:sl:support_resistance` | `system:sl:adverse_never_profit` | `system:sl:breakeven` | `system:sl:combined`；追踪止损会带档位与峰值/回撤信息。
- 执行前会调用 `SetPendingCloseReasonBySymbol` 把该原因写入持仓表，便于 OrderSync 或后续记录保留为「系统止损」并区分类型。

## 六、整体实现效果小结

| 维度 | 效果 |
|------|------|
| **谁先执行** | 每周期先做 SL/TP 检查（含最小持仓、breakeven），再做 AI 决策与开仓，因此策略止损优先于 AI。 |
| **震荡市** | 宽 ATR（如 1.5–2.5×）、高波动自动放宽、确认周期与高波动多确认，减少单 K 线假跌破；追踪止损只在有过浮盈后生效，避免一开仓就被「回撤」洗出。 |
| **逆势单** | 若开启「从未浮盈+反向过大早退」，在**从未浮盈**且**反向移动 ≥ 配置×ATR** 时提前止损，减小逆势单亏损，且不改变正常 ATR 止损线。 |
| **盈利保护** | 达到 LockProfitPercent 后，回撤到入场价会走 breakeven 止损；其他止损在已锁利时也会被限制为不劣于入场价。 |
| **多条件** | 默认「任一」触发即平；可选「全部」触发才平，适合多条件共振才认作真破位。 |

综合来看：**止损策略通过最小持仓、确认周期、高波动宽容和多种类型（固定/追踪/ATR/支撑阻力/逆势早退）组合，在震荡市尽量少被洗出，在逆势或结构破坏时又能及时或提前退出，并保证锁利后不亏出场。**

## 七、当前止损策略的优势

| 维度 | 优势说明 |
|------|----------|
| **设计目标清晰** | 明确服务于「震荡市拿住仓、盈利后平仓」，宽 ATR + 确认周期 + 高波动宽容，避免被区间内噪音洗出；同时通过逆势早退、锁利 breakeven 控制单笔与回撤。 |
| **多类型可组合** | 五类止损（固定/追踪/ATR/支撑阻力/逆势早退）可单独或组合使用，触发逻辑可选 any/all，适配不同风格（激进保本 vs 多条件共振才认破位）。 |
| **抗噪音** | 最小持仓避免「开仓即平」；ConfirmCycles 与高波动多确认，单根 K 线或单次触及不立刻平仓，减少假跌破。 |
| **波动自适应** | ATR 止损倍数随波动 regime 调整（高波动用 Max、多 1 确认），同一套配置在平静与剧烈行情下都能合理生效。 |
| **盈利保护闭环** | LockProfitPercent 达成后 breakeven 止损 + 其他止损价不劣于入场价，锁利后不会亏着出场。 |
| **逆势单有出口** | 「从未浮盈+反向过大早退」在不收紧正常 ATR 的前提下，给纯逆势单多一条早退路径，降低单笔亏损。 |
| **可观测可追溯** | 平仓原因写入 `close_reason`（含类型与追踪档位），便于回测与实盘对照、优化参数。 |

## 九、已实现的提升（除结构破坏退场外）

- **K 线周期**：`dynamic_stop_loss.klines_timeframe`（"15m" | "1h"），用于 ATR、支撑/阻力、入场后极值、逆势早退；默认 15m，设为 1h 可减轻 15m 毛刺。
- **支撑/阻力用 EMA20**：`support_resistance_use_ema20` 为 true 时，用同周期 EMA20 作为多单支撑/空单阻力，替代或补充局部极值。
- **确认时长（分钟）**：`confirm_minutes` > 0 时，止损条件需**持续满足该分钟数**才执行，否则仍按 `confirm_cycles` 周期数；便于跨部署一致。
- **逆势早退需 ATR 骤升**：`adverse_exit_require_atr_spike` 为 true 时，仅在 当前 ATR ≥ 长期 ATR×`adverse_exit_atr_spike_threshold` 时才触发逆势早退，减少温和震荡误触。
- **山寨币逆势早退倍数**：`adverse_exit_when_never_profit_atr_altcoin` 非空时，非 BTC/ETH 使用该倍数，BTC/ETH 仍用 `adverse_exit_when_never_profit_atr`。
