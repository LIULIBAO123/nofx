# 外部交易策略分析：多层过滤 + 方向池 + 系统执行

本文档基于用户提供的截图与描述，梳理**另一套交易系统**的策略与逻辑：币种过滤条件、过滤规则、做多/做空方向分析，以及「AI 只分析量化数据、开平仓与止盈止损由系统完成」的设计。可与 nofx 3.0 对照参考。

---

## 一、整体架构概览

| 维度 | 该套系统 | 说明 |
|------|----------|------|
| **AI 职责** | 只负责分析量化数据，输出方向/强度/可靠度/时机等 | 不做下单指令，不做止盈止损决策 |
| **系统职责** | 币种过滤、方向池维护、开仓、平仓、止盈、止损 | 全部规则化/策略化执行 |
| **止盈/止损** | 单独策略：止盈、动态止盈、止损、动态止损各自配置 | 与 nofx 3.0 的 DynamicStopLoss / DynamicTakeProfit 类似但独立成策略 |
| **实测** | 用户称实测结果很好 | 说明多层过滤 + 方向一致 + 严格入场时机能提升质量 |

## 二、币种过滤条件（第一、二、三层）

### 2.1 流程管线（从截图一）

```
方向池(多+空) 
  → 第一层（16 项全过才进入候选）
  → 候选
  → 第二层（至少 6 因子 + 可靠度≥0.67 + 入场信心≥31%，技策略）
  → 待提交
  → （第三层：OI 对齐 + 入场时机强度 + 自定义因子全过）
  → 可开单
```

- **第一层 16 项**：全部满足才进入「候选」；任一不满足就不在表面显示（“一二层过滤不了就不配在表面显示”）。
- **第二层**：在候选上再做技策略过滤，要求至少 6 个因子满足 + 可靠度 ≥ 0.67 + 入场信心 ≥ 31%。
- **第三层**（聊天补充）：即使第二层通过，开单前还要过：**OI 对齐、入场时机强度、自定义因子全过**；**入场时机必须低于 5 分钟**（即“入场时机必须低于5分钟”）。

### 2.2 第一层 16 项不达标统计（截图一）

从「第一层16项不达标统计」和「按币种不达标」可反推，第一层至少包含以下类型的条件（名称与顺序按截图描述整理）：

| 类别 | 条件示例 | 说明 |
|------|----------|------|
| 入场时机 | 入场时机须为 now/soon | 否则记「入场时机非now/soon」 |
| 量能 | 量能达标 | 否则「量能未达标」 |
| 持仓量/OI | OI 达标 | 否则「持仓量/OI未达标」 |
| 长周期 | 长周期方向对齐 | 否则「长周期未对齐」 |
| 短周期 | 短周期方向对齐 | 否则「短周期未对齐」 |
| 流向 | 资金/流向与方向一致 | 否则「流向未同向」 |
| 涨跌榜 | 涨跌榜与方向一致 | 否则「涨跌榜未同向」 |
| 可靠度 | 可靠度达到门槛 | 否则「可靠度不足」 |
| 大户多空 | 大户多空与方向一致 | 否则「大户多空未同向」 |
| 全市场多空 | 全市场多空与方向一致 | 否则「全市场多空未同向」 |

其余项可归纳为：**多维度方向一致性**（周期、流向、涨跌榜、大户、全市场）+ **质量门槛**（量能、OI、可靠度、入场时机）。AXSUSDT、SIGNUSDT 的失败原因也落在这些维度上。

### 2.3 第二层（技策略）

- **至少 6 因子**：在技策略定义的多个因子中，至少 6 个满足。
- **可靠度 ≥ 0.67**：数值化可靠度门槛。
- **入场信心 ≥ 31%**：入场信心下限。
- 只有通过第二层才会进入「待提交」，再进入第三层做最终开单校验。

### 2.4 第三层（开单前最后校验）

- **OI 对齐**：开单前再查 OI 是否与方向一致。
- **入场时机强度**：满足强度要求。
- **自定义因子**：用户自定义的因子需**全过**。
- **入场时机 < 5 分钟**：明确时间约束，避免“过期”信号开单。

### 2.5 与 nofx 的对比（币种与候选）

| 项目 | 该套系统 | nofx 3.0 |
|------|----------|----------|
| 候选来源 | 方向池(多+空)，先有方向再过滤 | CoinSource：AI500/静态/OI Top/OI Low/混合，再按策略拉 K 线与指标 |
| 过滤层次 | 三层：16 项 → 技策略(6 因子+可靠度+信心) → OI+时机+自定义 | 无显式“16 项”，靠策略配置的指标+风控+AI 决策里的置信度/盈亏比 |
| 表面展示 | 一二层不过的不显示 | 候选由 GetCandidateCoins 决定，未通过的不参与 AI 决策 |
| 入场时机 | 明确要求 now/soon、<5 分钟 | 无“入场时机”字段，靠 AI 输出 open_long/open_short 与 15m 入场逻辑 |

## 三、币种过滤规则（多空雷达界面，截图二）

### 3.1 无候选时的检查项（黄条提示）

- 当前交易员是否已启动。
- 币种源（静态列表 / NofxOS 等）是否已配置。
- 是否勾选「允许做多」「允许做空」。

即：**开关 + 数据源 + 方向开关** 三者齐备，才可能有候选。

### 3.2 主控与方向开关

- **预设 / 手动 / 平仓(自动)**：不同模式，平仓(自动)表示平仓由系统策略执行。
- **允许做多、允许做空**：必须勾选，对应方向才会进入方向池。
- **AI 自动分析**：由 AI 分析量化数据，输出到方向池。

### 3.3 技策略相关参数（从界面文字）

- **HeatScore 金色 0.70**：热度/强度类分数。
- **ATR% 60%**：波动率相关。
- **资金临界% 0.00%**、**血口临界 0.00**：资金/回撤类保护。
- **可靠度门 40%**：可靠度下限（与第二层 0.67 可能不同层级或不同用途）。
- **方向分位 0.72**、**方向问 2**（滑块为 3）：方向分位数与某种“方向询问”参数，用于多空池的筛选或排序。

### 3.4 挂单候选区

- **排除已持仓、排除已挂未触发**：避免重复开仓、重复挂单。
- **挂单上限 %**：例如 5%，限制挂单占用资金比例。
- **TTL/容量…限额双 0 额外加仓**：特殊条件下允许额外加仓。

### 3.5 方向池(多) / 方向池(空)

- **AI 驱动、自动下发、自动撤单、策略标记**：方向池由 AI 驱动，系统自动下单、撤单并打标记。
- **分位 / 分位动态 40%**：可能是取前 40% 分位作为多/空候选，或阈值 40%。
- 当前示例中「当前无做多/做空候选」：说明经过上述过滤后，没有币种进入方向池。

## 四、做多/做空方向分析（截图三、四 + 聊天“焚决”）

### 4.1 方向分析三要素（“简单来说就是：趋势、动能、多周期”）

| 要素 | 含义 | 在策略中的作用 |
|------|------|----------------|
| **趋势** | 若市场震荡、混沌、方向不明，做单运气成分大 | 避免在无趋势时开单，或降低仓位/不显示候选 |
| **动能** | 是否同向加强或反向减弱 | 同向加强做趋势跟随，反向减弱防反转，用于多空方向与强度 |
| **多周期一致** | 15m / 1h / 4h 至少两周期一致 | 与 nofx “4h 定方向、1h 确认、15m 入场”类似，用于过滤与方向确认 |

“日内交易：15m? 1h? 4h? 三周期至少两周期一致”直接对应多周期过滤规则。

### 4.2 方向池(多) / 方向池(空) 表格（截图四）

- **列**：标的、强度、评分、市况、可靠度、时机、方向、量价。
- **强度 100%**：当前示例里多空池标的强度都打满，可能表示“方向信号强度”或“满足方向条件的程度”。
- **评分 1.00**：统一 1.00，可能表示已进入该方向池即给满分，或为归一化后的得分。
- **市况 trend**：均为趋势市，与“趋势、动能、多周期”中强调趋势一致。
- **可靠度**：多池 15%，空池 45%–60%，说明空池在该时刻可靠度更高，可能影响第二层 0.67 或排序。
- **时机 18m/20m**：与“入场时机必须低于5分钟”的关系可能是：这里是“信号年龄”，开单时再要求 <5 分钟才允许下单。
- **量价**：百分比，可能为量价配合度或涨跌幅等，用于因子/强度。
- **自动下发、自动撤单、跟随标**：由系统按方向池和后续过滤结果执行下单与撤单。

### 4.3 与 nofx 的对比（方向与多周期）

| 项目 | 该套系统 | nofx 3.0 |
|------|----------|----------|
| 方向来源 | 方向池(多/空)，由 AI 分析量化数据填入 | AI 直接输出 open_long/open_short，无单独“方向池”结构 |
| 多周期 | 15m/1h/4h 至少两周期一致 | 4h 定方向 + 1h 确认 + 15m 入场，提示词强制顺序 |
| 趋势/动能 | 显式强调趋势、动能同向/反向 | 通过 EMA/MACD/RSI/OI/资金流等在提示词中体现 |
| 可靠度/信心 | 可靠度≥0.67、入场信心≥31%，数值化 | MinConfidence 70、MinRiskRewardRatio 3.0，执行层校验 |

## 五、止盈、动态止盈、止损、动态止损（单独策略）

- 用户明确说：**止盈、动态止盈、止损、动态止损是单独的策略**，且开平仓都由系统完成。
- 可推断：
  - **止盈/止损**：固定或简单规则的止盈止损（如固定百分比、固定 ATR 倍数）。
  - **动态止盈/动态止损**：随行情或持仓状态变化（如追踪、分层、根据波动率调整），由系统策略执行，不交给 AI 决策。
- 与 nofx 3.0 的对应关系：
  - nofx：`DynamicStopLoss`（追踪、ATR、支撑阻力、逆势早退等）与 `DynamicTakeProfit`（分层 2.5%/6%/10%、ATR、锁利等）也是**策略配置**，由 kernel/position 层执行，AI 只给 trend_view 调节确认周期，不直接下平仓指令；二者在「平仓由系统策略完成」上一致。

## 六、策略与代码逻辑归纳

### 6.1 数据流（简化）

```
1. 币种源 + 允许多/空
     ↓
2. AI 分析量化数据 → 输出到方向池(多) / 方向池(空)（强度、评分、市况、可靠度、时机、量价等）
     ↓
3. 第一层 16 项过滤（全部通过才进入候选）
     ↓
4. 第二层技策略（≥6 因子 + 可靠度≥0.67 + 入场信心≥31%）
     ↓
5. 第三层开单前校验（OI 对齐 + 入场时机强度 + 自定义因子全过；入场时机 < 5 分钟）
     ↓
6. 系统执行：开仓、挂单、撤单
     ↓
7. 持仓期间：止盈、动态止盈、止损、动态止损 单独策略由系统执行，AI 不再决策平仓
```

### 6.2 设计要点

| 要点 | 说明 |
|------|------|
| **AI 只做分析** | 不做下单、不平仓，只产出方向、强度、可靠度、时机等，降低 AI 执行层面的错误与延迟 |
| **多层硬过滤** | 16 项 → 技策略 → 第三层，层层淘汰，保证“能显示的都能打”，开单门槛高 |
| **方向与多周期** | 趋势、动能、多周期至少两周期一致，与 nofx 的 4h/1h/15m 思路一致，更强调数值化（可靠度、信心） |
| **入场时机严格** | now/soon + <5 分钟，避免过期信号，nofx 目前无此字段，可作增强点 |
| **止盈止损策略化** | 四种策略独立配置、系统执行，与 nofx 的 DynamicStopLoss/DynamicTakeProfit 思路一致，便于回测与风控 |

### 6.3 为何实测结果可能较好（推论）

1. **过滤严**：一二层不过不显示，第三层不过不开单，减少低质量与逆势单。
2. **方向清晰**：趋势 + 动能 + 多周期一致，只在方向明确时给候选。
3. **执行分离**：AI 不碰下单与平仓，减少模型幻觉与延迟对执行的影响。
4. **止盈止损独立**：规则清晰、可回测、可调参，盈亏比与回撤更可控。
5. **入场时机**：<5 分钟约束使信号“新鲜”，适合短线/日内。

## 七、实时价格与盈亏掌握（用户补充）

用户还分享了一条经验：**获取实时价格能更好地掌握盈利或亏损**。

### 7.1 含义与作用

| 维度 | 说明 |
|------|------|
| **实时价格** | 尽可能接近当前盘口的价格（如交易所最新成交/标记价），而非仅依赖 K 线收盘价或周期拉取时的快照。 |
| **更好掌握盈亏** | 未平仓的浮动盈亏（unrealized PnL）、峰值盈亏（用于追踪止损）、以及止盈/止损触发判断，都依赖「当前价」；价格越实时，计算越准、触发越及时。 |
| **对策略的影响** | 动态止损/止盈、追踪止损、分层止盈等，都依赖「当前价 vs 入场价/峰值」；若价格滞后，可能过早或过晚触发，影响实际盈亏与回撤。 |

因此，在该套系统中，若在**持仓监控与止盈止损检查**环节使用实时价格（如 WebSocket 推送或高频率轮询），能更准确判断是否达到止盈/止损条件，从而**更好掌握盈利或亏损**。

### 7.2 与 nofx 的对照

| 项目 | nofx 当前 | 可增强点 |
|------|-----------|----------|
| **价格来源** | 持仓的 `mark_price` / `markPrice` 来自交易所接口（如 GetPositions、GetBalance），在**每个交易周期**拉取上下文时更新；动态 SL/TP 检查时使用的是该周期内的持仓快照价格。 | 若周期较长（如 5–15 分钟），两次检查之间价格可能已明显变动；可考虑在 SL/TP 检查时**单独拉取一次最新标记价**，或对持仓标的订阅实时价格（WebSocket/高频轮询），使触发更贴近真实行情。 |
| **盈亏计算** | 未实现盈亏、峰值盈亏百分比等由 `mark_price` 与入场价、杠杆计算；逻辑正确，但依赖「何时取价」。 | 在仪表盘或风控逻辑中，若需「更好掌握」当前盈亏，可提高取价频率或接入实时价源，用于展示与决策。 |
| **止盈止损触发** | 使用当时上下文中的持仓 mark 价做判断；若与交易所强平/标记价一致，则主要差异来自**检查频率**与**价格延迟**。 | 提高检查频率 + 使用实时价，可减少「价格已穿止损但未及时触发」或「已触发但成交价滑点更大」的情况。 |

### 7.3 小结

- **用户观点**：获取实时价格能更好地掌握盈利或亏损。  
- **策略含义**：在持仓监控与止盈止损逻辑中使用实时（或更高频）价格，能更准确计算浮动盈亏、峰值回撤，并更及时地触发止盈/止损，从而更好掌握每笔仓位的盈利或亏损。  
- **nofx**：当前以周期内拉取的 `mark_price` 为准；若在 SL/TP 检查或前端展示中引入更实时的价格（如检查前单独拉取最新价、或 WebSocket 推送），将更贴合该经验。

## 九、总结

- **币种过滤**：第一层 16 项（方向、量能、OI、多周期、流向、涨跌榜、可靠度、大户/全市场多空等）全过 → 第二层技策略（6 因子 + 可靠度 0.67 + 入场信心 31%）→ 第三层 OI 对齐 + 入场时机强度 + 自定义因子全过，且**入场时机 <5 分钟**。
- **方向分析**：趋势、动能、多周期（15m/1h/4h 至少两周期一致），由 AI 分析量化数据填入方向池(多/空)，系统按池与后续过滤执行开仓与撤单。
- **执行分工**：AI 只负责分析；开仓、平仓、止盈、动态止盈、止损、动态止损均由系统按单独策略执行，实测效果较好。
- **实时价格**（用户补充）：获取实时价格能更好地掌握盈利或亏损；在持仓监控与止盈止损中使用实时（或更高频）价格，可更准确计算浮动盈亏与峰值回撤，并更及时触发止盈/止损。
- 与 **nofx 3.0** 相比：思路相近（多周期、OI、风控、动态止盈止损）；差异主要在**显式多层过滤、入场时机约束、方向池与可靠度/信心数值化**；nofx 若在以上几点及**价格实时性**上做增强，可更贴近该套逻辑。
