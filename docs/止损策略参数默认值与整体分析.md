# 止损策略：参数默认值与整体分析

本文档给出**所有止损相关参数的推荐默认值及依据**，并对**代码结构、提示词、参数逻辑与功能可用性**做整体分析。

---

## 一、参数一览与默认值

### 1.1 全局与触发

| 参数 | 类型 | 推荐默认 | 说明与依据 |
|------|------|----------|------------|
| `enabled` | bool | true | 关闭则整块动态止损不生效，默认开启。 |
| `trigger_logic` | string | "any" | "any"=任一条件触发即平；"all"=全部启用条件都触发才平。默认 any 符合常见「先到先执行」预期。 |

### 1.2 时间与确认

| 参数 | 类型 | 推荐默认 | 说明与依据 |
|------|------|----------|------------|
| `min_hold_minutes` | float64 | 5（前端）/ 10（预设） | 未满不参与动态止损/止盈，避免「开仓即平」。5 为最低建议（schema 建议如 5 分钟）；预设用 10 更稳。 |
| `confirm_cycles` | int | 2 | 条件需**连续 2 周期**满足才执行，减少单 K 线假跌破。1=立即。 |
| `confirm_minutes` | float64 | 0 | 0=按 `confirm_cycles` 周期数确认；>0=按**真实分钟数**持续满足才执行，跨部署一致。默认 0 保持周期语义。 |

### 1.3 K 线与结构

| 参数 | 类型 | 推荐默认 | 说明与依据 |
|------|------|----------|------------|
| `klines_timeframe` | string | "15m" | ATR、支撑/阻力、入场后极值、逆势早退均用该周期。15m 响应快；1h 可减毛刺，按需切换。 |
| `support_resistance_use_ema20` | *bool | false | 为 true 时用同周期 EMA20 作多单支撑/空单阻力。默认 false 保留原局部极值行为。 |

### 1.4 五类止损开关与数值

| 参数 | 类型 | 推荐默认 | 说明与依据 |
|------|------|----------|------------|
| `initial_stop_percent` | float64 | 0 | 0=不用固定百分比，仅动态/ATR/追踪；>0 则触及即触发。默认 0 与「无固定初始止损」设计一致。 |
| `trailing_enabled` | *bool | false（前端）/ true（预设） | 追踪止损需曾浮盈后才生效。前端默认关便于先配 ATR；预设可开。 |
| `trailing_levels` | [] | 见下表 | 档位：盈利达某%激活该档，再从峰值回撤某%触发。 |
| `atr_enabled` | *bool | false（前端）/ true（预设） | ATR 止损主开关。 |
| `atr_multiplier_min/max` | *float64 | 1.5 / 3.5 | 与 kernel getFloat64Value 默认一致；高波动时用 max。 |
| `atr_period_btc_eth` / `atr_period_altcoin` | *int | 20 / 14 | 主流币周期略长，山寨略短。 |
| `support_resistance_enabled` | *bool | false | 支撑/阻力止损开关。 |
| `support_resistance_buffer` | *float64 | 0.5 | 支撑/阻力缓冲百分比，默认 0.5%。 |
| `atr_tolerance_enabled` | *bool | true | 高波动时多 1 确认周期且 ATR 用 max，建议默认开。 |
| `atr_high_multiplier` | *float64 | 1.2 | 当前 ATR > 长期 ATR×1.2 视为高波动。 |

### 1.5 逆势早退

| 参数 | 类型 | 推荐默认 | 说明与依据 |
|------|------|----------|------------|
| `adverse_exit_when_never_profit_atr` | *float64 | 0 | 0=关闭。建议 1.0–1.2 时手动开启，避免默认改变行为。 |
| `adverse_exit_when_never_profit_atr_altcoin` | *float64 | 未设 | 未设则与主倍数一致；可设不同值区分 BTC/ETH 与山寨。 |
| `adverse_exit_require_atr_spike` | *bool | false | 为 true 时仅当 ATR 骤升才触发逆势早退。默认 false 避免漏触发。 |
| `adverse_exit_atr_spike_threshold` | *float64 | 1.2 | 开启骤升过滤时，当前 ATR ≥ 长期×此值才通过，与高波动判定一致。 |

### 1.6 默认值落点

- **前端** `DynamicStopLossEditor` 的 `defaultConfig`：用于新建/未保存策略的 UI 默认，已按上表设置（含 `confirm_minutes`、`klines_timeframe`、`support_resistance_use_ema20`、`adverse_exit_*`）。
- **后端** `store.GetDefaultStrategyConfig` 预设：两套预设均显式设置 `ConfirmMinutes: 0`、`KlinesTimeframe: "15m"`，其余未写字段为零值（与上表一致）。
- **运行时**：`kernel` 用 `getFloat64Value(ptr, default)` 处理 nil；`auto_trader` 在 `KlinesTimeframe == ""` 时用 `"15m"`，`ConfirmMinutes <= 0` 时走周期数逻辑。

## 二、代码结构

### 2.1 调用链

1. **入口**：`runCycle()` 内先调 `checkDynamicStopLossTakeProfit()`，再拉行情、调 AI、执行开仓。
2. **数据**：仓位来自 `at.trader.GetPositions()`；K 线由 `marketClient.GetKlines(symbol, tf, 50)` 拉取，`tf` 来自 `stopLossConfig.KlinesTimeframe`（空则 "15m"）。
3. **前置**：对每个仓位先做「最小持仓」判断（取止损与止盈 `MinHoldMinutes` 较大值），未满则跳过；再判「锁利后 breakeven」。
4. **五类止损**：在 `kernel.StopLossChecker.CheckStopLoss` 中依次检查：初始固定 → 追踪 → ATR → 支撑/阻力 → 逆势早退；收集触发的 signal 后按 `trigger_logic`（any/all）决定是否返回并执行。
5. **确认**：若 `ConfirmMinutes > 0` 用 `slFirstTriggeredAt` 做「持续满足分钟数」；否则用 `slConfirmCount` 做「连续周期数」，高波动时 `requiredCycles+1`。
6. **执行**：`executeStopLoss` 写 `close_reason`（含类型）、`SetPendingCloseReasonBySymbol`、下单并记录。

### 2.2 数据流与默认值

- **K 线周期**：仅当 `KlinesTimeframe` 非空且为 "15m" 或 "1h" 时使用，否则 "15m"。同一批 K 线用于：ATR(14)/ATR(28)、入场后最高/最低、支撑/阻力（或 EMA20）、逆势早退判定。
- **支撑/阻力**：若 `SupportResistanceUseEMA20 == true` 且 `CalculateEMA(klines,20) > 0`，多单用 supportLevel=EMA20、空单用 resistanceLevel=EMA20；否则仍用 `FindSupportLevel` / `FindResistanceLevel`。
- **逆势早退**：倍数由 `getAdverseExitMultiplier(symbol)` 按是否 BTC/ETH 选主倍数或 altcoin 倍数；若 `AdverseExitRequireATRSpike == true` 且 `atrLong > 0`，需 `atr >= atrLong * threshold` 才继续判定。

## 三、提示词

### 3.1 注入来源

- **策略动态 SL/TP 文案**：`kernel/engine.go` 的 `formatStrategyDynamicSLTP` 根据当前策略配置生成一段说明，包含：最小持仓、追踪/ATR/支撑阻力/逆势早退/K 线周期/EMA20/确认时长等**已启用或非默认**项。
- **系统原则**：`kernel/prompt_builder.go` 中固定写「止盈止损由策略自动执行」「结构破坏可建议平仓」等；schema 中建议 MinHoldMinutes 如 5 分钟。

### 3.2 与执行的一致性

- 提示词中的「追踪止损、ATR 止损、分层止盈由策略执行」与 `checkDynamicStopLossTakeProfit` 先于 AI 执行、且使用同一 `GetConfig().RiskControl` 一致。
- 展示的「从未浮盈+反向≥X×ATR」「山寨X×」「需ATR骤升」「止损K线周期」「支撑/阻力用EMA20」「确认时长X分钟」均来自同一份 config，与运行时逻辑一致。

## 四、参数逻辑合理性

| 检查项 | 结论 |
|--------|------|
| **min_hold 与 confirm 不冲突** | 先满足 min_hold 才进入 SL 检查；确认用周期数或分钟数二选一，逻辑清晰。 |
| **K 线周期统一** | 一处配置驱动 ATR、S/R、极值、逆势早退，避免多周期混用导致不一致。 |
| **逆势早退与主止损** | 逆势早退仅对「从未浮盈」且「反向≥X×ATR」生效，不改变已有 ATR/追踪线；可选 ATR 骤升与山寨倍数，语义清晰。 |
| **any/all** | any=任一触发即平；all=当前周期内触发的条件数≥启用条件总数才平，与 `countEnabledConditions` 一致。 |
| **高波动** | ATR 止损用 max 倍数、确认多 1 周期；逆势早退可选「需 ATR 骤升」，与「高波动更宽容」一致。 |

## 五、功能是否均可正常工作

| 功能 | 条件 | 结论 |
|------|------|------|
| 最小持仓 | MinHoldMinutes > 0 | ✅ 未满则本周期跳过该仓位 SL/TP。 |
| 锁利 breakeven | LockProfitPercent 达成且价格回到入场价 | ✅ 先于五类止损检查，执行后 continue。 |
| 初始固定止损 | InitialStopPercent > 0 | ✅ checkInitialStop 触及即加入 signal。 |
| 追踪止损 | TrailingEnabled 且 TrailingLevels 非空 | ✅ 曾浮盈后按档位与回撤%判定；从未浮盈不触发。 |
| ATR 止损 | ATREnabled 且 atr>0 | ✅ 高波动用 max 倍数；与 atrLong 判定一致。 |
| 支撑/阻力止损 | SupportResistanceEnabled 且 level>0 | ✅ 支持 EMA20 或局部极值，多单用支撑、空单用阻力。 |
| 逆势早退 | AdverseExitWhenNeverProfitATR>0（或 altcoin 设且非 BTC/ETH） | ✅ 从未浮盈+反向≥倍数×ATR；可选 ATR 骤升、山寨倍数。 |
| 确认周期/分钟 | ConfirmCycles / ConfirmMinutes | ✅ 分钟>0 用 slFirstTriggeredAt；否则用 slConfirmCount，高波动+1。 |
| K 线周期 | KlinesTimeframe | ✅ 空则 "15m"；"1h" 时拉 1h K 线，条数 50。 |
| 平仓原因 | executeStopLoss 写 close_reason | ✅ 类型与追踪档位写入；SetPendingCloseReasonBySymbol 供 OrderSync。 |

---

## 六、小结

- **默认值**：已在前端 defaultConfig、后端预设与 kernel/auto_trader 的 fallback 中统一；新参数（confirm_minutes、klines_timeframe、support_resistance_use_ema20、adverse_*）均有明确默认且不改变原有「震荡市拿住仓」行为。
- **代码结构**：入口→数据→前置→五类检查→触发逻辑→确认→执行，链路清晰；配置单源（策略 JSON），与提示词一致。
- **提示词**：由同一 config 生成策略 SL/TP 说明，与执行逻辑一致。
- **参数逻辑**：时间与确认、周期统一、逆势早退与主止损、any/all、高波动处理均合理。
- **功能**：最小持仓、breakeven、五类止损、确认（周期/分钟）、K 线周期、平仓原因写入均可正常工作；未实现仅「结构破坏退场」一项（已明确不做）。
