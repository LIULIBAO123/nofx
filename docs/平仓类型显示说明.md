# 平仓类型显示说明

## 为什么显示「交易所同步」而不是「系统止损/止盈」？

实盘平仓后，历史记录里的**平仓方式/平仓类型**可能显示为「交易所同步」或「由交易所同步获得」，而不是「系统」+「触发动态止损/止盈」。原因如下。

### 1. 实盘平仓的两种记录路径

- **路径 A（有明确原因）**  
  系统在**发出平仓单之前**会把本次平仓原因（如 `system:sl:trailing`、`system:tp:scaled`）写入持仓表。若后续是由「我们自己的逻辑」在本地完成关仓并写库（例如部分环境下的立即回写），则最终 `close_reason` 会保留为这些值，前端就会显示「系统」+「触发动态止损/止盈」等。

- **路径 B（交易所同步，常见于实盘）**  
  实盘对接的交易所（如 Binance、Bybit 等）在收到我们的平仓单并成交后，**不会在 API 里区分**这笔平仓是「用户手动」还是「系统止损/止盈」。后端通过 **OrderSync** 从交易所拉取已平仓记录并写入数据库时，只能得到「已平仓」这一事实，拿不到「具体平仓原因」，因此会存成：
  - `close_reason = "sync"`（由本地持仓数量变为 0 而关仓），或  
  - `close_reason = "unknown"`（由交易所历史成交/持仓接口同步得到，且交易所未提供原因）。

  这两种都会在界面上显示为**「交易所同步」**及「由交易所同步获得（可能为系统止损/止盈或外部平仓）」等文案，**不会**显示为「手动」。

### 2. 为何有的单显示「系统」、有的显示「交易所同步」或曾显示「手动」？

- **后端**：策略在发出平仓单前会把原因（如 `system:tp:scaled`）写入该笔持仓的 `close_reason`。但 OrderSync 在「把持仓从交易所同步为已平仓」时，会调用 `ReducePositionQuantity` 将持仓标为 CLOSED。旧逻辑里这里会**无条件**把 `close_reason` 写成 `"sync"`，把之前写好的 `system:tp:xxx` / `system:sl:xxx` 覆盖掉，所以界面上就变成「交易所同步」或旧版前端的「手动」。  
  **已修正**：在 `store/position.go` 的 `ReducePositionQuantity` 中，当将持仓标为 CLOSED 时，若该笔持仓已有 `close_reason`（例如已由策略写入的 system:tp/system:sl），则**保留不覆盖**，仅当为空时才设为 `"sync"`。这样由系统止损/止盈触发的平仓会正确保留为「系统」+「触发止盈/止损」。
- **前端**：旧版对所有「非 AI / 非 system:sl / 非 system:tp」的 `close_reason` 都显示为「手动」+「交易所/同步或手动平仓」。  
  已修正：只有 `close_reason === "manual"` 时才显示为「手动」；`sync` / `unknown` 显示为「交易所同步」及对应说明。

### 3. 当前展示规则（修正后）

| close_reason       | 平仓方式   | 平仓类型说明 |
|--------------------|------------|--------------|
| `ai`               | AI         | 通过 AI 分析判断 |
| `system:sl:xxx`    | 系统       | 触发动态止损：xxx |
| `system:tp:xxx`    | 系统       | 触发动态止盈：xxx |
| `sync`             | 交易所同步 | 由交易所同步获得（可能为系统止损/止盈或外部平仓） |
| `unknown`          | 交易所同步 | 由交易所同步获得（交易所未返回具体平仓原因） |
| `manual`           | 手动       | 手动平仓 |
| 其他/空            | 交易所同步 | 由交易所同步获得 |

因此：**若您没有在交易所或本系统里点击「平仓」，却看到「交易所同步」，通常表示该笔平仓是由系统止损/止盈或交易所侧逻辑触发的，只是交易所未把「原因」下发给我们，所以无法在界面上标成「系统：止损/止盈」，只能标成「交易所同步」。**

## 策略为「仅系统止盈止损平仓」时为何还会出现无具体原因？

若策略设置为「AI 仅开仓、仅由系统止盈/止损平仓」且每次平仓都有具体原因，理论上不应出现「交易所同步」或空原因。可能原因与修复如下。

### 1. 分层止盈（部分平仓）未写入原因（已修复）

- **原因**：原先只有在**全额**止盈（`PartialPercent >= 100`）时才会对持仓写入 `close_reason`。分层止盈是多次**部分**平仓（如 25%、25%、50%），每次都是部分平仓，因此从未在 DB 的 OPEN 持仓上写入 `system:tp:scaled`。当最后一次部分平仓被 OrderSync 处理、持仓数量归零时，`position.CloseReason` 为空，只能落成 `sync`，界面显示为「交易所同步」。
- **修复**：在 `executeTakeProfit` 中，**每次**执行止盈（不论部分还是全额）都调用 `SetPendingCloseReasonBySymbol`，使该持仓在 DB 上始终带有 `system:tp:xxx`。这样无论是第一次还是最后一次部分平仓，OrderSync 将持仓标为 CLOSED 时都能保留「系统」+「触发止盈」的展示。

### 2. 止损单也显示「交易所同步」——symbol 不一致导致未写入原因（已修复）

- **原因**：策略在触发止损时会调用 `SetPendingCloseReasonBySymbol`，用 `market.Normalize(position.Symbol)`（如 `VVVUSDT`）去更新 OPEN 持仓。若数据库中该持仓的 `symbol` 存的是无后缀形式（如 `VVV`），则 WHERE 条件匹配不到任何行，`close_reason` 实际上没有被写入。OrderSync 处理平仓时 `GetOpenPositionBySymbol` 会按「先 symbol 再 base」的兼容逻辑查到该持仓，但此时 `CloseReason` 仍为空，只能落成 `sync`，界面就显示为「交易所同步」。
- **修复**：在 `SetPendingCloseReasonBySymbol` 中与 `GetOpenPositionBySymbol` 保持一致：若用传入的 symbol 更新到的行数为 0 且 symbol 带 `USDT` 后缀，则再用去掉 `USDT` 的 base 再更新一次，保证无论 DB 存的是 `VVV` 还是 `VVVUSDT` 都能写上平仓原因。

### 3. 其他可能情况

- **无匹配 OPEN 持仓**：同步到一笔平仓时，若根据 trader/symbol/side 找不到对应的 OPEN 持仓（例如该持仓在别处开仓或数据异常），会走「孤儿平仓」逻辑，只能记录为 `sync`。
- **历史数据**：本次修复前的平仓记录已是「无原因」写入 DB，无法自动补全，只有修复后新产生的平仓会带具体原因。

## 如何查到「此次平仓的真正原因」？

当某笔平仓在界面上显示为「交易所同步」（即 `close_reason` 为空、`sync` 或 `unknown`）时，系统会**根据同期决策记录做推断**并展示：

- **推断逻辑**：在该笔持仓的平仓时间（`exit_time`）前后一段时间内（前 5 分钟、后 2 分钟），在 `decision_records` 中查找同一交易员、同一标的、同一方向（多/空）的 `close_long` / `close_short` 决策；若找到，则用该决策的 `Reasoning` 文案作为「推断原因」。
- **展示方式**：历史持仓列表中，若存在推断结果，则「平仓方式」显示为「推断：系统止盈」/「推断：系统止损」/「推断：系统平仓」，「平仓类型」显示决策中的具体说明（如 "Dynamic take profit triggered: ..." 或 "Stop loss triggered: ..."）。
- **限制**：仅当该周期有写入决策记录（AI 或策略触发的平仓被记入决策）时才能推断；若当时未写决策或记录已清理，则无法推断，只能继续显示「交易所同步」。
