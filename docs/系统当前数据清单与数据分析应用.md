# 系统当前获取的数据清单与数据分析应用

本文档列出 **nofx 当前实际获取到的全部数据**（不含 CoinAnk 套餐），并说明 **如何将这些数据用于分析**（过滤、方向判断、AI 辅助、风控等）。便于统一理解「数据从哪来」和「数据怎么用」。

---

## 一、当前系统获取到的数据（按来源与类型）

### 1. 账户与持仓（交易所 / 模拟盘）

| 数据项 | 来源 | 说明 |
|--------|------|------|
| 总权益、可用余额、未实现盈亏 | `Trader.GetBalance()` | 每周期从绑定交易所或 Paper 获取 |
| 持仓列表：标的、方向、开仓价、标记价、数量、杠杆、强平价、保证金、未实现盈亏 | `Trader.GetPositions()` | 用于 Context 持仓列表、止盈止损检查、AI 提示词 |
| 近期平仓记录（最近 N 笔） | `store.Position().GetRecentTrades()` | 写入 Context.RecentOrders，供 AI 参考 |
| 交易统计：胜率、盈亏比、夏普、最大回撤等 | `store.Position().GetFullStats()` | 写入 Context.TradingStats，供 AI 参考 |

---

### 2. 候选币来源（CoinSource）

| 数据项 | 来源 | 说明 |
|--------|------|------|
| 静态币列表 | 策略配置 `CoinSource.StaticCoins` | 固定交易对 |
| AI500 评分币池 | NofxOS（若 `UseAI500`） | 评分选币列表 |
| OI 排行（top/low） | NofxOS（若 `UseOITop`） | 作为候选池或与静态/AI500 取并集 |

---

### 3. 行情与技术指标（market 层）

**数据来源**：多周期 K 线来自 **CoinAnk 免费 K 线接口**（或 Hyperliquid，视交易所/资产类型）；单标的 OI、资金费率来自 **Binance fapi 公开接口**（`market/data.go`）。

| 数据项 | 说明 | 策略开关 |
|--------|------|----------|
| 多周期 K 线 OHLCV | 策略配置的 `SelectedTimeframes` / `PrimaryTimeframe`、`PrimaryCount` | Klines |
| 当前价、1h/4h 涨跌幅 | 由 K 线计算 | — |
| EMA（如 20、50） | 由主周期 K 线计算 | EnableEMA |
| MACD、RSI（如 7、14） | 由主周期 K 线计算 | EnableMACD, EnableRSI |
| ATR、布林带、成交量序列 | 由 K 线计算 | EnableATR, EnableBOLL, EnableVolume |
| 单标的持仓量 OI | Binance `fapi/v1/openInterest` | EnableOI |
| 单标的资金费率（当前） | Binance `fapi/v1/premiumIndex`（带 1h 缓存） | EnableFundingRate |

**写入位置**：`Context.MarketDataMap[symbol]`（在 `fetchMarketDataWithStrategy` 中按持仓 + 候选币拉取）。

---

### 4. NofxOS 量化与排行（需 NofxOS API Key，策略开关控制）

| 数据项 | 说明 | 策略开关 |
|--------|------|----------|
| 单币量化数据 | 机构/散户资金流、持仓变化、多周期涨跌幅等 | EnableQuantData |
| OI 排行 | 全市场 OI 增加/减少 top/low（1h/4h/24h） | EnableOIRanking |
| 资金流排行 NetFlow | 机构/个人、期货流入流出 Top/Low | EnableNetFlowRanking |
| 涨跌榜 Price Ranking | 全市场涨幅/跌幅排行（多周期） | EnablePriceRanking |

**写入位置**：`Context.QuantDataMap`、`Context.OIRankingData`、`Context.NetFlowRankingData`、`Context.PriceRankingData`。

---

### 5. 币安衍生数据（公开接口，无需 Key）

| 数据项 | 说明 | 策略开关 |
|--------|------|----------|
| 全账户 / 大户多空比 | `globalLongShortAccountRatio`、`topLongShortAccountRatio`，周期可配（5m/15m/1h/4h） | EnableBinanceLongShortRatio |
| 当前资金费率、下一档结算时间、标记价 | `premiumIndex` | EnableBinanceFundingHistory |
| Taker 买卖比 | `takerlongshortRatio`，周期可配 | EnableBinanceTakerVolume |
| 资金费率近 8h 均值 | `fundingRate` 历史最近 3 条均值 | EnableBinanceFundingRateHistory |
| 永续-现货价差 Basis | 永续标记价与现货价自算：(永续-现货)/现货×100% | EnableBasis |
| BTC 市值占比 | CoinGecko `/api/v3/global` → market_cap_percentage.btc | EnableBTCDominance |
| 强平聚合（1h/4h 多空 USD） | 币安 WebSocket `!forceOrder@arr` 本地按时间窗口聚合 | EnableBinanceWSForceOrder |

**写入位置**：`Context.BinanceLongShortMap`、`Context.BinanceFundingMap`、`Context.BinanceTakerMap`、`Context.BinanceFundingRateAvg8h`、`Context.BasisMap`、`Context.BTCDominancePct`、`Context.LiquidationAgg`。

---

### 6. 其他

| 数据项 | 说明 |
|--------|------|
| 本周期策略触发的平仓 | 动态止损/止盈触发的平仓记录，写入 `Context.StrategyTriggeredCloses` |
| 外部数据源 | 策略配置 `ExternalDataSources`：通用 HTTP API，按 JSON 路径解析后写入 Context |

## 二、数据如何用于分析（应用方式）

### 2.1 多层过滤（Pipeline Layer1）

当策略模式为 `multilayer_filter` 时，**Layer1** 对每个候选币做条件检查，数据与条件对应关系如下：

| 条件 ID | 所用数据 | 分析含义 |
|---------|----------|----------|
| volume_ok / volume_trend | MarketData 成交量序列 | 量能不低于近期均值，过滤无量标的 |
| oi_ok / oi_trend | MarketData.OpenInterest | 有有效持仓量，过滤流动性过差 |
| long_tf_aligned | PriceChange4h, PriceChange1h | 4h 与 1h 同向，趋势一致 |
| short_tf_aligned | CurrentPrice, CurrentEMA20, PriceChange1h | 短周期价格与均线、1h 涨跌同向 |
| flow_aligned | NetFlowRankingData + PriceChange1h | 机构资金流向与 1h 涨跌同向（流入+涨 / 流出+跌） |
| price_ranking_aligned / market_direction_aligned | PriceRankingData + PriceChange1h | 涨跌榜与 1h 方向一致（涨幅榜+涨 / 跌幅榜+跌） |
| whale_direction_aligned | OIRankingData + PriceChange1h | 大户 OI 增减与价格同向（OI 增+涨 / OI 减+跌） |
| trend_strength | PriceChange4h | 4h 有一定波动幅度，避免纯震荡 |
| rsi_zone | CurrentRSI7 | RSI 在可交易区间（如 28~72），避免极端超买超卖 |
| macd_signal | CurrentMACD, PriceChange1h | MACD 与 1h 方向一致 |
| funding_ok | MarketData.FundingRate | 资金费率不过于极端（|费率| &lt; 0.01） |

**结论**：行情（K 线、OI、资金费率）、OI 排行、资金流排行、涨跌榜共同支撑「趋势一致性、量价、资金与价格同向」等过滤，提高候选池质量。

---

### 2.2 二层打分与方向池（Pipeline Layer2 / Layer3）

- **Layer2**：用 MinFactors、ReliabilityThreshold、EntryConfidenceThresholdPct 等对通过 Layer1 的标的做数值化打分与门槛过滤。
- **Layer3**：信号年龄、OI 对齐等最终校验；输出 **DirectionLong / DirectionShort** 与 **ToSubmitSymbols**。

所用数据仍以 **MarketDataMap**（价格、涨跌、EMA、RSI、MACD、量、OI、FundingRate）及 **OIRankingData / NetFlowRankingData / PriceRankingData** 为主；方向池结果供「系统执行开仓」时使用，不依赖 AI 输出开仓动作。

---

### 2.3 AI 提示词（BuildUserPrompt）

所有写入 Context 的数据，在生成 User Prompt 时按模块写入，供 AI 做**辅助分析**（系统执行开仓模式下 AI 不输出 open_long/open_short，仅输出 trend_view、market_summary、market_regime、risk_alert 等）：

| 提示词模块 | 所用数据 | 分析用途 |
|------------|----------|----------|
| BTC 概览 | MarketDataMap["BTCUSDT"]：价格、1h/4h 涨跌、MACD、RSI | 大盘环境 |
| 账户与约束 | Account、Positions、MaxPositions | 仓位与开仓上限 |
| 策略触发的平仓 | StrategyTriggeredCloses | 本周期已平仓记录，辅助推理 |
| 持仓详情（含 K 线/指标） | MarketDataMap[pos.Symbol]、QuantDataMap[pos.Symbol] | 单仓技术面与资金面 |
| 候选币详情（含 K 线/指标） | MarketDataMap[coin.Symbol]、QuantDataMap[coin.Symbol] | 候选标的技术面与资金面 |
| OI 排行 | OIRankingData | 市场持仓变化结构 |
| 资金流排行 | NetFlowRankingData | 机构/散户资金流向 |
| 涨跌榜 | PriceRankingData | 市场强弱与热点 |
| 币安衍生 | BinanceLongShortMap、BinanceFundingMap、BinanceTakerMap | 多空情绪、资金费率、Taker 方向 |
| 数据补强 | BinanceFundingRateAvg8h、BasisMap、BTCDominancePct、LiquidationAgg | 资金费率趋势、溢价/贴水、BTC 主导度、强平规模 |

AI 据此输出：**trend_view**（持仓趋势是否 intact/choppy/reversing）、**market_summary**、**market_regime**、**risk_alert**（建议本周期是否不新开仓）等，用于解读与风控，不直接驱动下单。

---

### 2.4 执行与风控

| 用途 | 所用数据 | 说明 |
|------|----------|------|
| 系统开仓 | Pipeline 的 ToSubmitSymbols、DirectionLong/Short、GetSystemEntryList | 由规则与方向池决定开仓标的与方向，AI 不输出开仓 |
| risk_alert | AI 输出的 RiskAlert | 为 true 时本周期不执行系统开仓 |
| 止盈止损检查 | 持仓信息 + 实时价（Market.GetWithExchange 或缓存） | 动态止损/止盈、追踪止损、分层止盈由策略执行 |
| 开仓参数 | 策略配置的杠杆、仓位比例、InitialStopPercent、ScaledLevels 等 | 系统开仓时使用，不依赖 AI 输出 |

## 三、数据与分析应用对照总表（不含 CoinAnk）

| 数据类型 | 获取方式 | 在分析中的主要应用 |
|----------|----------|---------------------|
| 账户与持仓 | 交易所/Paper API | 仓位约束、止盈止损、AI 持仓描述与 trend_view |
| 候选币列表 | 静态 / AI500 / OI 排行 | 确定待过滤、待分析的标的集合 |
| K 线 + 技术指标 | CoinAnk K 线 + 本地计算 | Layer1 量价、趋势对齐、RSI/MACD/funding_ok；AI 技术面描述 |
| 单标的 OI / 资金费率 | Binance fapi | Layer1 oi_ok、funding_ok；AI 资金费率与 OI 描述 |
| 单币量化数据 | NofxOS | AI 提示词中资金流、持仓变化、多周期涨跌 |
| OI 排行 | NofxOS | Layer1 whale_direction_aligned；AI 市场持仓结构 |
| 资金流排行 | NofxOS | Layer1 flow_aligned；AI 资金流向描述 |
| 涨跌榜 | NofxOS | Layer1 price_ranking_aligned、market_direction_aligned；AI 市场强弱与热点 |
| 币安多空比 / 资金费率 / Taker | Binance 衍生 REST | AI 情绪与资金费率、Taker 方向描述 |
| 资金费率 8h 均值 | Binance fundingRate 历史 | AI 资金费率趋势与极端程度 |
| Basis | 永续与现货价自算 | AI 溢价/贴水与情绪 |
| BTC 占比 | CoinGecko | AI 宏观环境（BTC 主导 vs 山寨轮动） |
| 强平聚合 1h/4h | 币安 WS forceOrder 聚合 | AI 市场 regime、risk_alert（强平骤增可建议不开仓） |
| 近期平仓与交易统计 | Store | AI 对近期表现与风险的理解 |

## 四、小结

- **当前系统获取到的数据**：账户与持仓、候选币来源、行情与技术指标（K 线、OI、资金费率）、NofxOS 量化与排行（可选）、币安衍生与数据补强（多空比、资金费率、Taker、8h 均值、Basis、BTC 占比、WS 强平聚合）、策略触发的平仓与外部数据源。**未使用 CoinAnk 套餐时，不包含 CoinAnk 清算接口数据。**
- **数据分析应用**：同一份数据在 **规则层**（Layer1/2/3 过滤与方向池）、**AI 层**（提示词与 trend_view / market_summary / market_regime / risk_alert）、**执行与风控层**（系统开仓、risk_alert 拦截、止盈止损）中复用，形成「数据 → 过滤 → 方向池 → 系统开仓 + AI 辅助解读与风控」的完整链路。
