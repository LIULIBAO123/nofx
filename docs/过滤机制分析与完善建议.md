# 过滤机制分析与完善建议

本文档基于当前 `kernel/pipeline.go` 与策略配置，分析**多层过滤机制**的实现现状、潜在问题与可完善点。

---

## 一、当前过滤机制结构概览

- **第一层（Layer1）**：16 项条件逐币种检查，未通过项记入失败统计；`RequiredAll=true` 时任一未过即整币不通过。
- **第二层（Layer2）**：因子数 ≥ M、可靠度 ≥ 阈值、入场信心 ≥ 阈值（均由规则计算，无 AI）。
- **第三层（Layer3）**：开单前校验信号年龄、标的是否在 ToSubmitSymbols；另有方向过滤（多空雷达 AllowLong/AllowShort）。
- **方向池**：按 L1 通过列表构建 DirectionLong/DirectionShort，L2 通过列表再按方向过滤得到 ToSubmitSymbols；系统开仓时用 GetSystemEntryList(state, opts) 取最终开仓列表。

---

## 二、Layer1 现状与问题

### 2.1 条件与数据依赖

| 条件 ID | 当前逻辑 | 数据依赖 | 问题/说明 |
|---------|----------|----------|-----------|
| entry_timing | 恒 true | — | **未实现**：仅依赖 Layer3 信号年龄，Layer1 无“入场时机”判断。 |
| volume_ok | 最新量 ≥ 近期均值×0.5 | MarketData.IntradaySeries.Volume | **多周期策略下失效**：见 2.2。 |
| oi_ok | OI.Latest > 0 | MarketData.OpenInterest | 正常。 |
| long_tf_aligned | 4h 与 1h 涨跌同号 | PriceChange4h, PriceChange1h | 正常。 |
| short_tf_aligned | 价格 vs EMA20 与 1h 同向 | CurrentPrice, CurrentEMA20, PriceChange1h | 正常。 |
| flow_aligned | 机构流向与 1h 涨跌同向 | NetFlowRankingData | 数据为 nil 时**直接通过**（fail-open）。 |
| price_ranking_aligned | 涨跌榜与 1h 同向 | PriceRankingData | 同上。 |
| reliability_min | 恒 true | — | 有意留给 Layer2；若需 Layer1 门槛可再用 item.Value。 |
| whale_direction_aligned | 大户 OI 与 1h 同向 | OIRankingData | 数据为 nil 时通过。 |
| market_direction_aligned | 与 price_ranking_aligned 同逻辑 | PriceRankingData | 与 price_ranking_aligned 重复。 |
| trend_strength | \|4h 涨跌\|≥0.2 或 有价有 EMA | PriceChange4h, CurrentPrice, CurrentEMA20 | 正常。 |
| rsi_zone | RSI 在 28~72 | CurrentRSI7 | 正常。 |
| macd_signal | MACD 与 1h 同向 | CurrentMACD, PriceChange1h | 正常。 |
| volume_trend | 同 volume_ok | IntradaySeries.Volume | **同 volume_ok，多周期下失效**。 |
| oi_trend | OI.Latest > 0 | OpenInterest | 与 oi_ok 相同。 |
| funding_ok | \|资金费率\| < 0.01 | FundingRate | 正常。 |

### 2.2 多周期策略下 Volume 条件失效（需修复）

- `market.GetWithTimeframes()` 返回的 `*market.Data` **未设置 IntradaySeries**，仅设置 `TimeframeData`（各周期序列）。
- Layer1 的 `volume_ok`、`volume_trend` 依赖 `md.IntradaySeries.Volume`，为 nil 时直接 `return true`，导致**多周期策略下量能条件恒通过**。
- **建议**：
  - 在 `market.GetWithTimeframes` 中，用主周期 K 线计算并赋值 `IntradaySeries`（与 Get/GetWithExchange 一致）；或
  - 在 pipeline 的 `checkLayer1Item` 中，当 `IntradaySeries == nil` 时，若 `TimeframeData[primary]` 存在且含 Volume，用其做 volume_ok / volume_trend 判断。

### 2.3 默认 Layer1 仅 10 项

- `defaultLayer1Config()` 只启用 10 项，未包含：trend_strength、rsi_zone、macd_signal、volume_trend、oi_trend、funding_ok。
- 与“第一层 16 项”的文档描述不一致；若设计为“默认 16 项、可按需关闭”，建议在默认配置中补全 16 项并设为 Enabled；若设计为“默认 10 项、可选加严”，建议在文档中明确说明。

### 2.4 数据缺失时一律通过（fail-open）

- 当 `NetFlowRankingData`、`OIRankingData`、`PriceRankingData` 为 nil 时，依赖它们的条件（flow_aligned、whale_direction_aligned、price_ranking_aligned、market_direction_aligned）均返回 true。
- **风险**：数据源故障或未配置时，过滤会无形放宽。
- **建议**：在策略或 Layer1 配置中增加“数据不可用时是否视为不通过”（fail-closed）选项；当某条件 Enabled 且依赖数据为 nil 时，若为 fail-closed 则返回 false，否则保持当前 true。

### 2.5 可选的 Layer1 增强

- **reliability_min**：若配置了 `item.Value`，可在 Layer1 用 Layer2 的 reliability 预算（或简化版）做一次门槛过滤，不通过则直接不进入 Layer2。
- **entry_timing**：若需在 Layer1 体现“当前可入场”，可基于主周期 K 线或最近信号时间做简单规则（例如“最近 N 根 K 线内出现方向一致”），否则保持“仅 Layer3 信号年龄”并在文档中写清。

## 三、Layer2 现状与问题

### 3.1 因子与阈值

- **因子**：当前按 7 类计数（价 vs EMA20、有量能、RSI 合理、MACD 非 0、OI>0、4h/1h 同向、有涨跌），满足即 factorsPassed++；MinFactors 默认 6。
- **可靠度**：多周期对齐数 + 因子数线性组合，归一化到 0.5~1。
- **入场信心**：基础值 + RSI 非极端 + MACD 与 1h 同向 的加成。

### 3.2 可完善点

- **与 Layer1 数据一致**：Layer2 未使用 OI/NetFlow/Price 排行、币安多空比、资金费率 8h 均值、Basis 等；若希望 Layer2 与 Layer1 及数据补强一致，可将“排行/多空比/资金费率/Basis 与方向一致”纳入因子或可靠度/入场信心计算。
- **因子定义可配置**：当前因子种类写死在 `evaluateLayer2`；若需策略级调节“哪些算因子、权重如何”，可把因子列表与权重放进 Layer2Config（或单独结构），便于后续扩展。
- **与方向池一致**：方向池用 1h 涨跌划分多空；Layer2 的 entryConfPct 已用 RSI、MACD 与 1h，逻辑一致，可考虑把“在 OI/NetFlow/Price 排行中的方向与 1h 一致”也纳入加分项，使 Layer2 与 Layer1 的“对齐类”条件呼应。

## 四、Layer3 现状与问题

### 4.1 已实现

- **信号年龄**：`ValidateLayer3(symbol, side, traderID, maxSignalAgeMinutes)` 校验 pipeline 状态更新时间与当前时间差，超过则拒绝开单。
- **标的归属**：校验 symbol 是否在 `state.ToSubmitSymbols` 中，不在则拒绝。

### 4.2 配置未使用

- **Layer3Config** 中 **OIAlignedRequired**、**EntryTimingStrengthMin**、**CustomFactorsRequired** 在 pipeline 与 ValidateLayer3 中**均未使用**，仅 **MaxSignalAgeMinutes** 生效。
- **建议**：
  - **方案 A**：在 pipeline 或开单前实现三者：  
    - OIAlignedRequired：该标的在 OIRanking 方向与开仓方向一致（或不在反向榜）；  
    - EntryTimingStrengthMin：方向池中该标的 StrengthPct（或 Score）≥ 配置值才允许开单；  
    - CustomFactorsRequired：预留或与“自定义因子”扩展一起实现。  
  - **方案 B**：在文档与配置注释中明确“当前 Layer3 仅使用 MaxSignalAgeMinutes + ToSubmitSymbols 校验”，其余为预留，避免误解。

## 五、方向池（buildDirectionPools）现状与问题

### 5.1 当前逻辑

- 输入为 **L1 通过列表**；按 4h/1h 同向、短趋势(价 vs EMA20)、动能(MACD 与 1h 同向) 计算 alignedCount，≥1 且 momentumOk 时给较高 StrengthPct/ReliabilityPct，否则给较低值；再按 1h 涨跌划分多/空。

### 5.2 可完善点

- **未使用补强数据**：未使用 Binance 多空比、OI/NetFlow/Price 排行、LiquidationAgg、Basis、BTC 占比等；若“情绪/资金与方向一致”则提高 StrengthPct 或 ReliabilityPct，可减少假信号。
- **同标的多空同时存在**：当前同一标的可同时进入 DirectionLong 与 DirectionShort（例如 1h 涨但 4h 跌时两侧逻辑可能都满足）；GetSystemEntryList 已用 StrengthPct 取高侧，行为明确，但若希望“每标的只落一侧”，可在 buildDirectionPools 内按规则只写入一侧（例如 4h 优先或综合分数优先）。
- **config 未参与**：`buildDirectionPools(ctx, afterLayer1, config)` 中 `config` 未使用；若后续引入“方向池权重/阈值”等，可从 config 读取。

---

## 六、与数据源的衔接

- **行情**：Layer1/2 与方向池均依赖 `ctx.MarketDataMap[symbol]`；多周期策略下需保证 Volume 可来自主周期（见 2.2）。
- **NofxOS**：OI/NetFlow/Price 排行在 Layer1 的 flow_aligned、whale_direction_aligned、price_ranking_aligned、market_direction_aligned 中使用；数据缺失时当前为通过，可考虑 fail-closed 选项。
- **币安衍生与补强**：当前未进入 Layer1/Layer2/方向池；若需“多空比/资金费率/Basis/强平与方向一致”作为过滤或打分，需在 pipeline 中显式读取 ctx 的 BinanceLongShortMap、BinanceFundingRateAvg8h、BasisMap、LiquidationAgg 等并增加条件或因子。

## 七、完善项优先级建议

| 优先级 | 项 | 说明 |
|--------|----|------|
| 高 | 多周期下 Volume 条件 | 修复 GetWithTimeframes 未设 IntradaySeries 或 pipeline 回退到 TimeframeData[primary].Volume，避免量能条件在多周期下恒过。 |
| 高 | Layer3 配置落地或文档化 | 实现 OIAlignedRequired、EntryTimingStrengthMin（及可选 CustomFactorsRequired），或在文档中明确“仅用信号年龄+ToSubmitSymbols”。 |
| 中 | 默认 Layer1 项数 | 默认 16 项全开或文档明确“默认 10 项”，与产品/文档一致。 |
| 中 | 数据缺失行为 | 增加“数据不可用是否视为不通过”选项，防止数据源故障时过滤放宽。 |
| 中 | 方向池使用补强数据 | 用 Binance 多空比、排行、强平等对 StrengthPct/ReliabilityPct 做加减分或阈值。 |
| 低 | Layer2 因子扩展 | 将 OI/NetFlow/Price 排行、资金费率、Basis 等纳入因子或可靠度/入场信心。 |
| 低 | entry_timing / reliability_min 在 Layer1 | 按需实现或文档说明“仅 Layer3/仅 Layer2”的职责划分。 |

---

## 八、小结

- **过滤机制整体**：三层结构清晰，Layer1 条件丰富，Layer2 数值化门槛有效，Layer3 信号年龄与 ToSubmit 校验在开单前生效，方向池与 GetSystemEntryList 逻辑自洽。
- **必须修复**：多周期策略下 **volume_ok / volume_trend 因 IntradaySeries 为空而恒通过**，建议优先修复。
- **建议完善**：Layer3 未用配置落地或文档化、默认 Layer1 项数、数据缺失时的 fail-closed 选项、方向池与 Layer2 对补强数据的使用；其余为增强与可配置化扩展。

## 九、已实现的完善项（代码落地）

以下项已在代码中实现，与上文建议对应：

| 项 | 实现说明 |
|----|----------|
| **Layer3 配置落地** | `PipelineState` 增加 `OIAlignedLong` / `OIAlignedShort`；`RunPipeline` 中为 toSubmit 与方向池标的计算 OI 对齐；`ValidateLayer3(symbol, side, traderID, layer3)` 支持 `OIAlignedRequired`、`EntryTimingStrengthMin` 校验。 |
| **默认 Layer1 16 项** | `defaultLayer1Config()` 与默认/优化策略预设均补全 16 项（含 trend_strength、rsi_zone、macd_signal、volume_trend、oi_trend、funding_ok）并默认启用。 |
| **数据缺失 fail-closed** | `Layer1Config.FailClosedWhenDataMissing`；`checkLayer1Item` 对 flow_aligned、price_ranking_aligned、whale_direction_aligned、market_direction_aligned 在依赖数据为 nil 时若 fail-closed 则返回 false。 |
| **方向池补强数据** | `applyDirectionBonus(ctx, symbol, isLong, item)`：用 Binance 多空比、OI/NetFlow/Price 排行、LiquidationAgg 对 `StrengthPct`/`ReliabilityPct` 做加成；在 `buildDirectionPools` 中归入多/空前调用。 |
| **Layer2 因子与排行** | `evaluateLayer2` 增加 OI 排行、净流入排行、涨跌榜、资金费率 8h 均值等因子与入场信心加成；可靠度公式微调以容纳更多因子。 |
| **reliability_min 门槛** | `checkLayer1Item("reliability_min")` 当 `item.Value > 0` 时调用 `evaluateLayer2` 取可靠度，低于 Value 则不通过。 |
